# JLPT 單字複習工具

## Problem Statement

使用者手上有一副 132 張的 JLPT N2 單字牌組，目前存放在 AnkiApp 中。該 App 持續要求付費，且核心功能受限。使用者尚未背完這批單字，且會持續增加新詞，因此需要一個能長期使用、不受付費牆干擾的替代工具。

牌組已從 AnkiApp 匯出，但匯出檔只含日文詞條與中文釋義，**不含讀音**——AnkiApp 的振假名是伺服器端產生的，不隨資料匯出。使用者離開該 App 就失去這項資訊。

使用者主要在手機上利用零碎時間複習，偶爾在電腦上使用。

## Solution

一個純前端的閃卡工具，可加入手機主畫面、離線使用。

複習時只顯示日文詞條，漢字不標讀音，使用者自行回想後按「顯示答案」，即可看到振假名與中文釋義。接著以四級評分（再次／困難／好／簡單）回報熟悉度，系統據此安排該卡的下次到期日——越熟的卡間隔拉得越長，答不出來的卡則回到短間隔重來。每日只需複習已到期的卡，清空即完成。

讀音由人工預先標註並隨程式發佈。使用者亦可自行新增、編輯、刪除卡片。

## Implementation Decisions

### 模組與接縫

建立四個模組，各自對應一個測試接縫。前三個性質相同，第四個不同，分開說。

**跟畫面無關的核心**——不屬於任何一個畫面，換掉整套畫面它們照樣成立：

- **複習流程**：接受一組卡片、當前時間、亂數來源，對外提供「取得目前卡片」與「評分」兩項操作，回傳更新後的卡片狀態與剩餘的複習佇列。排程演算法、抖動、佇列排序、「再次」重排、今日完成判定全部收在此模組內。
- **讀音標記**：接受一個帶讀音標記的詞條字串，回傳可供渲染的振假名結構。另負責審核外部來源提供的讀音預填結果，通過才轉成讀音格，不通過整批退掉。純函式，不涉及任何狀態。
- **資料存取**：對外只提供載入與儲存兩項操作，內部負責首次初始化、單向合併、匯出與匯入。目前實作為瀏覽器本機儲存；日後若改接雲端服務，僅需替換此模組內部，畫面與其他模組不受影響（見 ADR-0002）。

**某個畫面的大腦**——只服務一個畫面，離開那個畫面就沒有意義，因此與畫面的檔案放在一起（`src/ui/`）：

- **讀音編輯器**：編輯畫面上讀音格的協調邏輯。持有詞條與各格的內容，對外提供「詞條改了」「某格填了字」「合併」「切開」「去預填」「儲存」六項操作。搶答檢查（讀音預填等待期間詞條被改掉，那份回覆整份丟掉）、要不要重建讀音格（漢字排列沒變就不准重建，否則正在輸入的格會失焦）、提示字的存亡、以及讀音預填的守門條件全部收在此模組內。**去問外部服務的那支函式以參數注入**，未設定時注入 `null`，模組全程靜默。

第四個模組與前三個的差別在於**它只搬走判斷，不搬走畫面**。能收進來的是「什麼情況下該做什麼」；不能收進來的是畫面自己的事——建立元素、註冊事件、中文文案與樣式一律留在畫面那一側，模組對外只吐狀態代號與「哪幾處要動」的旗標。這條界線不靠資料夾維持，只靠一條規則：**模組不得 import 任何 DOM（Document Object Model，文件物件模型）**。破了這條，這道接縫就跟原本埋在畫面裡時一樣測不到。

**當前時間與亂數必須以參數注入**，模組內不得直接取用系統時鐘或全域亂數，否則排程與抖動無法測試。

### 排程

依 ADR-0001，採簡化版 SM-2。每張卡持有「間隔」（天）與「成長倍數」兩個數值。新卡的間隔起始為 1 天、成長倍數起始為 2.5。四個評分的效果：

| 評分 | 新間隔 | 成長倍數變化 |
|---|---|---|
| 再次 | 重設為 1 天，且當日重新排入佇列 | −0.20 |
| 困難 | 目前間隔 × 1.2 | −0.15 |
| 好 | 目前間隔 × 成長倍數 | 不變 |
| 簡單 | 目前間隔 × 成長倍數 × 1.3 | +0.15 |

成長倍數下限為 1.3，不設上限。到期日為「現在 + 新間隔」。

**抖動**：間隔滿 7 天者，套用 ±15% 的隨機偏移後才決定到期日；未滿 7 天者不抖動。

**「再次」重排**：該卡插入剩餘佇列後半段的隨機位置。剩餘卡片少於 4 張時，改排至佇列末端。

**複習佇列**：僅納入到期日已到的卡片，以隨機順序排列。所有卡片首次進入時皆為新卡（到期日視為已到），因此第一次使用時 132 張全數進入佇列。不設每日新卡上限。

### 卡片列表

列表依到期日由舊到新排序，最急的在最上面：逾期最久 → 今日到期 → 未來（越遠越後）→ 新卡墊底。到期日相同者維持資料中的原始順序。排序固定、不提供切換，搜尋結果亦套用同一規則。

排序與逾期天數的計算歸屬複習流程模組——「到期」與「新卡」的語意權威在該處。列表只負責呼叫與顯示。排序僅比較到期日字串（其字典序即日期序），故不需注入時間；逾期天數則依既有原則注入當前時間。

每張卡的狀態文字有四種：新卡、逾期 N 天、今日到期、到期日原文。逾期以警示色顯示，今日到期沿用既有強調色，其餘為次要色。

### 讀音標記

詞條以方括號標示漢字讀音，例如 `焦[こ]がす`、`書[か]き下[お]ろす`、`帰省[きせい]`。方括號前緊鄰的漢字序列為被標注對象，括號內為其讀音。無方括號者不顯示讀音。此語法同時用於內建牌組與使用者新增的卡片。

新增與編輯卡片時，使用者不再手動輸入方括號。編輯畫面偵測詞條中的連續漢字，為每一串長出讀音格供填入假名，並可切開或合併以決定假名如何分配到哪些漢字上；儲存時再組回上述方括號字串。貼上帶標記的字串會自動攤回讀音格。方括號語法本身沒有改變，仍是唯一的儲存與顯示格式，只是不再需要人工輸入（見 ADR-0004）。

讀音格另可由程式預填：詞條打完後，假名與各串要開幾格都由程式代填（見 ADR-0005）。預填是選配的，使用者未設定時完全不發生；填進來的結果仍是草稿，可改、可清空，畫面上一行提示要求儲存前人工確認。方括號語法與儲存格式完全沒有改變——預填只是幫使用者把格子填好，之後的路徑與手動填一字不差。

### 資料模型

依 ADR-0002，卡片資料以瀏覽器本機儲存為唯一來源。內建牌組於首次啟動時整份複製進本機儲存，此後僅作為單向合併的來源：每次啟動時，將內建牌組中本機尚未存在的詞條補入，已存在者一律不動。

每張卡持有：識別碼、帶讀音標記的詞條、中文釋義、間隔、成長倍數、到期日。識別碼在建立後不變，即使詞條被編輯亦然，以確保單向合併不會重複加入。

**匯出**：卡片、進度、設定合併為單一 JSON，含版本號以利日後格式演進。**匯入**：整份覆蓋現有資料，不做合併。

### 技術與部署

- 建置工具 Vite，不使用前端框架。
- 以 PWA 形式發佈（含 manifest 與 service worker），支援加入主畫面與離線使用。快取採自動更新策略。
- 語音朗讀使用瀏覽器內建語音合成，僅在偵測到日文語音時顯示朗讀按鈕，且僅在使用者主動點擊時播放。
- 版面以手機優先設計，電腦上置中並限制最大寬度。
- 電腦端鍵盤操作：空白鍵掀開答案，數字鍵 1–4 對應四個評分。
- 部署至 GitHub Pages（`brad0924.github.io/va-practice`）。

## Testing Decisions

**好的測試只驗證外部行為，不碰內部實作**。測試應描述「給定這些卡片與這串評分，結果應該如何」，而非「某個內部函式被呼叫了幾次」。內部結構重組時，測試不應失敗。

四個接縫各自對應一組測試：

- **複習流程**：注入固定的時間與亂數，驗證各評分後的間隔與到期日、成長倍數的升降與下限、抖動落在預期區間內、「再次」的當日重排位置（含少於 4 張的退化情況）、佇列在清空後回報今日完成；以及列表排序的四段順序（含同日並列維持原序、新卡永遠墊底）與逾期天數（含跨月、跨年，且不受當下時刻影響）。
- **讀音標記**：驗證單一漢字、多段漢字、連續漢字、無漢字、以及送假名邊界（如 `書[か]き下[お]ろす`）的解析結果。另驗證讀音格與方括號字串的雙向轉換，含 132 張內建卡的往返一致。另驗證讀音預填的接受與拒絕條件——串數、漢字一字不差、讀音必須是假名、形狀不對一律整批退掉。
- **資料存取**：驗證首次啟動的初始化、單向合併只補不覆蓋（含使用者已刪除該詞條的情況）、匯出與匯入的往返一致性。
- **讀音編輯器**：注入一支手寫的假「去問外部服務」函式，藉此控制何時回覆、回什麼，測試不打出任何網路請求。驗證讀音預填的守門（未設定時全程靜默、詞條空白不問、詞條無漢字不問、讀音格已有內容不問、同一串不重問）與搶答（等待期間詞條被改掉則整份丟掉、回覆的漢字對不上或連不上網路只掛一行失敗訊息且讀音格保持原狀）；驗證要不要重建讀音格（改詞尾不重建、換漢字要重建、逐格輸入恆不重建、合併與切開要重建）；驗證提示字的存亡（預填的假名還在就必須留著、清空所有讀音後消失）；以及貼上帶標記字串會攤回讀音格，與儲存時的空白與驗證結果。

本專案為全新建立，無既有測試可參照。測試框架採 Vitest（與 Vite 同源，不額外引入生態）。

**畫面本身不撰寫自動化測試**。以此工具的規模，瀏覽器層級測試的維護成本高於其所能攔截的缺陷。

這句擋的是**需要瀏覽器（或 jsdom 這類假瀏覽器）才跑得起來的測試**，不擋畫面資料夾底下的純邏輯：`src/ui/` 之中不 import DOM 的檔案照常撰寫測試，在既有的 node 環境直接跑。目前屬於這一類的有讀音編輯器，以及卡片列表的時間桶分組。

## Out of Scope

- **雲端同步**：進度僅存於本機，跨裝置以手動匯出／匯入處理。資料存取模組的介面已預留替換空間，但本次不實作。
- **提前複習**：不提供把未到期卡片提前拉來複習的功能。
- **額外練習**：今日份清空後即結束，不提供不影響排程的自由練習模式。
- **反向複習**：不支援由中文回想日文。
- **統計與成就**：不做連續天數、學習曲線、圖表等。
- **多牌組**：僅支援單一牌組。
- **每日新卡上限**：不設限，亦不提供相關設定。
- **列表排序切換**：列表固定依到期排序，不提供切回原始順序或改以其他欄位排序的選項。
- **匯出檔的合併**：匯入為整份覆蓋，不處理兩份進度的合併。
- **原牌組的附件**：AnkiApp 匯出檔中的音訊與手寫筆跡檔案未被 XML 引用，不予移植。
- **畫面層級（瀏覽器）自動化測試**。

## Further Notes

### 預期的使用曲線

由於 132 張卡在首次使用時全數進入佇列，第 3 至第 10 天的複習量會明顯偏低，可能連續數日僅有個位數甚至為零。這是「不設每日新卡上限」的必然結果，約兩週後每日量將趨於穩定。此為預期行為，非缺陷。

若日後認為此空窗期難以接受，最小的補救是加入不影響排程的自由練習模式（見 Out of Scope）。

### 資料來源與已知修正

內建牌組轉換自 AnkiApp 匯出的 XML，讀音為人工標註。轉換過程中已確認的調整：

- 原資料中兩張卡的正面為假名、語音欄為漢字（`わた`／`綿`、`ひたい`／`額`）。已改為漢字為正面，否則讀音無從測驗。
- `属する` 的釋義由「規屬」修正為「歸屬」。
- 使用者已審閱全部 132 筆讀音。`黴び`、`通づる`、`送り仮名` 三筆雖與現代標準日語寫法有出入，經確認維持原樣。

### 新增卡片的定位

使用者將持續加入新詞，且明確選擇在 App 內直接新增而非修改資料檔。因此新增／編輯功能屬於核心流程，不是附屬功能——其可用性（特別是讀音標記的輸入體驗）應與複習流程同等對待。
