# 拼字完全不碰排程，練再多次進度都不動

拼字是複習之外的第二種練法：只給釋義，限時把讀音一格一格拼出來。它**不寫任何一張卡的排程狀態**——`interval`、`ease`、`due` 三個欄位一個都不動，`rate()`（`core/lib/review.ts`）從頭到尾不被呼叫。拼對拼錯只影響那一輪的成績，成績本身也不落地，離開畫面就只剩「上一輪」那一份。

拼字挑的那幾本單字本同樣不進 `AppData`：它存在本機、不隨備份走，因此 `BookScopes` 維持三格不變（`core/lib/types.ts`），資料版本號不升。

## 為什麼

**這是維護者當面挑掉的。** 談規格時攤開三條路：把作答換算成評分（拼對＝好、逾時＝再次）、只有拼錯才算「再次」、完全不動。維護者選了第三條，原話是「先完全不動排程，先把這個東西做出來，但不影響任何複習」。

三個理由撐著這個決定：

**限時作答與自評量的不是同一件事。** 四級評分問的是「你對這個詞有多熟」，答案由人給。拼字量的是「你在九秒內點不點得出那三塊磚」，會被手指滑掉、螢幕大小、當下分心整批污染。把後者自動翻譯成前者，等於讓手速決定下次什麼時候複習——`ADR-0001` 那套簡化 SM-2 的輸入從此多了一種它沒被設計來吃的雜訊。

**這支 app 唯一不可重來的東西就是排程。** 卡片打錯可以改，單字本刪了可以再建，備份可以匯回來。間隔與成長倍數是幾個月累積出來的，被一晚亂點洗掉就是真的沒了。新玩法在還沒有人玩過的階段就伸手進去，代價與收益不對等。

**不接排程換到的是一整片自由。** 秒數、磚數、干擾怎麼挑、計分曲線，全都可以在真機上邊玩邊調，不必擔心「上週那一版的手感把我的到期日排歪了」。這些數字本來就要靠實玩才定得下來。

## Considered Options

- **拼對算「好」、拼錯或逾時算「再次」**：最省事，直接複用 `rate()`，拼字立刻變成第二種複習方式，練了就有進度。否決的原因見上——手速被當成熟悉度，而且新玩法第一版就握有寫排程的權力。
- **只有拼錯與逾時算「再次」，拼對什麼都不做**：只往安全的方向推，拼對再多次也不會把間隔拉長，聽起來像個穩健的折衷。否決的原因是它仍然會寫 `due`，一晚亂點照樣能把一整本推回「今天再看一次」；而且它單向壓縮進度，久了整份排程往前擠，是另一種歪。
- **拼字結果先記著，不動排程，日後再決定要不要換算**：把作答歷程存起來留退路。否決的原因是那份歷程要進 `AppData` 才活得過重整，於是資料版本號要升、備份與雲端格式要跟、匯入匯出要相容——為一個還不確定要不要的功能先付掉整包代價。真要接回去的時候再存也不遲。
- **拼字挑的單字本開成第四組範圍，跟著備份走**：與現有三組同規格，四個畫面一致到底。否決的原因是同一包代價：`BookScopes` 多一格，`parseScopes()`、`normalizeScopes()`、備份、雲端、舊檔相容全部要動，而拼字挑書這件事本來就適合各裝置不一樣——手機在通勤時想練小本的，電腦前想練整批。

## Consequences

**拼字畫面不需要任何寫入路徑。** 它只讀 `app.data.cards`，不呼叫 `applyData()`、不碰 `storage.ts`。這讓整個功能可以在不理解排程的前提下實作與測試，也是把它切成獨立畫面而不是複習畫面第二模式的底氣。

**「練了半天進度沒動」是預期行為，不是 bug。** 使用者可能會困惑，畫面上要講清楚。日後有人回報「拼字不會更新到期日」，答案在這裡。

**這扇門推得開。** 要接回排程，是在一輪結算時多呼叫幾次 `rate()` 的事；真正的成本在「要不要存作答歷程」那一題，而那一題今天沒有被回答，只是被推遲。維護者用的字是「**先**完全不動」——這份記的是一個可以回頭的決定，不是一條紅線。

**與 `ADR-0001`（簡化 SM-2）不牴觸，是替它擋掉一種輸入。** 那份定的是四級評分怎麼換算間隔；這份定的是拼字的作答不進那條管線。日後若真要接，`ADR-0001` 的輸入定義得先重新談過。
