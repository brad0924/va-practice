# 讀音預填改用遠端 LLM，作為選配的預填，不引入本地字典

新增卡片時，詞條打完就把該詞送去問一個遠端的 LLM（Large Language Model，大型語言模型），把回來的假名填進讀音格，並依它的自述決定每一串漢字要開幾格。填進來的是草稿：可改、可清空，畫面上一行提示要求儲存前人工確認。整個功能是選配的，需要使用者自備的金鑰，沒設定時連請求都不發。程式仍然不內建任何漢字讀音字典。

這是走 ADR-0004 預留的那扇門，不是推翻它。該決定的結語寫著「日後若真的想要自動推測，只能作為選配的預填（填完仍需人工確認），而非取代手動輸入」——本決定就是那扇門被打開的紀錄，門的形狀一寸沒改。

ADR-0004 拒絕字典的四個理由，現在有三個不成立。不是鑽漏洞，是問題本身換了：

- **體積**：知識搬到遠端，字典本身一個位元組都沒進打包產物；長出來的只有這個功能自己那幾十行程式碼。產物因此從當初的「約 33 KB」變成約 36.5 KB（未壓縮的程式碼，另加約 7.0 KB 樣式），同一個量級。原本那句「10 倍於整個 app」不再適用。
- **正確性天花板**：熟字訓（`剃刀[かみそり]`、`吹雪[ふぶき]`）是字典查不到、逐字拆本來就無解的，但 LLM 答得出來。連濁（`円高` → `えん`＋`だか`）與促音便（`昨今` → `さっ`＋`こん`）同理，不必另寫規則。

  **2026-08-21 後記：「LLM 答得出來」是真的，但要看是哪一顆 LLM。** `reading-prefill` 票 06 把預設模型換成 `gemini-3.5-flash-lite`（理由是「等超過 10 秒沒有回覆」十次有三次），同一題各打五次量出來：`gemini-3.6-flash` 全對，`flash-lite` 錯一次——錯的那次拆對了格子，讀音卻接成 `ふくふき`，沒有連濁成 `ふぶき`。本 ADR 選 LLM 而不選本地字典的判斷沒有變（字典在這題是 0/5），但「答得出來」不是全稱句，它跟著模型走。而下面那句「中小型模型會很有自信講錯熟字訓、連濁、促音便」，現在也適用於我們自己選的這一顆——**這是知情選擇**，換來的是逾時 3/10 掉到 0/10。想把這一格贏回來的嘗試記在票 08。
- **失敗模式**：這是最關鍵的一項。**分配錯誤不會產生錯卡**——`吹`／`雪` 分反了，卡片正面的文字與語音朗讀完全不變，只有振假名標的位置不同，而且編輯畫面的預覽當場看得到。ADR-0004 擔心的「安靜的錯卡」在這個形狀下不成立。
- **失敗模式裡仍然成立的那一半**：整串讀音幻覺。AI（Artificial Intelligence，人工智慧）說 `吹雪` 唸 `すいせつ`，那是真的錯卡——不會報錯，要等複習翻面才發現，而且會一路存進雲端備份。這一項只靠「填進格子而非直接存檔」＋「一行『請確認』提示」＋「預覽」擋，沒有第二道防線。**本決定沒有解決這個風險，只是把它縮小到人眼看得見的位置。**

第四個理由（實際負擔很小）沒有消失，只是不再是拒絕的理由：填假名確實是打字而非查資料，但使用者要的體驗是「打完詞條什麼都不用打」。

供應商選 Google Gemini。五家有免費層的服務（Gemini、Groq、OpenRouter、Cerebras、Mistral）實測 CORS（Cross-Origin Resource Sharing，跨來源資源共用）預檢**全部放行**瀏覽器直呼，免費額度對「一個詞一個請求」的用量也全都碰不到——所以 CORS 與額度都不是選擇因素，**唯一該比的是日文能力**。

## Considered Options

- **kuromoji.js 本地形態素解析**：字典目錄實測 17.0 MB（已 gzip），約是打包產物的 470 倍，比 ADR-0004 當初寫的「300 KB 起跳」還大 50 倍。而且它**只解決一半**——它給的是整個詞的讀音（`吹雪` → `フブキ`），不會告訴你 `吹`＝ふ、`雪`＝ぶき；逐字分配仍得自己做一張單漢字音訓表，再加上連濁、促音便、送假名的規則。真實成本是「一份大字典」加上「一整套自寫邏輯」。

- **瀏覽器內建的 Prompt API（Application Programming Interface，應用程式介面；模型是 Gemini Nano）**：真的免金鑰、免費、離線，體積問題完全消失。但 Android、iOS、ChromeOS 都還不支援——而這個 app 主要就是在手機上用的；桌機也要約 22 GB 可用磁碟與 4 GB 的 VRAM（Video RAM，顯示卡記憶體）。更根本的是，日文漢字讀音正是超小模型會很有自信地講錯的題型。

- **只做分配、讀音由使用者輸入整串**：使用者打一整串假名，程式負責切給各個漢字。只需數十 KB 的音訓表、免金鑰、離線可用、風險最低，工程上也最乾淨。否決的原因單純是它沒有解決使用者要的那件事——仍然要打字。

- **Groq／Cerebras／OpenRouter 的開源模型**：CORS 與免費額度都不成問題（見上），單看規格甚至比 Gemini 大方。但唯一該比的日文能力，正是中小型開源模型的弱項；熟字訓、連濁、促音便是它們會很有自信講錯的地方。

- **自動連釋義一起填**：順手就能做，但中文釋義錯了沒有任何機制抓得到——預覽看不出來、驗證擋不住，而使用者會拿它背一輩子。與讀音不同，這裡沒有「翻面就發現」的補救點。

## Consequences

**金鑰刻意不進 `AppData`，因此 ADR-0003 那句「若日後要放入任何敏感資料，這個前提必須重新評估」沒有被觸發。** 這是主動迴避不是忽略：金鑰若進 `AppData`，會同時打開三個出口——雲端備份（加密後仍上傳）、本機儲存（明文）、**匯出檔（明文，而匯出檔是使用者會自己傳來傳去的東西）**。加密只堵得住第一個。金鑰因此存在自己的抽屜裡，不上雲、不進匯出檔。

**代價是金鑰不跨裝置，每台各設定一次。** 換裝置、清瀏覽器資料都要重設，手機上尤其麻煩（要在小鍵盤上貼一串長字元）。已知並接受——這是上一條的必然結果，不是疏漏。

**這個功能永遠是選配的。** 沒設金鑰時完全靜默：不發請求、不顯示任何多出來的字，新增卡片的行為與沒有這個功能時一字不差。離線、超額、模型掛掉、回覆過不了驗證，一律降級成手動填，絕不擋住儲存。ADR-0004 的「讀音一律由人輸入」仍然是這個 app 的保底路徑，不是被取代的舊做法。

**免費層的內容通常會被供應商拿去改進模型，而且一旦該帳號啟用計費，免費層會整個消失、每個呼叫從第一個 token 起計費。** 送出去的內容是日文單字，前者可接受；後者要在設定金鑰的介面上提醒使用者，否則使用者會在不知情的狀況下開始付錢。

**專案對外部服務的依賴又多了一項。** ADR-0003 已經讓「換裝置接上進度」取決於 Firebase，現在「讀音預填」取決於 Google 的模型端點。兩者都不影響離線複習，但模型下架或改名會讓這個功能安靜地停擺——`gemini-2.5-flash` 對新金鑰關閉一事就是在實作期間發生的，而且 ListModels 型錄查不出來，只有實際呼叫才會知道。端點寫死單一模型而非 `-latest` 別名，是為了讓「模型換人」以錯誤的形式暴露出來，而不是讓同一個詞的讀音無預警改答案。
