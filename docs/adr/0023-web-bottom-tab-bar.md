# 網頁版的導覽改成底部四格，拼字與問答收進複習

網頁版的頂層畫面只有四個：複習、卡片、資料、統計，由底部一條導覽列切換，與手機版的四個 tab 一模一樣。拼字與問答**不是頂層畫面**：它們收在複習底下，由複習、拼字、問答三個畫面標題列正下方那一排分段切換（複習｜拼字｜問答）進出。標題列上不再放「往隔壁畫面」的鈕，只放這一頁自己的東西。

之後新增的畫面，先問它是不是第五個頂層畫面——答案幾乎一定是「不是」。練法類的畫面加進分段切換，其餘的從某一個頂層畫面點進去。

## 為什麼

**原本那條線撐不住了。** 網頁版原本沒有導覽列，六個畫面靠標題列左右各一顆鈕串成一條線：複習 → 拼字 → 問答 → 卡片 → 資料 → 統計。每接進一個新畫面，就要改四支檔案的標題列；問答接進來之後，複習標題列右邊擠了三顆鈕，375px 寬時中文換成兩行、日文換成三行（`quiz/02` 的 Comments）。一條線還有一個更根本的毛病：從複習到統計要按五下，而且回頭的路是沿原路退回，不是直接跳。

**四格而不是六格，因為 Apple HIG 與 Material Design 都建議底部導覽放 3 到 5 格。** 六格全放超過上限；五格（統計留在資料裡）與手機版不一致。維護者選了與手機版一致的四格（`web-tab-bar/01` 決定 1）。

**拼字與問答收進複習，因為它們是同一件事的三種練法。** 三者都是「拿一批卡來練」，差在怎麼問；卡片、資料、統計則是管理與回顧。練法放在一起，頂層就只剩四格。

**入口選分段切換，是看原型挑的。** 原型（分支 `prototype/web-tab-bar`）疊在真的 app 上並排了三種入口，維護者選了分段切換（決定 5）：一眼看得到，點一下就換，同一排也是回複習的路。

## Considered Options

- **六格全放進導覽列**：每個畫面都一步到得了。否決的原因是超過 HIG 與 Material 建議的五格上限，375px 寬時每格只剩約 55px，三種語言的字排不下。
- **五格，統計收進資料**：少動一個畫面。否決的原因是與手機版不一致——兩邊同一個人在用，同一個位置的東西不該不一樣。
- **拼字與問答的入口放在標題列一顆「練習 ▾」選單裡**：標題列只多一顆鈕，不佔高度。否決的原因是入口藏起來了，要多點一下才看得到；進去之後還得另外放一顆返回鈕。
- **拼字與問答的入口放在「今日份完成」那一頁**：畫面最乾淨，也等於鼓勵先複習完。否決的原因是還沒複習完就完全進不去拼字與問答。

## Consequences

**複習、拼字、問答三個畫面各少一行高度。** 分段切換佔了標題列底下一排，底部又多了導覽列。手機橫著拿時切兩欄的門檻因此從 31rem 改成 34.25rem（在 375px 寬的畫面上逐一量磚開始縮的那個高度，見 `styles.css` 的 `max-height` 那一段）。

**標題列上的鈕只剩「這一頁自己的東西」。** 卡片的「新增」、編輯頁的「取消」、複習的剩餘張數與單字本膠囊。之後有人想在標題列加一顆往別的畫面的鈕，答案在這裡：往別的畫面走導覽列或分段切換。

**編輯頁照樣顯示導覽列，跳走時正在打的字直接丟掉。** 網頁版的編輯頁沒有草稿，維護者知情接受（決定 4）。

**拼字與問答的「上一輪」規則不變。** 答題途中按導覽列或分段切換跳走，那一輪照舊封存，回來看到成績頁。封存靠的是 `app.spellingRound` 與 `app.quizRound` 那兩格，跟入口長什麼樣無關。

**與 `ADR-0017`（手機版改寫成 React Native）是兩條線上的同一個決定。** 手機版的四個 tab 由系統的 `UITabBarController` 畫，網頁版是自己畫的膠囊，兩邊的格數、順序、字與圖示要一起動。圖示的樣子（平常線條、選中實心）目前只有網頁版照做，手機版的那一步在 `ios-app/23`。
