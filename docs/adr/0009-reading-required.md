# 讀音由選填改必填：詞條裡有漢字就一定要填讀音

自己新增或編輯卡片時，詞條裡只要有漢字，**每一個讀音格都要填**才存得下去。原本的規則是「同一串漢字要麼全部填、要麼全部留空」——整串留空是合法的，現在不再合法。純假名與外來語詞條不長讀音格，不受影響。

匯入單字與備份匯回**不檢查**，照收。必填是「使用者自己打字」那條路上的規則，不是資料的規則。

## 為什麼

起因是換欄鍵。使用者要的是「只要還有輸入格空著，按手機的 ↵ 就把游標送過去」，而 ADR-0006 目前只在詞條與釋義之間跳，讀音格完全不參與。

把讀音格納進來時撞上一個死結：**空的讀音格既是合法的終點，又不能當終點**。留空是合法的存檔狀態，所以「輪到它、你卻不想填」時，Enter 沒有出口——再按一次還是它，永遠走不到釋義、也永遠送不出去。沒設 AI（Artificial Intelligence，人工智慧）金鑰時每張有漢字的卡都是這個狀態，等於這條路對多數人直接壞掉。

閃避的辦法有幾種（見下方），但都是在「空格有時算數、有時不算數」上疊規則。必填是把矛盾本身拿掉：**還空著的格子＝還沒填完**，一條規則管三種欄位，輪詢自然收斂。

另一個獨立的理由是這個 app 本來要的東西。複習時卡片正面不標讀音，翻面才看到振假名——那正是要測的東西。一張有漢字卻沒讀音的卡，翻面也沒有振假名可看，等於這張卡放棄了測驗讀法這件事。ADR-0004 的立場一直是「讀音由人輸入」，這次只是把它從「可以不填」推到「一定要填」。

## Considered Options

- **維持可留空，Enter 只在詞條與釋義之間跳**（現狀）：什麼都不用改，但需求沒被滿足——讀音格裡按 ↵ 仍然直接送出表單，釋義還空著就閃紅字，正是 ADR-0006 花力氣要避免的那件事。

- **維持可留空，只有「同一串漢字填了一半」的空格才算數**：規則自洽、也不會卡死，因為「填一半」本來就是錯誤狀態，你非填不可。但「填一半」是罕見狀態，多數時候這個功能等於沒有；而且多一條「什麼樣的空格才算空」要記，使用者看畫面看不出來。

- **維持可留空，空的讀音格只跳一次，跳過就記住你不想填**：要在畫面上記狀態，而「已經跳過一次」這件事使用者完全看不見——同一格有時擋你、有時不擋，比不擋還難預測。

- **必填，但只擋新增、編輯舊卡放行**：不會讓手上沒讀音的舊卡突然「改不動」。否決的原因是同一支編輯畫面長出兩套規則，而且那些沒讀音的舊卡會永遠留著，沒有任何時機被補上。使用者選擇一視同仁：舊卡打開來改任何東西，都得先把讀音補齊。

- **必填，連匯入單字與備份匯回一起擋**：資料層從此保證「有漢字必有讀音」，最乾淨。否決的原因是代價落在你修不了的地方——別人給的檔案可能大半都進不來，而且被擋掉的卡你連補的機會都沒有（匯入不經過編輯畫面）。改成照收，那些卡下次被打開編輯時才被要求補齊。

## Consequences

**不知道讀音就存不了那張卡。** 沒設 Gemini 金鑰時，每張有漢字的卡都得自己打假名——這正是 ADR-0005 之前的日子。這是刻意付的代價，不是疏漏。

**手上沒讀音的舊卡變成負債。** 打開來只想改一個錯字，也得先把讀音補齊才存得回去。好處是這些卡會被逐步洗乾淨，壞處是你不會挑時間，是它挑你。

**「每張卡都有讀音」是編輯畫面的承諾，不是資料的保證。** 匯入那條路照收，所以渲染、語音朗讀、複習翻面三處仍然得容忍沒讀音的卡，一行防禦都不能拿掉。誤以為必填之後就能省掉那些分支，會出事。

**`reading.ts` 的「要麼全部填、要麼全部留空」退場**，被「一律要填」取代。那條規則存在的唯一理由是要區分「整串沒填」與「填一半」，現在兩者都是錯，不必再分。

**這扇門很好推回去**——把那條驗證刪掉就回到選填。真正留下來的是使用者在必填期間補上的那些假名：那是資料，改回選填也不會消失。所以反轉的成本幾乎是零，被鎖住的只有使用者在這段期間多花的打字時間。
