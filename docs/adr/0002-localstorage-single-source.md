# 卡片資料以 localStorage 為唯一來源，內建牌組僅供單向合併

> **內建牌組的部分已被 ADR-0008 取代。** `src/data/cards.json` 與單向合併都已刪除，第一次打開 app 是空的。「localStorage 為唯一來源」這一半仍然成立，也仍是現況。以下內文維持決策當下的原樣，不予改寫。

`cards.json` 隨程式發佈，但它不是執行時的資料來源。首次啟動時整份複製進 localStorage，此後應用程式只讀寫 localStorage；每次啟動時再做一次單向合併——把 `cards.json` 裡尚未存在的詞條補進去，已存在的一律不動。

這樣做是為了讓「內建卡」與「使用者新增的卡」在程式裡不存在區別。使用者可以編輯、刪除任何一張卡（包含原始 132 張），匯出時整包倒出即可，不必處理兩種來源的合併。單向合併則補回這個模型唯一的缺口：新版本追加的卡片仍能送達使用者，同時保證其修改與刪除永不被覆蓋。

## Considered Options

- **內建卡唯讀**：程式最單純，但原始資料是使用者自行輸入、確知含有錯字（例如 `属する` 的釋義誤植為「規屬」），無法修正是實質缺陷。
- **覆寫層**：以 `cards.json` 為基底，localStorage 僅存差異與刪除標記。理論上兩全其美，但三層合併邏輯的維護成本對單人自用工具不成比例。

## Consequences

`cards.json` 對已安裝的使用者而言，事實上是**唯讀且僅可追加**的。修正既有卡片的內容（錯字、讀音）不會傳遞出去——使用者本機的版本永遠優先。若日後需要推送修正，必須另行設計機制（例如帶版本號的強制覆寫清單），而非直接改 `cards.json`。
