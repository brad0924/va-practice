# 元件要聽全域事件時：畫面層走插槽，元件層走成對註冊

專案裡有兩套「想聽 `document` 上的事件」的做法，兩套都對，差別在**哪一層**用：

- **畫面層**（`review-view.ts`、`stats-view.ts` 這種一整頁的東西）→ **常駐分派器加插槽**。`document` 上永遠只有那一個監聽器，畫面把自己的處理器放進 `App` 的插槽，`mount()` 換畫面時把插槽清空。
- **元件層**（`book-filter.ts` 這種被畫面組裝進去的零件）→ **成對註冊**。需要監聽的那段時間才掛上去，狀態一結束就解除，另加一道自癒防「畫面在監聽期間被換掉」。

判準是**有沒有天然的解除時機**。畫面有 `mount()`，那一刻必然發生、且必然知道自己在換人；元件沒有——`root.replaceChildren()` 把整棵樹丟掉，不通知任何人。所以元件不能用「註冊了等以後解除」的寫法，只能用「這段狀態需要它才存在」的寫法：元件若只在某個狀態期間才需要監聽（例如選單開著），**那個狀態的開關本身就是解除時機**。

## 為什麼

兩套做法都已經在 repo 裡，這份文件只是把界線寫下來。

鍵盤走的是插槽（`src/app.ts:231`、`:236`）：

```ts
function mount(build: () => HTMLElement): void {
  app.keyHandler = null;          // 換畫面時把插槽清空
  root.replaceChildren(build());
}

document.addEventListener('keydown', (event) => {   // 全 app 只註冊這一次
  if (isTyping(event.target)) return;
  app.keyHandler?.(event);
});
```

點外面收選單走的是成對註冊（`src/ui/book-filter.ts`）：開合狀態變動一律經過 `refresh()`，掛與解除就寫在那裡（`:127`），三個關閉點（點 toggle、Esc、點外面）自動涵蓋，選單關著時 `document` 上一個都沒有。

**為什麼不讓 `bookFilter` 也用插槽。** 那是與現有模式最一致的做法，但 `bookFilter` 目前只吃純資料、不認識 `app`；要拿插槽就得收 `app`，三個呼叫端與整批既有測試全要跟著改。更重要的是分層：插槽是畫面層的東西（它的生命週期綁在 `mount()` 上），讓一顆被畫面組裝進去的零件去搶它，是分層上的倒錯——那顆零件從此只能活在有 `app` 的地方。

**自癒那三行為什麼必要。** 成對註冊唯一的破口是「狀態還開著的時候，畫面被整個換掉」，而這條路真的走得到：`app.ts:242` 的 `initSpeech(() => render())` 在語音清單載入完成時會重畫，雲端拉到新資料時也會。所以 `onOutside` 開頭先看 `node.isConnected`，脫離文件就自我拆除。

少了這三行的後果**不是監聽器無限累積**——殘留的那顆會在下一次點外面時跑完自己的 `refresh()` 而自我解除。真正堵住的是那一下的傷害：**使用者在新畫面上的第一下會被一顆看不見的選單 `preventDefault()` 吃掉，並且對一個已經死掉的元件回報一次 `onOpenChange(false)`。**

**順帶訂正一句寫錯的否決理由。** `.scratch/review-scope-switcher/issues/02-book-filter-esc-and-open-state.md` 當初否決「點外面自動關閉」時寫：

> 沒被要求，而且做起來要掛 `document` 的 click 監聽器，撞上同一個「沒有拆卸時機」的問題。

那句錯在**把「碰 `document`」當成成因**。碰 `document` 本身沒有問題——鍵盤那條也碰，而且碰得心安理得。成因是「註冊了永不解除」。當時沒把 `app.keyHandler` 這個既有模式算進去，只看了 `book-filter.ts` 裡替 Esc 寫的那段註解就下了結論。那張票的檔案依慣例不回頭改，訂正落在這裡。

## Considered Options

- **`bookFilter` 也改用 `app` 插槽**：與現有模式最一致，`document` 上永遠只有一個監聽器。否決的原因見上——元件得收 `app`，三個呼叫端與十一條測試全要改，而且是分層上的倒錯。
- **改聽 `focusout` 判 `relatedTarget`，完全不碰 `document`**：拆卸問題整個蒸發，監聽器與 Esc 掛在同一個地方（`editor-view.ts` 判落點就是這樣做的）。否決的原因是 iOS Safari 點到不可聚焦的空白處時按鈕不一定失焦，而這個 app 主要在 iPhone 上用——手機上會收不起來。
- **`focusout` 與 `pointerdown` 兩條都做**：覆蓋最完整。否決的原因是兩條會互相觸發（點外面同時造成失焦），得多寫一層擋重複收合與重複回報，程式碼與測試大約翻倍。
- **只註冊不解除，也不加 `isConnected` 自癒**：省下那幾行。否決的原因見上——換過畫面之後，使用者的下一下會被看不見的選單吃掉。

## Consequences

**新元件要聽全域事件時有明確判準**，不必站在岔路口猜，也不必為了拿插槽而把 `app` 硬塞進一個本來很乾淨的零件裡。

**代價是專案裡永遠有兩套寫法。** 讀到其中一套時得先確認自己在哪一層，否則會誤以為另一處寫錯了——這份文件存在的一半理由就是防這個誤會。

**成對註冊的那一套需要紀律。** 掛與解除必須寫在同一個地方（`bookFilter` 是 `refresh()`），分散到各個觸發點就會漏掉其中一條路。`addEventListener` 對同一個函式參考是冪等的，解除沒掛上的也無害，所以「狀態一變就照現況重設一次」是安全的寫法，比「這裡掛、那裡解」可靠。

**`isConnected` 自癒是這套做法的固定配件，不是這顆元件的特例。** 下一個走成對註冊的元件同樣沒有拆卸時機，同樣得自己看一眼還在不在文件上。
