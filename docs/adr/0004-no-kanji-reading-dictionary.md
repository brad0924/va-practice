# 讀音格逐字開格、由使用者填假名，不引入漢字讀音字典自動推測

新增或編輯卡片時，多字的漢字串預設逐字開成一格，讀音一律由使用者自己填假名。程式不內建漢字讀音字典，也不嘗試自動推測讀法；使用者可切開或合併讀音格，自行決定假名如何分配到哪些漢字上。

拒絕引入字典的理由有四：

- **體積**：現有打包產物約 33 KB，一份精簡的漢字讀音字典約 300 KB 起跳，是整個 app 的十倍，與「純前端、可離線、可加入主畫面」的定位不成比例。
- **正確性天花板本來就到不了 100%**：連濁（`円高` → `えん`＋`だか`）、促音便（`昨今` → `さっ`＋`こん`）需另寫規則；熟字訓（`剃刀[かみそり]`、`吹雪[ふぶき]`）逐字拆本來就無解，字典查不到。
- **失敗模式最糟**：猜錯時產生的是看起來正常的錯卡，不會報錯，要等複習翻面才發現——比「請使用者自己填」更危險，而且會一路存進雲端備份。
- **實際負擔很小**：121 個漢字串裡 85 個是單一漢字，根本無從猜起；使用者本來就知道讀音（詞是自己要加的），填假名是打字而非查資料。

## Considered Options

- **引入漢字讀音字典自動預填**：新增漢字時自動填入推測讀音。體積、正確性、失敗模式三項皆不利（見上），對單人自用工具的效益不足以抵銷成本。
- **強制逐字一格、不可合併**：實作最單純，但熟字訓（`剃刀`、`下駄`、`吹雪`）的讀音對不到單字，硬拆會逼使用者填出錯的東西。故保留切開／合併，讓使用者自行決定分配。

## Consequences

讀音一律由人輸入。這扇門沒有關死：日後若真的想要自動推測，只能作為**選配的預填**（填完仍需人工確認），而非取代手動輸入。在那之前，程式不承擔任何「猜讀音」的責任，也就不會產生安靜的錯卡。
