# 卡片頁可切換到期排序的方向

Status: done
Type: enhancement

## 需求

卡片頁（`src/ui/list-view.ts`）的排序寫死為 `sortByDue()`：到期日由舊到新，新卡墊底。使用者想要一顆能切換正序／倒序的按鈕。

## 決定

1. **新卡視為最早到期，不再是墊底。** 這改掉了現有的預設呈現：正序變成「新卡 → 逾期久 → 逾期短 → 今日 → 未來」，倒序整個反過來、新卡沉到最底。等於把新卡在排序上的無限值從「無限晚」換成「無限早」，規則仍是單一的，不需要為新卡多開一段判斷。內建牌組 132 張初始全是新卡，因此新使用者打開卡片頁會先看到一整片新卡——已知且接受，這正好也是找「還沒學過的詞」最快的路。

2. **只反轉日期的比較，同一組內部的順序不跟著翻。** 給 `sortByDue()` 加 `direction` 參數，把比較結果乘上 `flip`，而不是對結果 `reverse()`。同一天到期的卡、以及新卡彼此之間，在兩個方向下都維持同一個相對順序，來回切換時畫面不會亂跳；`review.ts` 既有的「排序是穩定的」性質也因此保住。

3. **方向不記憶。** 只存在 `listView()` 的區域變數裡，離開卡片頁再回來就回到正序。與搜尋框離開即清空的現有行為一致，不動 `App` 介面、不動 `localStorage`——排序方向是畫面偏好，與 `AppData`（卡片與進度）不同類，混進備份會很怪。

4. **按鈕放在「共 N 張」那一列的右側。** 上方 bar 已有四個元素，手機寬度下再塞會擠掉標題。文字為「到期 ↑」／「到期 ↓」而非純箭頭：頁面上沒有別的排序線索，孤零零的箭頭不好確定它在排什麼。沿用 `review-view.ts` 朗讀鈕的無障礙慣例，另給 `aria-label`。

5. **不影響複習。** `sortByDue()` 只有卡片頁在用，複習佇列走的是 `buildQueue()`（隨機順序），兩者互不相干。

## 驗收

- `npm test` 全綠。既有的 2 個「新卡墊底」測試改為「排最前」，另補 2 個倒序測試（日期反轉、同組內部不翻）。
- 打開卡片頁，預設就是新卡在最上面，不必按任何東西。
- 按一下「到期 ↑」，整份顛倒且新卡沉到最底；再按一下回到預設。
- 搜尋框打字後，篩選結果仍照當前方向排。
- 切到「複習」再切回「卡片」，方向回到正序。
- 複習畫面的出題順序完全沒變。

## Comments

- `CONTEXT.md` 的「排程」段落新增「到期排序」詞條。放在段落最後，因為它引用了到期、逾期、新卡三個概念，擺在後面才不會前向引用。`_Avoid_` 特別排除「優先度」「排程順序」「佇列順序」——這三個說法都會讓人誤以為它會影響複習時誰先出現。
- `.count` 從 `<p>` 改為 `<span>` 並包進新的 `.list-toolbar`。`.count, .status` 那組共用樣式（含 margin）保持不動，`.status` 在資料頁的呈現因此不受影響，toolbar 的高度也直接由 `.count` 原本的 margin 撐開。
