# 「再次」重排回佇列的卡，重整頁面後消失，複習不到

Status: needs-triage
Type: bug

## 回報

> 我如果把單字標了「再次」，剩餘 X 張的數字不會減少，繼續學習，該單字也會繼續出現讓我重新練習，但重整頁面，被標為「再次」的單字馬上就會不見，不讓我重新學習。

## 跟 `date-rollover/01-stale-date-on-rollover.md` 的關係

表面上都跟「頁面重整／重建佇列」有關，但根因不同：

- issue 01 講的是**該重建的時候沒重建**（跨午夜後 `now()` 沒被重新讀取，佇列停在前一天）。
- 這張講的是**重建了，但重建依據漏資訊**，跟跨日完全無關，同一天內任何時候重整都會發生。

## 根源

`src/lib/review.ts` 的 `rate()`：

```ts
const rest = queue.slice(1);
return {
  card: updated,
  queue: rating === 'again' ? reinsert(rest, updated, random) : rest,
};
```

按「再次」時，兩件事同時發生，但只有一件被存起來：

1. `updated.due` 被設成**明天**（`interval` 重設為 1 天）——這是長期排程要用的最終狀態，會被 `app.advance()` 存進 `localStorage`。
2. `reinsert()` 把這張卡塞回**記憶體中**目前這份佇列的後半段，讓它「今天稍後」還會再出現一次——這個「今天還要再考一次」的狀態**只存在記憶體裡，沒有進 `localStorage`**。

`剩餘 X 張不會減少、會繼續出現在今天的佇列裡`是刻意的設計（`src/lib/review.test.ts:168` 有測試涵蓋），這部分沒問題。

問題在重整（或任何造成 `src/app.ts` 的 `start()` 重跑的情況，例如關掉分頁再打開）：

```ts
let data = store.load();
let queue = buildQueue(data.cards, now(), random);
```

`store.load()` 讀回的卡片，`due` 已經是明天；`buildQueue()` 只認 `due <= 今天`，於是這張卡直接被濾掉，從今日佇列裡消失。使用者以為「再次」的卡還會再出現，結果永遠等不到。

## 重現步驟

1. 進入複習畫面，任選一張卡標「再次」。
2. 觀察：剩餘張數沒變，這張卡稍後確實會再輪到（記憶體內佇列正常）。
3. 重整頁面（或關閉分頁重開）。
4. 這張卡從今日佇列消失，即使它理論上「今天還要再考一次」。

## 待決定

修法牽涉一個設計決定，不是單純的程式錯誤：

1. **重整後，「再次」的卡該不該繼續留在今天的佇列？**
   - **選項 A**：「再次」時 `due` 改設為今天（不是明天），讓 `buildQueue()` 重整後仍撈得到它，同時滿足「今天再考一次」的需求。需要確認：這樣改會不會影響「今天沒複習完就結束、下次登入」時的長期排程意義（`interval` 重設為 1 天這件事本身要不要跟著調整）。
   - **選項 B**：把「今天還要再考一次」這個暫存狀態額外持久化（例如把當前佇列本身也存進 `localStorage`，重整後還原佇列，`due` 照樣設明天，長期排程不受影響）。
