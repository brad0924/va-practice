# 把卡片收進單字本，並支援多本

拆成七張實作票，見 `issues/` 底下各檔。本檔案是七張票共用的決策紀錄，不直接實作。

## Problem Statement

目前所有卡片是一坨：132 張內建卡加上使用者自己新增的，全部混在同一個 `cards` 陣列裡。這帶來三個具體的痛：

1. **複習範圍無法切換。** 使用者想「這個月只衝 N2」或「這週只練工作用的字」時，做不到——當日到期的卡一律全數進佇列。
2. **卡片沒有歸屬。** 使用者自己新增的字與內建牌組的字無法區分，也無法依主題整理。找一個詞只能靠搜尋。
3. **內建牌組是唯一的來源。** 卡片只能來自「隨程式發佈的那一份」或「一張一張手動新增」，沒有辦法把一批既有的字整批帶進來。

`docs/spec.md` 的 Out of Scope 原本明文寫著「**多牌組**：僅支援單一牌組」。本 spec 推翻該項。

## Solution

引入**單字本**：卡片的容器，使用者可以自由新增、改名、刪除。一張卡剛好屬於一本。

複習、卡片列表、統計三個畫面各有一組**獨立的**單字本範圍開關，決定該畫面看哪幾本。三組互不影響，都預設全選。

內建牌組完全退場——`src/data/cards.json`、單向合併、`knownBuiltinIds` 一併刪除。卡片改由使用者自己新增，或用新的**匯入單字**功能，把一份備份檔的卡整批帶進指定的一本。

## User Stories

### 單字本本身

1. 作為使用者，我想要新增一本單字本並替它取名，這樣我才能把不同主題的字分開放。
2. 作為使用者，我想要替既有的單字本改名，這樣當我對分類的想法改變時不必重建。
3. 作為使用者，我想要刪除一本單字本，這樣不再需要的整批字可以一次清掉。
4. 作為使用者，我想要在刪除前被告知「會一併刪掉幾張卡與它們的複習進度」，這樣我不會誤按而丟失幾個月的成果。
5. 作為使用者，我想要在單字本清單上看到每本有幾張卡，這樣我不必進去就知道規模。
6. 作為使用者，我想要在取了重複的名字時被擋下來，這樣下拉選單裡不會出現兩個長得一樣的選項。
7. 作為使用者，我想要「JLPT N2」與「jlpt n2」、「ＪＬＰＴ　Ｎ２」被視為同一個名字，這樣我不會不小心建出兩本肉眼分不出來的本。
8. 作為使用者，我想要單字本畫面顯示我原本打的字（不是被正規化後的小寫），這樣名字看起來就是我取的樣子。
9. 作為使用者，我想要單字本可以刪到一本都不剩，這樣我可以徹底重來。
10. 作為第一次使用的人，我想要在還沒有任何單字本時看到明確的空狀態與「新增單字本」入口，這樣我知道下一步該做什麼。

### 卡片的歸屬

11. 作為使用者，我想要在新增卡片時指定它屬於哪一本，這樣它一開始就有家。
12. 作為使用者，我想要新增卡片時的單字本預設是「上一張卡選的那本」，這樣連續往同一本加字時不必每次重選。
13. 作為使用者，我想要編輯一張既有的卡時改掉它的單字本，這樣搬家不需要刪掉重建。
14. 作為使用者，我想要卡片搬家時複習進度跟著走，這樣重新分類不會讓我重練。
15. 作為使用者，我想要在卡片列表的每一列看到那張卡屬於哪一本，這樣多本混在一起時我分得出誰是誰。
16. 作為使用者，我想要複習畫面上**不要**顯示單字本，這樣答題時視線裡沒有多餘的提示。
17. 作為使用者，我想要同一個詞在整個 app 裡只會有一張卡，這樣我不會在同一天被問到同一個詞兩次。
18. 作為使用者，當我新增或編輯的詞條已經存在於別本時，我想要被擋下來並知道它現在在哪一本，這樣我可以直接去把那張搬過來。

### 範圍開關

19. 作為使用者，我想要指定複習只練哪幾本，這樣我可以集中衝刺某一個主題。
20. 作為使用者，我想要卡片列表只顯示哪幾本，這樣我在管理某一批字時不必在全部之中翻找。
21. 作為使用者，我想要統計只算哪幾本，這樣我看得到單一主題的進度而不是被全部稀釋。
22. 作為使用者，我想要這三組開關各自獨立，這樣「我在練什麼」與「我在看什麼」互不干擾。
23. 作為使用者，我想要三組開關都能複選，這樣我可以同時練兩本而不是被迫二選一。
24. 作為使用者，我想要每組開關都有一個「全部」項目，這樣我可以一鍵回到全選。
25. 作為使用者，我想要開關至少要留一本被勾選，這樣我不會不小心把畫面弄成空的。
26. 作為使用者，我想要在只剩一本單字本時那本的勾選不能取消，這樣「至少一本」的規則不會被繞過。
27. 作為使用者，我想要開關的選擇被記住，這樣關掉瀏覽器隔天打開還是我上次設的範圍。
28. 作為使用者，我想要開關的選擇跟著雲端備份走，這樣我在手機上設好的範圍，電腦打開也是一樣的。
29. 作為使用者，我想要新建的單字本自動被三組開關勾上，這樣我剛加的字馬上就會出現在複習裡。
30. 作為使用者，我想要複習畫面上**不要**有單字本開關，這樣複習畫面維持乾淨。
31. 作為使用者，我想要複習範圍在資料頁改完、回到複習畫面時就生效，這樣我不用重整頁面。

### 匯入

32. 作為使用者，我想要把一份備份檔的卡整批匯進指定的一本，這樣我不必一張一張重打。
33. 作為使用者，我想要匯入時複習進度（間隔、成長倍數、到期日）原封不動搬過來，這樣我累積的成果不會歸零。
34. 作為使用者，我想要匯入時已經存在的詞被跳過而不是整批失敗，這樣三張重複不會擋掉一百五十九張。
35. 作為使用者，我想要匯入結束後一次看到所有被跳過的詞（而不是匯一個跳一次訊息），這樣我一眼就知道發生了什麼。
36. 作為使用者，我想要在被跳過的清單上看到那個詞現在在哪一本，這樣我知道去哪裡找它。
37. 作為使用者，我想要「匯入備份」（整份覆蓋、換裝置用）與「匯入單字」（加進某一本）是兩個分開的功能，這樣我不會弄錯而蓋掉整台裝置的資料。

### 升級與相容

38. 作為既有使用者，我想要升級後打開 app 時，原本的卡自動被收進一本，這樣我的 162 張卡與幾個月的進度不會消失。
39. 作為既有使用者，我想要那本可以改名或刪掉，這樣自動收出來的分類不會綁死我。
40. 作為既有使用者，我想要舊格式的備份檔仍然匯得進來，這樣我留存的檔案不會作廢。
41. 作為既有使用者，我想要雲端上那份舊格式資料被拉下來時同樣自動收成一本，這樣換裝置接得回來。

## Implementation Decisions

### 領域概念

**單字本（Vocabulary Book）**：卡片的容器。有一個使用者自取的名字與一個穩定不變的識別碼。一張卡剛好屬於一本，不能同時屬於多本，也不能不屬於任何一本。

**詞條全域唯一**：同一個詞條在整個 app 裡只會有一張卡，跨單字本亦然。想讓另一本擁有某個詞，唯一的辦法是把那張卡搬過去。

**複習範圍／列表範圍／統計範圍**：三組各自獨立的單字本選擇，決定對應畫面看哪幾本。三組都是複選、都至少要有一本、都隨資料一起備份。

### 模組與接縫

**不新增接縫。** 單字本的一切收進既有的**資料存取**接縫（`src/lib/storage.ts`）：

- 單字本的新增、改名、刪除
- 名稱正規化與重名檢查
- 詞條全域唯一的檢查
- 匯入單字與重複回報
- 舊格式資料的遷移
- 三組範圍選擇的持久化

**複習流程與統計的模組完全不動。** `buildQueue()` 與 `computeSnapshot()` 已經是吃 `Card[]` 的純函式，把過濾後的卡片傳進去即可——它們不需要知道單字本存在。過濾本身是一支純函式（「取出屬於這幾本的卡」），與其他範圍相關的判斷一起放在資料存取模組，三個畫面共用同一支。

**卡片列表的既有純邏輯不動。** `groupByBucket()` 與搜尋過濾維持原狀，單字本篩選發生在它們之前。

畫面層仍然只負責建立元素、註冊事件、中文文案與樣式。

### 資料模型

`AppData` 的變化：

- 新增 `books`：單字本清單，每本有識別碼與名字，順序即畫面上的顯示順序。
- `Card` 新增 `bookId`：指向所屬單字本。
- 新增三組範圍選擇：複習、列表、統計各一組單字本識別碼的集合。
- 移除 `knownBuiltinIds`。
- `version` 升到 `3`。

新單字本的識別碼用 `crypto.randomUUID()`，與新卡的識別碼同一套做法。名字可改，識別碼不變。

### 名稱規則

名稱不可為空白。重名以**正規化後的值**比對，正規化步驟依序為：Unicode NFKC（統一全形半形）→ 轉小寫 → 去除前後空白 → 中間連續空白收成一個。正規化只用於比對，**畫面上顯示的永遠是使用者原本輸入的字串**。

不設長度上限，過長由畫面截斷顯示。

違規在按下確定時擋下並顯示原因，不做邊打字邊提示——沿用編輯器現有「詞條與釋義沒填就存不下去」的做法。

### 詞條全域唯一

比對基準沿用單向合併原本在用的規則：**去掉讀音標記後的詞條原文**（`焚[こ]がす` 與 `焚がす` 視為同一個），釋義不參與比對。

新增卡片、編輯卡片改詞條、匯入單字三條路都受此約束。被擋下時要指出該詞現在在哪一本。

### 範圍開關

三組獨立，都是複選，都必須至少有一本被勾選。只剩一本單字本時，那本的勾選不可取消。

每組的下拉最上面有一個「全部」項目，點它把所有本勾起來。全部勾滿時收合後的標籤顯示「全部」，否則顯示本名或本數。

新建的單字本一律自動加入三組。刪除的單字本一律自動從三組移除。

三組選擇存在 `AppData` 裡，因此進備份檔、也跟著雲端備份走。**這是對 `src/ui/list-view.ts` 現有註解「UI 偏好不進 storage.ts」的刻意例外**——排序方向與桶的展開狀態仍然只活在畫面裡，但單字本範圍是「我現在在讀哪幾本」這種讀書狀態，使用者明確要求跨裝置一致。

零本時三組皆為空，畫面顯示空狀態。

### 各畫面的位置

**資料頁**：新增「單字本」區，放在**最上面**（雲端備份、Gemini 金鑰、備份檔案之前），可收縮、預設展開。一本一列：勾選框（＝納入複習範圍）＋ 本名 ＋ 張數。點該列展開，才出現「改名」「匯入」「刪除」三顆。區塊底部一顆「新增單字本」。

**複習畫面**：不放任何單字本開關，頂部列維持「剩餘 N 張」與「卡片」。複習範圍在資料頁改完，回到複習畫面時重建佇列。

**卡片列表**：上方一組單字本篩選（獨立於複習範圍）。每一列右邊顯示該卡所屬的本名。

**統計頁**：一組單字本範圍（獨立於前兩者）。**不另外做「每本一列」的比較表**——想看單一本切過去即可。

**編輯器**：新增一個「單字本」下拉。新增卡片時預設「這次開 app 期間上一張卡選的那本」，第一次進來則是清單第一本；此偏好只活在記憶體，不進儲存。編輯既有卡時改掉它就等於搬家，進度跟著走。

### 匯入是兩個功能

**匯入備份**（資料頁「備份檔案」區，既有功能）：整份覆蓋整台裝置，換裝置用。行為不變，只是內容多了單字本與範圍選擇。

**匯入單字**（單字本區，每本各自一顆，新功能）：吃本 app 匯出的備份 JSON，把其中的卡加進**按下按鈕的那一本**。`interval`、`ease`、`due` 原封不動搬過來。若吃到新格式（含多本）的備份檔，其中的卡**全部壓進目標那一本**，來源的單字本結構不還原。

重複的處理：**跳過重複的、其餘照匯**。匯入結束後一次列出所有被跳過的詞，每一筆標明它目前在哪一本。檔案自己內部的重複（同一份檔裡兩張同詞）併入同一份清單。

### 內建牌組退場

刪除 `src/data/cards.json`、單向合併邏輯、`knownBuiltinIds`。第一次打開 app 是零本。資料存取模組不再需要「內建牌組」這個建構參數。

### 舊格式遷移

新版讀到沒有 `books` 的資料時，**自動把所有卡收進一本名為「我的單字」的單字本**，進度完整保留，並把三組範圍設為含該本。使用者之後可以改名或刪除。

三條路徑共用同一套相容邏輯：本機 localStorage、匯入備份檔、雲端拉下來的那份。也就是說相容處理發生在既有的解析入口，而不是散在三處。

無效的 `bookId`（指向不存在的單字本）比照處理：收進「我的單字」，必要時建立它。

## Testing Decisions

**好的測試只驗證外部行為，不碰內部實作**。測試描述「給定這份資料與這串操作，結果應該如何」，而非「某個內部函式被呼叫了幾次」。

本次所有新邏輯都落在既有的**資料存取**接縫上，因此測試也集中在該接縫（prior art：`src/lib/storage.test.ts` 的 `fakeStorage()` 假本機儲存，同一個 storage 傳給不同的 store 等同重開 App）。要涵蓋的情境：

- **單字本 CRUD**：新增後出現在清單且自動進入三組範圍；改名不影響裡面的卡；刪除連同該本的卡一起消失，且該本從三組範圍移除；可以刪到零本。
- **名稱規則**：空白被拒；四種正規化情境（前後空白、中間連續空白、大小寫、全半形）皆判為重名；顯示值保留使用者原輸入；改名撞到別本同樣被拒；改名成自己原本的名字不算重名。
- **詞條全域唯一**：跨本新增同詞被拒並回報所在的本；編輯改詞條撞到別本被拒；改成自己原本的詞條不算撞。
- **卡片搬家**：改 `bookId` 後 `interval`／`ease`／`due` 不變。
- **範圍過濾**：那支純函式在單本、多本、全選、空集合下的結果。
- **匯入單字**：進度原封搬過來；重複的被跳過而其餘照匯；回報清單含所有重複項與各自所在的本；檔案內部重複併入同一份清單；新格式多本備份被壓進目標一本；壞檔案不弄壞既有資料（沿用既有的「先驗證再寫入」行為）。
- **舊格式遷移**：無 `books` 的資料被收進「我的單字」且進度保留、三組範圍含該本；`bookId` 指向不存在的本時同樣被收攏；已是新格式的資料不受影響（不重複建立「我的單字」）。
- **匯入備份**：整份覆蓋的既有行為不變，且新格式的 `books` 與範圍選擇一併覆蓋。
- **原有的單向合併測試整批刪除**（該行為已不存在）。

**畫面本身不撰寫自動化測試**，依 `docs/spec.md` 既有決定。`src/ui/` 底下不 import DOM 的純邏輯照常測試——本次 `groupByBucket()` 與 `computeSnapshot()` 皆不變動，既有測試應保持全綠。

以下靠手動驗收：資料頁單字本區的收縮與展開、三組開關的 UI 行為（含「全部」項目與「只剩一本不可取消」）、編輯器下拉的預設值、卡片列表列上的本名、匯入結果的那份清單長什麼樣、複習範圍改完回到複習畫面佇列重建。

## Out of Scope

- **批次搬移**：不做「選取模式」勾多張一次搬。搬家一次一張，在編輯器裡做。
- **卡片列表上直接搬家**：列上的本名只顯示、不可點。
- **統計的單字本比較表**：不做「每本一列」的橫向比較。
- **CSV 或純文字匯入**：匯入單字只吃本 app 的備份 JSON。
- **單字本排序與拖曳**：順序即建立順序，不提供調整。
- **單字本的顏色、圖示、描述欄位**：只有名字。
- **每本各自的每日新卡上限或排程參數**：排程仍是全域一套。
- **一張卡屬於多本**：明確否決，見下。
- **保留內建牌組作為「可選匯入」**：明確否決，內建牌組完全退場。
- **升級時清空本機資料**：明確否決，舊資料自動收成一本。

## Further Notes

### 訪談中先後提出並被否決的方案

- **單字本只當分類、不影響複習**：被否決。使用者要求「至少要選一本」，這個約束本身就意味著選擇會影響複習。
- **一張卡掛多本（標籤模型）**：被否決。統計加起來會超過總數、刪本時「只在這本裡的卡怎麼辦」沒有乾淨的答案、佇列要去重。
- **兩本各一張獨立的卡**：被否決。同一個詞一天被問兩次，且改了一邊另一邊不會跟著改。
- **三個畫面共用一組全域開關**：被否決。使用者明確要求三個分開控制。
- **內建牌組保留為「可選匯入」或「維持自動塞入」**：兩者皆被否決，選擇完全退場。
- **升級時真的從零開始（舊資料不管）**：訪談中一度傾向此案，最後改為自動收成一本——「自己匯入」的前提是手上先有備份檔，忘了先匯出就沒了。
- **匯入時整批擋下**：被否決。162 張卡 3 張就卡死，而這個 app 沒有「改匯入檔」的工具。
- **重名只去前後空白（最寬）**：被否決。使用者選了最嚴的一組（全形半形、大小寫、連續空白皆歸一）。
- **複習畫面上放單字本開關**：被否決。使用者選擇維持複習畫面乾淨，複習範圍改到資料頁設定。

### 與既有文件的衝突

- `docs/spec.md` 的 Out of Scope 有一項「**多牌組**：僅支援單一牌組」，本 spec 推翻它，該行需一併更新。
- `CONTEXT.md` 需新增「單字本」「詞條全域唯一」「複習範圍」「匯入單字」等詞條，並刪除「內建牌組」「單向合併」。
- ADR-0002（localStorage 為單一資料來源）不受影響。ADR-0004、ADR-0005 不受影響。

### 佇列順序

`buildQueue()` 的洗牌邏輯不動。多本混在一起時，各本的卡自然交錯出現，不做「同一本連續出題」之類的分組。
