# 匯入單字：把一份備份檔的卡加進指定的一本，重複的一次列出

Status: done
Type: enhancement

決策背景見 `.scratch/vocabulary-books/spec.md`。依賴 `01` 與 `03`。

## 需求

新增一個與「匯入備份」**分開**的功能：吃本 app 匯出的備份 JSON，把其中的卡加進指定的一本，複習進度原封搬過來，已存在的詞跳過並在結束時一次列出。

## 決定

1. **與 `importJson()`（整份覆蓋）是兩個不同的操作，不合併。** 兩者意圖相反：一個把整台裝置變成另一台的樣子，一個往某一本裡加料。`importJson()` 行為完全不變。

2. **介面形狀**（可微調，但必須回報得出被跳過的每一筆與它所在的本）：

   ```ts
   export interface ImportSkip {
     /** 去掉讀音標記後的詞條原文，直接顯示給使用者。 */
     term: string;
     /** 這個詞目前所在的單字本；來源檔案內部重複時為目標本。 */
     bookId: string;
   }

   export interface ImportResult {
     data: AppData;
     imported: number;
     skipped: ImportSkip[];
   }

   /** 把 json 裡的卡加進 bookId 那一本。整份寫回並回傳結果。 */
   importWords(json: string, bookId: string): ImportResult;
   ```

3. **只吃本 app 的備份 JSON**，新舊格式都吃。不支援 CSV 或純文字清單。

4. **進度原封不動搬過來**：`interval`、`ease`、`due` 照抄。卡片識別碼沿用來源檔案裡的；與現有卡撞號時重新產生一個，避免覆蓋既有卡。

5. **新格式（含多本）的備份檔，其中的卡全部壓進目標那一本**，來源的單字本結構不還原。理由：按鈕就長在某一本上，語意即「匯進這本」。

6. **重複的判斷沿用詞條全域唯一那一套**（`toPlainText(card.text)` 比對，釋義不參與），比對對象是**全 app 的卡**而非只有目標本。

7. **跳過重複的、其餘照匯。** 不整批擋下、不預告後再確認、不逐筆詢問。

8. **檔案自己內部的重複併入同一份清單**：同一份檔裡兩張同詞時，第一張匯入、第二張列進 `skipped`，其 `bookId` 為目標本。

9. **壞檔案不弄壞既有資料。** 沿用 `importJson()` 現有的「先驗證再寫入」順序：JSON 解析失敗或格式不合時丟出可直接顯示的例外，一張卡都不寫。

10. **目標單字本不存在時視為錯誤**，丟例外，不自動建立。

11. **一次匯入是一次本機資料變動**，成功後要走既有的存檔與推上雲端那條路（見 `app.ts` 的 `persist()`）。

## 驗收

- `npm test` 全綠。
- 匯入一份 3 張卡的舊格式備份到空的一本：3 張都進去，每張的 `interval`／`ease`／`due` 與來源一字不差，`bookId` 全部是目標本。
- 全 app 已有 `打ち合わせ`（在 A 本）時，匯入含該詞的檔到 B 本：那張被跳過、`skipped` 裡有一筆且 `bookId` 是 A 本，其餘照匯。
- 來源檔案自己內含兩張 `約束`：第一張進去、第二張列進 `skipped` 且 `bookId` 是目標本。
- `imported` 與實際新增張數一致，`imported + skipped.length` 等於來源卡片總數。
- 匯入新格式（兩本、共 5 張）的備份檔到目標本：5 張全部 `bookId` 指向目標本，`books` 沒有多長出來源的那兩本。
- 壞 JSON 與缺欄位的檔案：丟出可讀的例外，且既有資料一張卡都沒變。
- 目標 `bookId` 不存在時丟例外。
- 讀音標記不同但詞條相同（`焚[こ]がす` vs `焚がす`）判為重複。

## Comments

- **決定 11 的落地寫在 `app.ts`**：`store.importWords()` 只負責寫回本機，推上雲端那一步照票 03 的理由不由 `Store` 自己做。因此本票一併加了 `App.importWords()`，形狀完全比照既有的 `importBackup()`（`store.importXxx()` → `reload()` → `cloud.push(data)`），而不是字面呼叫 `persist()`——`persist()` 會再存一次已經存好的東西，且 `importBackup()` 本來就沒走它。票 05 的畫面直接呼叫 `app.importWords()` 即可，不必自己碰 store 或 cloud。
- **重複比對是邊收邊比**：`findTermConflict()` 吃的是「已經收下的全部」而不是原本那份，所以決定 6（比對全 app）與決定 8（檔案內部重複）走的是同一行程式碼，內部重複回報的本自然就是目標本，不必另外寫一段。
- **識別碼撞號用 `Set` 追蹤而非只看既有的卡**：同一份來源檔裡兩張卡帶同一個 id 時，第二張同樣會拿到新的識別碼。票上只寫「與現有卡撞號」，但只擋既有的話那兩張會在 app 裡同號。
- **順手抽出的兩支小函式**：`blank()`（`load()` 與 `importWords()` 共用的「零本零卡那一份」）與 `parseJson()`（兩條匯入共用的 JSON 解析與錯誤訊息）。都是本次新增造成的重複，非既有程式碼的重構。
- **`ImportResult.data` 對 `app.ts` 而言是多餘的**（它接著 `reload()` 會重讀一份）。仍照票上的介面形狀保留，因為測試直接吃它比從 storage 讀回來讀得清楚。
