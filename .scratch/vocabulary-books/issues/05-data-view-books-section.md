# 資料頁的「單字本」區：清單、複習範圍勾選、改名／匯入／刪除

Status: done
Type: enhancement

決策背景見 `.scratch/vocabulary-books/spec.md`。依賴 `01`、`03`、`04`。本票只做畫面。

## 需求

資料頁長出「單字本」區，是新增／改名／刪除單字本、匯入單字、以及設定**複習範圍**的唯一地方。

## 決定

1. **放在資料頁最上面**，在既有的雲端備份、Gemini 金鑰、備份檔案三區之前。

2. **整區可收縮，預設展開。** 放到最上面就是因為它是主角，一進去還收著等於白放。（卡片列表的時間桶預設收合是另一回事，那裡一次要塞一百多列。）

3. **一本一列**：勾選框 ＋ 本名 ＋ 張數。勾選框的意義是「**納入複習範圍**」——這是複習範圍唯一的設定入口，複習畫面上不放任何開關。

4. **點該列展開，才出現「改名」「匯入」「刪除」三顆。** 平常看到的就是「哪幾本要練」這件事，不常用的維護鈕收起來。同時只展開一列。

   ```
   單字本                    ▾
   ───────────────────────────
    ☑ JLPT N2         132 張
    ☑ 工作用日文        30 張
      └─ [改名] [匯入] [刪除]
    ☑ 文法句型          18 張

    [+ 新增單字本]
   ```

5. **只剩一本時，那本的勾選框 disabled**，避免違反「至少一本」。

6. **零本時**顯示「還沒有單字本」與「新增單字本」入口，不顯示空的清單。

7. **新增與改名用同一組輸入介面。** 名稱違規（空白、重名）時在按下確定後顯示原因，不做邊打字邊提示——沿用編輯器現有「詞條與釋義沒填就存不下去」的做法。

8. **刪除前跳確認**，訊息必須說出張數與不可復原：形如「將一併刪除 30 張卡片與它們的複習進度，無法復原。」沿用資料頁現有 `confirm()` 的做法（見 `STOP_CONFIRM`）。

9. **匯入單字**沿用備份檔那一區既有的選檔做法。結束後**一次列出所有被跳過的詞**，每一筆標明它目前在哪一本；匯入張數也要顯示。清單可能很長，需可捲動，且不會被壓出容器外（見 `.scratch/stats-snapshot` 的同類修正）。

   ```
   已匯入 159 張

   以下 3 個詞已存在，已跳過：
    ・打ち合わせ（JLPT N2）
    ・焚がす（JLPT N2）
    ・約束（JLPT N2）
   ```

10. **複習範圍改動後回到複習畫面時重建佇列。** 資料頁本身不需要立即重建。

11. 中文文案與樣式一律留在畫面這一側；所有判斷（名稱是否合法、範圍是否會被清空、匯入結果）都來自資料存取模組。

## 驗收

手動驗收（依 `docs/spec.md`，畫面不寫自動化測試）：

- 資料頁最上面就是「單字本」區，預設展開，可收起來再打開。
- 新增一本 → 出現在清單末端、勾選框已勾、張數為 0；~~回到複習畫面，該本的卡（若有）會進佇列~~（後半段延到票 06，見 Comments）。
- 取名為空白 → 被擋並看得到原因；取名為既有本的另一種大小寫／全形寫法 → 被擋。
- 改名 → 清單上的名字變了，該本張數不變，卡片列表上該本的卡仍在。
- 點一列 → 出現三顆鈕；點另一列 → 前一列收起來。
- 刪除 → 跳出含張數的確認；取消則什麼都沒發生；確認則該本與它的卡一起消失，且從三組範圍移除。
- 只剩一本時，那本的勾選框點不動。
- 全部刪光 → 顯示「還沒有單字本」與新增入口。
- 匯入一份含重複詞的備份檔 → 看到匯入張數與完整的跳過清單，清單長時可捲動、不被切掉。
- ~~取消某本的勾選 → 回到複習畫面，該本的卡不再出現在佇列~~（延到票 06，見 Comments）；卡片列表與統計不受影響。

## Comments

- **新增了一支 `App.applyData()`**。票上寫「本票只做畫面」，但 `addBook` / `renameBook` / `deleteBook` / `setScope` 是吃一份 `AppData` 吐一份新的純函式（票 03 的形狀），`app.ts` 原本沒有任何入口收得下那份新的。照票 03 的理由（畫面不自己碰 store，否則繞過 `cloud.push()`）補在 `app.ts`：換上新的那份、把已刪掉的卡從佇列剔除、走既有的 `persist()`。

- **勾選框 disabled 的條件比票上寬一格**：票上寫「只剩一本時 disabled」，實作寫的是「取消它會讓複習範圍空掉時 disabled」。三本只勾一本時，取消那一本同樣會違反「至少一本」，`setScope()` 會丟例外——列上沒有放紅字的地方，讓它按不動比按了才吃錯誤好。票上那個情況是這條規則的特例（只有一本時，那本必然是唯一被勾的），因此涵蓋得到。

- **匯入結果畫在該本底下，不另開彈窗**。票上要求「可捲動、不被壓出容器外」，`.skip-list` 自己 `max-height: 40vh` 加 `overflow-y: auto` 就滿足了，不必把 `stats-view.ts` 的 `.modal-*` 抽成共用元件——那是本票沒要求的重構。

- **這一區自己重畫，不呼叫 `app.showData()`**。資料頁其他三區改狀態時是整頁重畫，但單字本區有展開狀態與取名中的輸入框，整頁重畫會順手清掉雲端那區使用者打到一半的密碼。因此獨立成 `src/ui/books-section.ts`，內部留一支 `refresh()`。

- **名字違規時就地寫紅字、不重畫**，使用者打的字才留得住。這是取名表單不走 `refresh()` 的唯一原因。

- **決定 10 與兩條驗收延到票 06，上面已劃線標明。** 「回到複習畫面重建佇列」要有東西可重建，前提是 `buildQueue(cardsInBooks(cards, scopes.review), …)`——那是票 06 的決定 2，先做決定 10 只會得到一支重建出同一份佇列的死程式碼。票 06 的驗收本來就涵蓋這兩條（「取消某本的複習勾選 → 回複習畫面，該本的卡不出現在佇列」、「在複習範圍內的本新增一張卡 → 立即進入當日佇列」），不必另外搬。本票只到「範圍存進 `scopes.review` 並跟著備份走」為止；`applyData()` 只剔除被刪掉的卡，那是決定 8 的正確性所需，不是提前做票 06。

- **手動驗收在瀏覽器上跑過**（隔離的 origin，不動使用者本機那份）：預設展開與收合、三本的清單與張數、點列展開／同時只展開一列、全形大小寫重名被擋（「已經有一本叫「JLPT N2」了」）、空白被擋、改名後張數不變、勾到只剩一本時上鎖、刪除的確認訊息帶張數、取消不動作、確認後卡與三組範圍一起消失、刪到零本的空狀態、新增後進三組範圍且張數 0。匯入用一份 33 張的檔（20 新 + 12 撞既有本 + 1 檔案內部重複）匯進第三本：顯示「已匯入 20 張」與 13 筆跳過清單，每筆標明所在的本，清單自己捲動。
