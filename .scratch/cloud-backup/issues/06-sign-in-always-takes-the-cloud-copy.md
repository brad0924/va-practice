# 06 — 登入一律以雲端那份為準，不再比新舊

Status: ready-for-agent
Type: enhancement

修的是票 `05` 記錄的災情。病因與最小重現在那張票，這張只寫要做成什麼樣子。
決策過程見底下的 Comments。

## 為什麼是這個修法

票 `05` 的〈待決定〉列了四個方向，全部沒被採用。談的過程中發現一件事把它們一起淘汰掉：

**那四條裡有三條都要先分得出「同暱稱」與「跨暱稱」**，而程式沒有那個資訊——`AppData`
只有 `updatedAt`，沒有一格記著這份資料上次推給誰。要分得出來就得加一格血統，再加一格
「推上去之後改過沒有」（`updatedAt` 只在推成功時動，離線改的東西不留痕跡），
外加一段舊資料遷移。

改成**登入不再比新舊**之後，那兩格欄位都不需要了：既然本機那份永遠不會被推上去覆蓋別人，
「它本來屬於誰」就不必知道。`AppData` 一個字不動，沒有遷移。

## 規則

登入某個暱稱時，先讀那個暱稱的雲端備份，然後分兩大類。

**雲端已經有備份**

1. 先解密。解不開就是密碼不對，中止登入，雲端一個字不動。
   （現況只在「雲端較新」那條路上解密，另一條是送出去被安全規則擋在 401。改完兩條一致。）
2. 本機沒有資料 → 直接拉下來，登入成功。
3. 本機有資料，內容與雲端那份相同 → 直接拉下來，登入成功，不問。
4. 內容不同 → 跳確認框。**確定** → 拉下來，登入成功。**取消** → 不登入，本機一個字不動。

**雲端還是空的**

5. 本機沒有資料 → 直接建立備份，登入成功。
6. 本機有資料 → 跳三選一：**用這台的資料**（推上去建立備份）／**清空，重新開始**
   （本機清成剛裝好的樣子再推上去）／**取消登入**。

**沒有任何一條路寫得到別人現有的雲端備份。** 這就是票 `05` 被收掉的地方。

### 「內容相同」怎麼比

整份比，只排除 `updatedAt` 那一格。複習進度不同也算不同——那本來就會被蓋掉，該問。

排除是必要的，不是省事：密文裡那份 `AppData` 的 `updatedAt` 記的是**上一次**推成功的時間戳，
而本機現在那格已經被 `onPushed` 回寫成**這一次**的，兩個數字天生不相等
（`core/lib/cloud-backup.ts` 的 `write()` 與 `flush()`）。

### 沒有動到的東西

`begin()`（開 app 自動拉）、`push()`（平常改東西自動推）、`changePassword()`、`signOut()`
全部照舊。`CONTEXT.md` 那句「較新的那一份整份勝出」在這三條路上仍然成立。

## 要改的東西

### 程式

- **`core/lib/cloud-backup.ts`**：`signIn()` 改成上面那條規則。兩個問句從
  `CloudBackupHooks` 遞進來，回 `Promise`——接法照 `core/lib/cloud-consent.ts` 的先例
  （core 定介面、不碰畫面，各版接自己的對話框）。
- **`core/lib/storage.ts`**：`blank()` 目前是私有的，「清空，重新開始」那條路需要它。
  匯出即可，不要在別處重寫一份零本零卡。
- **`src/app.ts:116`** 與 **`mobile/lib/app-context.tsx:101`**：兩個 `createCloudBackup()`
  各自接上那兩個問句。
- **`src/ui/data-view.ts`**：網頁版的三選一。`confirm()` 只有兩顆按鈕，做不到，要自己畫一個
  ——`src/ui/stats-view.ts:170` 那個 `.modal-overlay` 是先例，CSS 已經在了，但它是拿來看東西的，
  選擇用的要新寫。兩選一那個照舊走 `confirm()`。
- **`mobile/ui/cloud-account-screen.tsx`**：手機版兩個都走 `Alert.alert()`，它收按鈕陣列，
  三顆沒問題（`mobile/lib/cloud-consent-native.ts:32` 現在放兩顆）。
  「清空，重新開始」帶 `destructive` 樣式，「取消」帶 `cancel` 並排在前（HIG `B-06`）。

### 文案（草案，實作時再定稿）

三種語言都要。**「同步」不出現在領域用語裡**，見底下〈詞彙〉。

- 兩選一：雲端上「{nickname}」的備份會整份蓋掉這台裝置目前的卡片與進度，且無法復原。
  想留住這台這份，請先取消，到資料頁匯出備份檔。確定要繼續？
- 三選一標題：「{nickname}」還沒有雲端備份
- 三選一內文：要用這台裝置目前的卡片與進度建立備份，還是清空這台、從頭開始？清空無法復原。
- 三選一按鈕：用這台的資料／清空，重新開始／取消

### 詞彙與文件

- **`CONTEXT.md` 的〈雲端備份〉**：「兩邊內容不一致時，較新的那一份整份勝出」要拆成兩句
  ——平常如此，登入是例外，指向新條目。
- **`CONTEXT.md` 新增〈登入〉**，擺在〈雲端備份〉後面。定義是「把這台裝置接上某個暱稱的
  雲端備份」，並寫明它不比新舊、以及「改用別的暱稱」走的是同一個動作。
  `_Avoid_`: 同步、連線、綁定、帳號登入
- **`docs/glossary.md`** 跟著加一列，**順序要與 `CONTEXT.md` 一致**
  ——`src/lib/glossary.test.ts` 釘住條目清單與順序，多一條少一條都紅燈。
  譯名：`登入 | Sign in | ログイン`
- **新開一張 ADR**（下一個編號是 `0020`）：登入一律以雲端那份為準，不比新舊。
  記下被淘汰的三個方向與各自的理由，以及「離線改過的東西不能靠重新登入帶上雲端」這個後果。

### 介面用詞：「同步」全部改成「備份」

**這是既有的違規，順手收掉，不是這次的新決定。** `CONTEXT.md` 與 `docs/glossary.md` 把
「同步」列為〈雲端備份〉的避用詞，理由是「會讓人誤以為兩邊的進度會被逐張合併」；
`core/i18n/en.ts` 的檔頭明文說連英文避用欄一起遵守，「全檔一個 sync 都沒有」。
**只有繁中與日文逆著走。**

- `core/i18n/zh-Hant.ts:185` `data.stopSync`：「停止同步」→「停止備份」
- `core/i18n/zh-Hant.ts:184` `data.changeHint`、`:206` `data.passwordUpdated`：
  「才能繼續同步」→「才能繼續備份」
- `core/i18n/ja.ts:148` `data.stopSync`：「同期を停止」→ バックアップ系の言い方
- `core/i18n/ja.ts:147`、`:163` 同上
- `core/i18n/ja.ts:9` 那句註解說「中文那份的『同步』在這裡照樣是『同期』」——前提沒了，要改
- `core/i18n/en.ts` 一個字都不用改，它本來就是對的

**技術性的「同步」留著**，那不是領域用語：`zh-Hant.ts:188` 講的是 Keychain 那一筆標記為
可同步、`zh-Hant.ts:292` 講的是兩個字串刻意不一致。

### 測試

- **`core/lib/cloud-backup.test.ts` 的 `describe('換暱稱')`**：兩條 `it.fails` 改成 `it`，
  **斷言一個字不動**。不管使用者按哪一顆，舊暱稱雲端那張卡都還在。
  兩條測試要各遞一個假的問句 hook 進去。
- 新增：規則六種情況各一條。特別是第 3 條（內容相同不問）與第 2、5 條（本機空的不問）
  ——那三條是「不該跳對話框」的守門，漏掉的話對話框會變成每次登入都跳。
- 網頁版新那個三選一元件要有自己的測試（jsdom，`ADR-0014`）。

## 驗收

1. 票 `05` 的最小重現走完，舊暱稱的雲端備份原封不動。
2. 兩個暱稱、同一組密碼，來回登入數次，兩邊的雲端備份各自完整。
3. 兩台裝置同步得好好的，重新登入同一個暱稱**不跳任何對話框**。
4. 全新裝置（本機零本零卡）登入一個已有備份的暱稱，**不跳對話框**，直接拉下來。
5. 本機有資料、登入一個全新暱稱，跳三選一；選「用這台的資料」後雲端有了，本機不變。
6. 同上，選「清空，重新開始」後本機零本零卡，雲端那份也是空的。
7. 同上，選「取消」後沒有登入，本機一個字不動。
8. 密碼打錯時，不論本機那份比雲端新或舊，都是同一句「暱稱或密碼不對」，雲端不動。
9. 繁中與日文介面上找不到「同步／同期」這兩個詞（Keychain 那條技術註解除外）。
10. `npx vitest run` 全綠，`npm run typecheck` 乾淨。
11. **實機**：iPhone 上跑第 1、5、6、7 條，確認 `Alert.alert` 三顆按鈕的排列與
    `destructive` 樣式正確。

## 這張票不做的事

- **不救資料。** 已經被覆蓋的那份救不回來，票 `05` 已經寫明。
- **不動開 app 自動拉那條路。** 同一個暱稱下雲端較新就整份拉下來、本機未推的變動跟著沒——
  維護者確認接受這個行為，不開票（見 Comments）。
- **不加血統欄位，不加「改過沒有」欄位，不做資料遷移。** `AppData` 一個字不動。
- **不改「停止備份」的行為**，只改它的名字。卡片與進度照舊完整留在本機。

走了一輪 `/grill-with-docs`。過程中有三件事值得留著。

**第一，四個候選方向是被同一個發現一起淘汰的。** 票 `05` 把「跳確認框」與「記住血統」
列成並排的選項，但確認框那條的觸發條件（本機比較新、雲端有東西）抓不住跨暱稱
——同一個暱稱離線改過再登入回來，條件一樣成立。要只在跨暱稱時跳，就得先有血統那一格。
**兩條其實是綁在一起的**，不是二選一。

**第二，簡化是維護者提的，不是 AI 提的。** 談到一半已經定案「加兩格欄位」，維護者反問
「登入時只要看雲端要帶回來的資料跟目前的一不一樣就好了，這樣是不是更簡單」。
推了一遍找不到破口，兩格欄位與整段遷移就一起消失了。

**第三，那顆按鈕的名字有前情。** 一度決定三種語言都改用「同步」，查下去才發現
