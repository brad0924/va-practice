# 雲端備份的控制項：停止同步、換密碼

Status: done
Type: enhancement

**Blocked by:** `01-cloud-backup-core.md`——本票的兩個控制項都是在「已登入」狀態下才會出現的操作，沒有登入與推拉機制無從測起。

## 決策依據

完整決策紀錄在 `../spec.md`，本票只列出與本張直接相關的決定：8（停止同步）、9（換密碼與其後果）、21 末段提到的指紋比對機制（換密碼靠 `prev` 與新指紋一起送出）。

## 要做出什麼行為

在「資料」畫面已登入狀態下，新增兩個動作：

- **停止同步**：忘掉本機記住的暱稱密碼，之後不再推拉雲端，回到未登入狀態；卡片與進度完整留在本機不受影響。
- **換密碼**：輸入新密碼後，雲端該筆資料改用新密碼的指紋與金鑰。操作完成後，介面要明確提示「其他還在用舊密碼的裝置會需要重新輸入新密碼」——這是機制決定的必然後果，不是可以隱藏的細節（決定 9）。

## 驗收

- 「停止同步」後不再有任何網路請求；本機卡片與進度完好；「資料」畫面回到未登入的樣子。
- 「換密碼」成功後，這台裝置用新密碼繼續正常推拉。
- 另一台仍記著舊密碼的裝置，下次推拉會被雲端擋下（密碼不對的提示），要求重新輸入；輸入新密碼後恢復正常同步。
- 換密碼流程中，介面明確告知「其他裝置需要重新輸入新密碼」這件事。
- 既有測試全綠；換密碼牽涉的指紋比對邏輯補上單元測試（純函式）。
