# 備份按鈕搬到獨立的「資料」畫面

Status: ready-for-agent
Type: enhancement

## 問題

匯出備份／匯入備份兩顆按鈕目前掛在「卡片」清單畫面的最底部（`dataSection()`，`src/ui/list-view.ts`），位置在卡片列之後。內建牌組有 132 張，加上使用者自己新增的卡只會更多，等於備份功能被埋在一份會持續變長的清單後面，每次都要滑到底才找得到。

備份是低頻但重要的動作，且匯入會整份覆蓋、無法復原。把它跟高頻的「瀏覽／搜尋卡片」混在同一個捲動頁面裡，兩邊都不舒服：備份難找，清單頁的職責也變模糊。

## 決定

1. **獨立成第四個畫面，命名「資料」。** 沿用 `dataSection()` 現有的 `section-title` 用字。語意比「備份」寬，日後要放「清空進度」「重灌內建牌組」這類同性質功能不必再改名；比「設定」誠實，因為裡面沒有任何可調的選項。
2. **入口放在卡片頁 header，變成四格 `[複習] [卡片] [資料] [新增]`。** 資料管理與卡片清單語意最近，且從複習頁按一次「卡片」就到得了。複習頁 header 不放入口——備份跟複習當下的情境無關。
3. **返回按鈕寫「卡片」。** 沿用複習頁「非表單畫面的按鈕寫目的地」的慣例（編輯頁寫「取消」是因為它是表單）。「資料」畫面只有卡片頁一個入口，直接呼叫 `showList()` 即可，不必像 `showEditor()` 那樣傳 `back` callback。
4. **這一版只搬，不加功能。** 說明文字、兩顆按鈕、隱藏的 file input、錯誤訊息列原封搬過去。不加統計資訊，不加危險操作。
5. **匯入成功仍跳回卡片頁，不加成功訊息。** 維持現行行為，使用者馬上看到新資料進來，等於用畫面本身當回饋。匯入失敗仍留在「資料」畫面顯示紅字。
6. **`<h2>資料</h2>` 拿掉。** header 標題已經是「資料」，留著是重複。

不開 ADR：這個決定不難逆轉，也沒有真正對立的替代方案，不符合開 ADR 的門檻。

## 驗收

- 卡片頁 header 為 `[複習] [卡片] [資料] [新增]` 四格，在 30rem 寬度上限下不擠壓、不換行、不溢出。
- 卡片頁最底部不再有備份區塊；`dataSection()`、`download()`、`status` 及連帶失效的 import 一併從 `list-view.ts` 移除。
- 按「資料」進入新畫面，header 為 `[卡片] [資料]`，按「卡片」回到清單。
- 「匯出備份」下載的檔名與內容與搬移前一致（`jlpt-cards-YYYY-MM-DD.json`）。
- 「匯入備份」仍先跳確認對話框；成功後回到卡片頁並看到新資料，失敗則留在「資料」畫面顯示紅字錯誤。
- `.data-section` 原本用來與卡片列拉開距離的 `margin-top` 與上框線，在獨立畫面已無意義，一併調整。
- 既有測試全綠。專案目前沒有 UI 層測試，本次不補——驗收靠實際開瀏覽器操作一輪。
