# 03 — 複習頁標題列加上單字本下拉，切換複習範圍

Status: done
Type: enhancement
Blocked by: 01, 02

## 現況

複習範圍目前只有一個入口：資料頁 → 單字本區 → 每一列的勾選框（`books-section.ts:94`）。從複習畫面要換一本得跑三四步。

這件事**當初是被否決的**。`.scratch/vocabulary-books/spec.md:223`：

> **複習畫面上放單字本開關**：被否決。使用者選擇維持複習畫面乾淨，複習範圍改到資料頁設定。

同一份 spec 第 150 行、以及 `review-view.ts:16`、`book-filter.ts:8` 兩處程式碼註解，都是這個決定的護欄。

**這張票推翻它。** 理由：當初「答題時視線裡不放多餘的東西」的顧慮，換來的是每次切本都要離開複習畫面；而開關放在標題列、不在答題區中央，對「視線乾淨」的破壞有限。舊 spec 依 `docs/agents/issue-tracker.md:12`（決策紀錄保留不刪）**不修改**，訂正寫在 `04`。

### 兩個現存的結構障礙

**一、複習頁是三支各自回傳完整畫面的函式。** `reviewView`（`review-view.ts:15`）、`doneView`（`:109`）、`noBooksView`（`:89`）各畫各的一整頁，任何互動都呼叫 `app.showReview()` 整頁重建。

**二、下拉不能整頁重建。** `stats-view.ts:95` 的註解講得很直白：

> 只重畫底下三區而不整頁重建，下拉才不會每勾一本就收起來。

兩個現有呼叫端都是局部重畫。複習頁抄不了同一招，因為**勾完之後佇列可能剛好空掉**，畫面得從「複習中」變成「今日份完成」——而那是另一支函式。

## 決定

### 合併 `reviewView` 與 `doneView`，共用同一條頂部列

一支函式建出整個畫面，頂部列建好就不再動；`main` 與 `footer` 依 `isComplete(app.queue)` 由 `refresh()` 換內容。`noBooksView` **維持獨立不合併**（見下）。

```
header（建一次，之後只更新「剩餘 N 張」）
  剩餘 N 張   〔bookFilter pill〕   卡片
main   ┐ refresh() 依 isComplete(app.queue) 換這兩塊
footer ┘
```

### 頂部列的三個位置

| 位置 | 內容 |
|---|---|
| 左 | `剩餘 N 張`（既有的 `.remaining`） |
| 中 | `bookFilter`，`variant: 'pill'` |
| 右 | `卡片` 按鈕（既有的 `.bar-action`） |

下拉當成這頁的標題——複習頁是四個畫面裡唯一沒有中央標題的，「現在在練哪幾本」正是這頁的標題。

**不加「單字本：」前綴**（那是 `block` variant 的事）：中央欄寬度有限，加前綴會讓本名被 `max-width: 9rem` 截得更兇，而 `▾` 已經足夠說明它可以點。**不新增第三個 variant。**

### CSS：讓複習頁的頂部列也吃三欄 grid

`styles.css:77` 的 `.bar:has(.bar-title)` 只對「有標題文字」的頂部列生效，複習頁沒有 `.bar-title`，選不到。用 `flex: space-between` 放三個東西不會真的置中（左右兩側寬度不等，就是 `.scratch/center-bar-title/` 修過的同一個毛病）。

作法：複習頁的 header 掛一個新 class，把 grid 規則的選擇器擴充成兩者都吃：

```css
.bar:has(.bar-title),
.bar.bar-centered {
  display: grid;
  grid-template-columns: 1fr auto 1fr;
  justify-items: start;
}
```

中欄需要 `justify-self: center`（`.bar-title` 現在自己帶著這行，新 class 底下的中欄要另外給）。`.bar > *:last-child:not(.bar-title)` 那條讓最右欄靠右的規則不用改，複習頁最右仍是「卡片」按鈕。

選單是 `position: absolute; right: 0`（`styles.css:389`），最小寬度 `12rem`，從中央往左長，穩穩在畫面內。

### 勾選只重畫 `main` 與 `footer`

```ts
const books = bookFilter({
  books: app.data.books,
  selected: app.data.scopes.review,
  variant: 'pill',
  onChange: (ids) => {
    app.applyData(setScope(app.data, 'review', ids));
    refresh();
  },
  onOpenChange: (open) => { menuOpen = open; },
});
```

`app.applyData()` 走 `01` 的 `rebuildQueue()`：正在看的那張若仍在範圍內就留在最前面、答案還掀著；不在了就換下一張。

**`onChange` 裡絕不呼叫 `app.showReview()`**——那會整頁重建、選單跟著消失，等於回到「勾一本收一次」。

### 掀答案與評分也改走 `refresh()`

`reveal()` 與 `submit()` 現在都呼叫 `app.showReview()`（`review-view.ts:50`、`:55`）。它們影響的只有 `main` 與 `footer`，既然 `refresh()` 已經在重畫這兩塊，一併改過去。

理由是一條規則走到底：**選單開著時，畫面上任何操作都不會弄丟選單**。快捷鍵已經被下面的閘門擋住，但滑鼠沒有——評分列在底部 `footer`，不會被浮起來的選單遮住，點得到。留著 `app.showReview()` 的話會變成「勾選不弄丟選單，但點評分鈕會」。

`app.showReview()` 仍然是外面進來的入口（`app.ts:242`、其他畫面的返回鈕），也仍然負責設定 `render`（`app.ts:187`）供語音清單載入與雲端拉取後重畫用。這裡改的只是畫面內部的互動。

### `refresh()` 要更新的東西

- 「剩餘 N 張」的數字
- `main`：`isComplete(app.queue)` 為真時畫完成內容（`✓` / 今日份完成 / 說明），否則畫卡片（含編輯鈕、詞條、掀開後的釋義與朗讀鈕）
- `footer`：完成時是「瀏覽全部卡片」，否則依 `app.revealed` 畫「顯示答案」或四顆評分鈕

下拉本身不重畫——它自己管勾選狀態（`book-filter.ts:37` 的 `chosen`）。

### 快捷鍵閘門

```ts
let menuOpen = false;

app.keyHandler = (event) => {
  if (menuOpen) return;                    // 選單展開期間讓路
  if (isComplete(app.queue)) return;       // 佇列空了沒東西可按
  // …既有的空白鍵與 1–4 照舊
};
```

第一條擋掉「點開下拉、焦點停在 toggle 按鈕上、按空白想收起來、結果答案被掀開」——`isTyping()`（`app.ts:255`）只放行 `HTMLInputElement`，`<button>` 不算。收選單改用 Esc（`02` 已做）。

第二條取代舊 `doneView` 的 `app.keyHandler = null`：合併之後處理器只掛一次，完成狀態靠這條讓它不作用。

### `noBooksView` 維持獨立，不放下拉

零本時選單是空的，點開一片空白，是個死按鈕。這支繼續 `app.keyHandler = null`、繼續用原本的 `flex` 頂部列（不掛新 class）。

### 註解訂正

`review-view.ts:16`：

> 這裡沒有任何單字本開關——複習範圍在資料頁設（見票 05），答題時視線裡不放多餘的東西。

已被本票推翻，改寫成現況：標題列有一顆單字本開關，改的是複習範圍那一組；資料頁的勾選框仍然是另一個入口，兩邊改的是同一個東西。

## 這張票不做的事

- **不動資料頁那排勾選框。** 複習範圍刻意保留兩個入口。
- **不合併 `noBooksView`。**
- **不動 `bookFilter` 的內部**（Esc 與開合回報是 `02`）。
- **不動 `applyData()` 的重建規則**（是 `01`）。
- **不動評分演算法、抖動、「再次」重排。**
- **不改 `CONTEXT.md` / `docs/spec.md` / ADR**（是 `04`）。
- **不修改 `.scratch/vocabulary-books/spec.md`** 那兩行過期的字。
- **不加「切換前先確認」的彈窗。**

## 被放棄的替代方案

- **不推翻舊決定，改善資料頁的路徑**（複習頁加一顆直達單字本區的捷徑，或資料頁改完自動彈回複習頁）：動的地方少、複習畫面完全乾淨。否決的原因是切本時仍然得離開複習畫面。
- **只在「今日份完成」畫面放下拉**：複習中完全乾淨，剛好對上「這本練完了，換一本」，也完全避開佇列重建。否決的原因是練到一半想換就沒轍。
- **不合併兩支畫面，`onChange` 直接 `app.showReview()`**：程式改動最小。否決的原因是要勾三本得開三次選單，而且同一顆零件在卡片列表、統計頁不會收，只有複習頁會收。
- **勾選時不生效，關選單那一刻才一次套用**：不用重構也能連勾。否決的原因是 `bookFilter` 多一種「改了還沒生效」的狀態，三顆同樣的元件只有這顆這樣。
- **下拉放右側跟「卡片」並排**：空間最充裕，選單貼右邊往左長。否決的原因是「在練哪幾本」是狀態不是動作，跟導覽按鈕擺一起會讓人以為它也是跳頁鈕。
- **下拉放左側跟「剩餘 N 張」並排**：兩個狀態擺一起。否決的原因是選單最小 `12rem` 從 pill 右緣往左長，pill 靠左時會溢出畫面左緣，手機上尤其明顯，得另外改 CSS 讓選單改成靠左對齊。
- **把下拉包進 `.bar-title` 直接吃到現有的 grid 規則**：一行 CSS 都不用加。否決的原因是 `.bar-title` 的語意是「標題文字」，包一顆按鈕進去會讓 `.bar > *:last-child:not(.bar-title)` 那條規則的意圖變模糊。
- **三個畫面都放下拉（含零本）**：一致性最高。否決的原因是零本時它是死按鈕。

## 驗收

`npm test` 全綠、`npm run typecheck` 過。畫面行為靠實測，做法與 `.scratch/vocabulary-books/issues/06` 一致。

**版面**

- 下拉在整條頂部列**水平置中**，不因「剩餘 N 張」的位數或本名長度而偏移
- 「剩餘 12 張」在左、「卡片」貼齊右
- 其他四個畫面（卡片列表、資料、統計、編輯）的標題仍然置中，沒被 CSS 改動波及
- 本名很長時鈕上的字被截斷收在一行，不撐破頂部列
- 選單展開時浮在卡片上方，不把底下的東西推開，左右都沒有超出畫面
- 手機寬度（iPhone Safari）下三個位置不擠在一起

**切換行為**

- 連續勾兩三本，**選單全程開著**，不會勾一本收一次
- 「剩餘 N 張」跟著勾選即時更新
- 加勾一本、正在看的那張仍在範圍內 → 那張留在畫面上，**已掀開的答案還開著**
- 取消正在看的那張所屬的本 → 換成別張，答案蓋回去
- 勾到今日沒有卡到期 → 畫面就地變成「今日份完成」，**下拉還在、還開著，可以繼續勾**
- 承上，再勾回有卡的本 → 就地變回複習中
- 只剩一本被勾時，那本的勾選框點不動（`bookFilter` 既有行為）
- 鈕上的字：全勾顯示「全部」、只勾一本顯示本名、其餘顯示「N 本」
- 切換完的範圍存得住：重整頁面後仍是同一組
- 資料頁改複習範圍 → 回複習畫面 → 下拉顯示的與資料頁勾的一致（兩個入口同步）

**鍵盤（桌機）**

- 點開下拉（焦點停在 toggle）→ 按**空白鍵** → 答案**不**被掀開、選單維持開著
- 承上按 `1`–`4` → **不**送出評分
- 按 **Esc** → 選單收起
- 選單收起後按空白鍵 → 答案正常掀開
- 掀開後按 `1`–`4` → 正常送出評分
- 「今日份完成」狀態下按空白與 `1`–`4` → 什麼都不發生

**沒壞掉**

- 「編輯」鈕、朗讀鈕、「卡片」鈕照舊
- 評分後前進到下一張、佇列清空後變成「今日份完成」
- 零本時仍然是「還沒有單字本」畫面，**沒有下拉**，「去建立單字本」鈕可用
- 卡片列表與統計頁的下拉沒被波及
