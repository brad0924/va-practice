# 04 — 文件收尾：CONTEXT.md 佇列重建、docs/spec.md、ADR-0010

Status: ready-for-agent
Type: enhancement
Blocked by: 01, 02, 03

## 需求

`01`–`03` 做完之後，三件事需要落在文件上：佇列會被重建這條領域規則、`docs/spec.md` 裡兩段過期的敘述，以及替「推翻複習畫面不放開關」留一則 ADR。

## 決定

### CONTEXT.md

**只改〈複習佇列〉一條，不新增詞條。**

現在的內容：

> **複習佇列**：當日所有已到期卡片組成的待複習清單。清空後即為當日完成。

補上重建規則，大意是：複習範圍一變，佇列就照新的範圍重建；正在看的那張若仍在範圍內，會留在最前面、答案維持掀開，不在了才換下一張。

**不新增〈佇列重建〉之類的詞條**：詞彙表 20 多條全是名詞（列的是「東西」不是「動作」），多一條動作條目會破格。重建是佇列自己的性質，寫在同一條裡。

**〈複習範圍／列表範圍／統計範圍〉不動**——它只講「三個畫面各自獨立的選擇」，沒提在哪裡設。本次推翻的是 UI 位置，不是領域概念。

`CONTEXT.md` 是詞彙表不是規格書，不要把函式名、檔案路徑、UI 位置寫進去。

### docs/spec.md

1. **`:126`〈複習佇列〉**：補上重建規則，與 `CONTEXT.md` 那句對齊但可以講得細一點（這裡本來就允許寫「以隨機順序排列」這種程度的細節）。要涵蓋：觸發條件是複習範圍內的卡片集合有變動、正在看的那張仍在就留在隊首、已答過的卡因為到期日被推到未來所以不會重來、評為「再次」的卡到期日是當天所以會回到佇列裡。

2. **`:210` 手動驗收那段**：末尾「複習範圍改完回到複習畫面時佇列重建」已經不完整，改寫成涵蓋複習頁那顆下拉：連勾多本時選單不收、剩餘張數即時更新、正在看的那張留不留、勾到沒卡時就地變成完成畫面、選單展開期間快捷鍵讓路、Esc 收選單。

3. **檢查〈複習〉一節**有沒有別的句子描述複習畫面的頂部列只有「剩餘 N 張」與「卡片」。有的話一併改。

4. **`:208` 那句 jsdom 清單**：把「單字本開關收合後那行標籤」移出「不碰 DOM 的純邏輯」那一類——`02` 之後 `book-filter.test.ts` 整個檔案跑在 jsdom 上，`scopeLabel` 雖然仍是純函式，但它已經不是那句話舉例的對象了。見下方〈與 focus-target-tests/02 的碰撞〉。

### ADR-0010

三個條件的判讀：**難以回頭**這條其實偏弱（把下拉從標題列刪掉、把 `rebuildQueue` 換回 `buildQueue`，兩者都是幾行的事），使用者知情後仍然選擇開這一張——理由是這個問題來回採過兩次相反的決定，值得有一個正式的落點，以後不必翻舊 spec。

要寫進去的東西：

- **背景**：`.scratch/vocabulary-books/spec.md:223` 當初明文否決過，理由是「維持複習畫面乾淨」。
- **決定**：複習畫面的標題列放一顆單字本下拉，改的是複習範圍那一組；資料頁的勾選框保留，同一組設定刻意有兩個入口。
- **為什麼改主意**：「答題時視線裡不放多餘的東西」換來的是每次切本都要離開複習畫面；開關在標題列不在答題區中央，對視線乾淨的破壞有限。
- **連帶的第二個決定**：佇列重建時保留正在看的那張，且這條規則對所有入口一律適用（不替複習頁開特例）。
- **Considered Options**（理由見 `03` 與 `01` 的〈被放棄的替代方案〉）：不推翻只改善資料頁路徑、只在完成畫面放、勾一本收一次不重構、關選單才一次套用、下拉放左／放右、拿掉資料頁的勾選框讓每組範圍只有一個入口、切換前先跳確認。
- **Consequences**：複習畫面不再是「零開關」；複習範圍有兩個入口，兩邊必須行為一致（這是 `01` 統一 `applyData()` 的原因）；`reviewView` 與 `doneView` 合併，之後要加複習頁的畫面狀態得走 `refresh()` 而不是新增一支 view。

編號接續現有的 `docs/adr/0009-*`，格式沿用既有檔案（標題 → 前言 → `## 為什麼` → `## Considered Options` → `## Consequences`）。

### `.scratch/vocabulary-books/spec.md` 不動

第 150 行（「複習畫面：不放任何單字本開關」）與第 223 行（「被否決」）**保留原樣**。依 `docs/agents/issue-tracker.md:12`，那份 spec 是「當時這麼決定」的紀錄，與 commit 訊息互為對照；改掉就看不出曾經另有判斷。前例是 `79d7816`（`required-fields 02`）——它訂正了 `CONTEXT.md`、`docs/spec.md`、ADR-0006，沒碰任何舊的 `.scratch` spec。

也**不加**「後來被推翻，見新票」之類的迷你註記：repo 沒有這種寫法的先例，順手發明一個新慣例不划算。訂正的落點是 ADR-0010。

## 與 `.scratch/focus-target-tests/issues/02` 的碰撞

那張票還開著（`Status: needs-triage`），內容正是「`docs/spec.md:206`／`:208`／`:227` 那三條『畫面本身不撰寫自動化測試』已經被 `editor-view.test.ts` 的 jsdom 翻案，但方向與措辭還沒拍板」。它列的第一個方案是**窄例外**——留著通則，唯一例外是 `editor-view.ts`。

`02` 在 `book-filter.test.ts` 也開了 jsdom，那個「唯一」就不成立了，例外變兩個。

**本票不代它拍板。** 使用者已拍板走這條：測試照寫，規則怎麼重寫留給那張票。因此本票只做兩件事：

1. `docs/spec.md:208` 的清單訂正（見上面第 4 點）。
2. 在 `.scratch/focus-target-tests/issues/02` 的 `## Comments` 追加一筆：`review-scope-switcher/02` 又開了一個 jsdom 檔案（`book-filter.test.ts`，測 Esc 與開合回報），例外已增為兩個，該票〈一〉的「窄例外」方案要重新評估——**只補這個事實，不替它選方向、不改它的 `Status:`**。

`docs/spec.md:206` 與 `:227` 那兩句**不動**，仍然留給那張票。
