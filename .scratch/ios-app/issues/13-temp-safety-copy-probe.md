# 13 — 暫時的鷹架：讓保險副本驗得到

Status: done
Type: enhancement
Blocked by: 05

**這不是功能，是鷹架。** 它的存在只為了回答一個問題，答完就拆掉，不會留在專案裡、也永遠不會出現在網頁版或 App Store 上的版本。

## 為什麼需要它

票 05 的保險副本有兩件事沒被驗到，而且**沒有它就驗不到**：

1. **寫入**：用 app 的時候，原生儲存裡真的有一份跟著更新
2. **還原**：localStorage 空了、副本有東西時，開 app 會自己倒回來

兩件事在畫面上都看不見。要驗第 2 件就得先讓 localStorage 變空，而 iPhone 上沒有辦法「只清 localStorage、不動原生副本」——刪掉 app 是把兩邊一起帶走（票 05 的 Comments 已記錄這條驗收在沒有 Mac 的情況下驗不到）。

而這是一個**壞了也沒有任何徵兆**的功能：寫入端與還原端的錯誤都被刻意吞掉（那是票 05 驗收第六條要的），所以它靜默失效與正常運作，在畫面上長得一模一樣。沒驗過等於沒有。

## 決定

### 一顆按鈕：清掉本機資料

在「資料」畫面加一顆按鈕，按下去只做兩件事：清掉 localStorage、重新載入畫面。**完全不碰原生副本**——那正是要留著讓它證明自己的東西。

### 連雲端憑證一起清掉，否則測出來的是假的

只清卡片那一個鍵的話，雲端備份的暱稱密碼會留在原地，開 app 時 `cloud.begin()` 會把資料整份拉回來——**卡片確實會回來，但那是雲端救的，不是副本救的**，而兩者在畫面上分不出來。

因此按鈕要把 `va-practice:data` 與 `va-practice:cloud` 一起清掉。清完之後，任何出現在畫面上的卡片就**只可能**來自保險副本。代價是驗完要重新登入雲端一次，可接受。

### 只在 iOS 上出現

網頁版一個像素都不會變。這一點沒有妥協空間——「網頁版行為一字不改」是整個 iOS 工程的硬約束。

平台判斷因此會短暫地出現在畫面層，違反本 repo「不要讓條件判斷散落到畫面層」的立場。**明知故犯，因為它要被拆掉**：包成一個接縫、讓它看起來像正式功能，反而會讓人忘記拆。

### 用重新載入，不靠使用者自己關 app

按下去直接 `location.reload()`。理由是可靠：使用者「關掉 app」多半只是滑掉，WebView 常常還活著，再打開不會重跑啟動流程——那樣測到的是「什麼都沒發生」，會被誤讀成功能壞了。重新載入則保證 `main.ts` 從頭跑一次，還原那條路一定會被走到。

### 要有確認對話框

它會清掉資料。雖然是自己人在用，但一個手滑就是一次真實的損失。

## 這張票不做的事

- 不碰保險副本的任何實作（票 05 的程式碼一行不動）
- 不做任何形式的畫面顯示、狀態列、除錯資訊——只有一顆按鈕
- 不修匯出備份（那是票 12）

## 怎麼用

1. 出一個帶這顆按鈕的 build，裝到 iPhone
2. 建幾張認得出來的卡（例如「測試一」「測試二」）
3. 按「清掉本機資料」→ 確認 → 畫面變成空的 app
4. 看結果：

   | 看到什麼 | 意思 |
   | --- | --- |
   | 卡片自己回來了 | **寫入與還原兩件事一次全部證實**，票 05 的驗收可以勾完 |
   | 還是空的 | 功能真的沒在運作，回頭查（最可疑的是插件沒註冊成功） |

5. 驗完再發一次 build 把這顆按鈕拆掉

## 驗收

- [x] iPhone 的「資料」畫面出現「清掉本機資料」按鈕，按下去先跳確認
- [x] 確認後畫面重新載入
- [x] 網頁版看不到這顆按鈕，行為與本票之前一字不差
- [x] 既有測試全數通過，且一個既有測試檔都沒被修改
- [x] **驗證結果寫進本票的 `## Comments`，並回填票 05 的驗收**
- [x] **鷹架已拆除**（這一條要等驗完才勾得掉，也是本票結案的條件）

#### 「連雲端憑證一起清掉」這個決定是對的

如果只清卡片那一個鍵，`cloud.begin()` 會把資料整份拉回來，畫面上一樣會看到卡片回來——**而那是雲端救的，不是副本救的**。兩者長得一模一樣。少了這一步，這次測試會給出一個看起來成功、實際上什麼都沒證明的結果。

#### 鷹架已拆

`src/ui/data-view.ts` 已還原成票 13 之前的樣子，`git diff b9031e5 -- src/ui/data-view.ts` 為空（逐字相同），網頁版 bundle 的檔名 hash 也回到 `index-5LN7lw1a.js`，與加鷹架之前完全一致。

#### 這個做法值得記住

這類「壞了也沒有任何徵兆」的功能——錯誤被刻意吞掉、成功與失敗在畫面上無法分辨——**光靠自動測試與目視是驗不到的**。一顆用完就拆的暫時按鈕，成本是兩趟 CI，換到的是「它真的在運作」這件事的確據。下次再遇到同類的功能（例如第二版的 Widget 讀取端），同一招可以再用一次。
