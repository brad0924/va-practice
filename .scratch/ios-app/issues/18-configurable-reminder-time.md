# 18 — 提醒時間開放設定，不再固定 06:00

Status: ready-for-human
Type: enhancement
Blocked by: 09（已 done）

`spec.md` 決定二十二寫的是「第一版固定為每日 06:00，不做設定畫面。**日後若要開放設定，是獨立的一件事**」。**這張票就是那件事**——它不是推翻那個決定，是那個決定當初就預留的下一步。

## 要做什麼

讓使用者自己決定幾點被叫，預設仍是 06:00。

## 決定

### 用 `<input type="time">`，不自己做時間選擇器

iOS 上這個原生欄位會叫出系統的滾輪，長得跟使用者在其他 app 裡看到的一樣，也自動跟著系統的 12/24 小時制走。自己做一個只會比它差。網頁版同樣有得用（雖然那裡看不到這一區）。

### ~~時間與開關共用同一格 localStorage，值就是時間~~ 時間自己一格

> **訂正（2026-08-11，動工前）**：原本寫的是「時間與開關共用 `va-practice:reminder` 一格，關掉就整格移除」，理由是不想生出「關著但記得上次設 22:30」的狀態。**維護者推翻了它**：關掉開關往往只是暫時的（出門幾天、這週不想被吵），把設好的時間一起洗掉、回來得重設一次很怪。
>
> 這同時解掉票裡自打架的地方——驗收第五條要的「關掉再打開記得上次的時間」在共用一格的設計下根本做不到。

開關那一格 `va-practice:reminder` **一個字都不改**（`'on'` 或不存在）。時間另外開一格：

| `va-practice:reminder` | `va-practice:reminder-time` | 意思 |
| --- | --- | --- |
| 不存在 | （不管有沒有） | 提醒關著 |
| `'on'` | 不存在 | 開著，早上 6 點 |
| `'on'` | `'22:30'` | 開著，晚上 10 點半 |

**舊值的相容處理因此是零行**：舊裝置上開關那一格仍是 `'on'`，時間那一格不存在，讀不到就用預設的 06:00——正是升級前的行為。原訂那個「一行相容處理、日後記得刪掉」的待辦一併消失。

### 仍然只存本機，不上雲、不進匯出檔

與決定二十三一致：這是「這台裝置要幾點叫我」的偏好，不是使用者的資料。多台裝置各設各的。

### `REMINDER_HOUR` 常數消失，時間變成參數

`planReminders(cards, now)` 要多吃一個時間。「今天那一則」的閘門（`beforeReminderTime()`）也跟著讀設定值而不是常數。

`ScheduledReminder` 的 `hour` / `minute` 兩個欄位**形狀不變**——原生那一端一個字都不用改。

### 改了時間就整批重排

沿用票 09 既有的路徑：寫進 localStorage 之後叫一次 `refresh()`。不需要任何新的機制。

### 版面：時間欄位只在開關打開時出現

關著的時候那一格沒有意義，長在那裡只會讓人以為關著也會叫。開關打開 → 時間欄位出現在它下面。

> **這一條最值得推翻。** 另一種做法是開關與時間同一行、關著時把時間變灰。我選前者是因為「關著就不該看到它」比較誠實，但那會讓這一區的高度跳動一次。有意見就改。
>
> **維護者確認（2026-08-11，動工前）**：照票做，開關打開才出現。

## 這張票不做的事

- 不做多組提醒時間（一天叫兩次之類）——沒有被要求過
- 不做「週末不要叫」之類的條件
- 不動通知的標題與內文
- 不改原生插件（`DailyReminderPlugin.swift` 一個字都不必動）
- 不改開關的外觀（那是票 19）

## 一個順帶的好處：驗收不必再調系統時鐘

票 09 的手動驗收要把 iPhone 的日期時間調到 05:58 再等兩分鐘，麻煩又容易驗錯。時間可設定之後，**把提醒時間設成「現在的兩分鐘後」就能驗**——「今天那一則」的閘門本來就是拿設定時間跟當下比，這條路天然成立。

票 09 那份手動驗收清單因此可以整份簡化，**這張票要順手把它改掉**。

### 三處實作判斷

**一、時間由提醒自己遞給 `plan()`，不是讓 `app.ts` 自己去讀那一格。** `plan` 的型別從 `() => ...` 變成 `(time: string) => ...`。兩邊各讀各的雖然也會動，但那就變成兩個地方都知道那個鍵的名字，而它們有機會讀到不一樣的答案。

**二、`refresh()` 從物件字面值裡的方法提成一支區域函式。** `setTime()` 要用它，寫成 `this.refresh()` 的話一旦被拆下來單獨呼叫（`const { setTime } = reminder`）就會斷。提出來之後兩邊共用同一支。

**三、時間欄位可以被清空，那不是一個時刻。** `<input type="time">` 的值可以變成空字串。存進去的話讀出來是壞的，因此畫面那側遇到空字串就把記著的時間填回去，不呼叫 `setTime()`。純模組那側另外有一道 `readTime()` 的形狀檢查，守的是別的東西——存進去之後才壞掉的資料（手改、更早的版本），壞了就退回 06:00。

### 本機驗到哪裡

原生那一半仍然一行都沒被執行過（開發機是 Windows，沒有 Xcode），但這次**畫面那一半有實跑**：

那一趟探針驗到的：關著時時間欄位不存在 → 打開後出現、值是 06:00、同時排出 7 則 `hour=6 minute=0` → 改成 22:30 後立刻重排成 `22 30` → 關掉重排成 0 則 → 再打開，欄位仍是 22:30 且重排回 `22 30` → `localStorage` 裡兩格分開（`reminder='on'`、`reminder-time='22:30'`），卡片那一格連 `reminder` 這個字都沒有。驗完把那兩格從瀏覽器裡刪掉了。

### 2026-08-11 — code-review 後的修正

雙軸審查。Standards 軸零硬性違規，Spec 軸的十條打勾逐條核對全部成立。修掉三處，駁回兩處。

#### 1. 寫入端不擋，只在讀出來時補救（兩軸都指到）

`setTime()` 原本不驗形狀就寫進 localStorage，形狀只守在 `readTime()`。真存進壞值的話，畫面上顯示的是使用者送進來的那個、排程用的卻是退回的 06:00——**看到的與排出去的各說各話**，正是本票寫在畫面那側要避免的同一件事。

修法是在 `setTime()` 加一道形狀檢查，不成形就當沒發生。`readTime()` 那一道留著，但它守的不再是同一件事：現在守的是**別人留下的東西**（更早的版本、手改過的 localStorage）。加 1 條測試，變異驗證（拿掉那道檢查）轉紅 1 條。

實務上目前碰不到——唯一入口是 `<input type="time">`，只吐得出 `HH:MM` 或空字串。但 `setTime()` 是模組的對外介面，而票 19 正要動這一區的畫面。

#### 2. `timeRow.hidden` 散在四處各算一次

初次畫、關掉、開起來、被拒絕，四條路各自設一次，算的其實是同一件事「跟著 `check.checked` 走」。ADR-0011 對這種寫法有現成的判準：照現況重設一次比「這裡掛、那裡解」可靠。抽成一支 `syncTimeRow()`，四處改成呼叫它——漏一條就會出現「關著卻看得到時間欄位」。

#### 3. 兩句講反了的註解

- `parseTime()` 原本寫「形狀在存進去之前就守住了」，當時守的其實是讀取端。（第 1 點修完之後這句話反而成真了，但仍改成講明兩道各守什麼。）
- 模組開頭寫「每天**早上**把今天有幾張到期送到鎖定畫面」——時間可設定之後這句不再成立。

#### 駁回兩項

**一、「開關文案不該動，那是票 19」。** Spec 軸指出票明寫「不改開關的外觀（那是票 19）」，而文案從「每天早上 6:00 提醒我」改成了「每天提醒我」。**維持改動**：票 19 要換的是開關的**外觀**（勾選框改膠囊式），不是那行字；而舊文案在時間可設定之後是一句假話——`REMINDER_HOUR` 已經不存在，那個「6:00」沒有出處可以組。留著它比動它更違背本票。

**二、「劃掉 spec『不做的事』那一條算多做」。** 驗收只要求決定二十二補訂正。但「不在範圍內」還掛著「提醒時間的自訂」而它已經做掉了，兩處互相打架，留著會讓下一個讀 spec 的人得自己判斷哪一處是舊的。劃掉並指回決定二十二，是同一件事的另一半。

最終：**442 個測試全過（19 檔）**，`tsc --noEmit` 乾淨。

### 2026-08-11 — 真機回報：時間欄位把畫面撐開

維護者在 iPhone 上的 app 回報功能正常，但**時間那一格太寬，把整個畫面撐出去，畫面因此可以左右晃**。

原因是那個欄位借用了 `.field`（滿寬），而 `.field` 是給打字用的欄位設計的。滿寬的表單元件在 iOS 上會用自己的內建寬度把版面頂出容器。維護者選擇**縮成剛好裝得下時間**——一個時刻配一整條空白盒子本來就很怪。

修法是一個 `.field.time`，三條各有各的工作：

| 這一條 | 沒有它會怎樣 |
| --- | --- |
| `align-self: flex-start` | `.labelled` 是 column flex，子元素預設被拉滿寬，改 `width` 也沒用 |
| `width: auto` | 蓋掉 `.field` 的 `100%` |
| `max-width: 100%` | **唯一真的夾得住的那道** |

第三條是實測逼出來的，不是照抄的保險。原本只寫了前兩條加 `min-width: 0`，用 JavaScript 把容器壓到 60px 量出來**仍然超出 44px**——表單元件的內建寬度是硬的，`min-width: 0` 拿掉地板也不會讓它跟著容器縮。換成 `max-width: 100%` 之後同一個測法量到 60px、零溢出，正常情況仍是 104px（原本會是整列的 441px）。

驗的方式與上面那趟一樣：暫時把原生端換成假的讓那一區在網頁版長出來，用 JavaScript 量 `getBoundingClientRect()` 與 `scrollWidth > clientWidth`，驗完還原（`git diff` 確認過那個檔案零差異）。**iOS 上的實際效果仍需維護者確認**——量到的是 Chrome 的數字，而這個 bug 本來就是 iOS 才發作的。不過 `max-width: 100%` 夾的是使用寬度，不依賴內建寬度是多少，兩邊的道理相同。

### 2026-08-11 — 版面再一次：併成一句話

維護者要求把時間格移到「提醒時間」右邊、整個往上移，讀起來是一句：

> ☑ 每天提醒我，提醒時間 `06:00`

逗號照他寫的真的印出來（給過三個選項：不放逗號用空隙分、放逗號、維持兩行；他選了放逗號）。

**時間那一塊不能塞進開關那個 `<label>` 裡**——塞進去的話點時間格會順手把開關關掉。因此是兩個並排的 `<label>`：逗號留在開關那半（換行時斷在它後面才讀得順），`.reminder-line` 用 `flex-wrap` 讓時間那一塊在窄螢幕整塊換行。

量到的（同樣是暫時探針 + `getBoundingClientRect()`，驗完還原）：

| 容器寬 | 排版 | 時間格 | 溢出 |
| --- | --- | --- | --- |
| 正常 | 一行 | 104px | 0 |
| 360px | 一行 | 104px | 0 |
| 260px | 換兩行 | 104px | 0 |
| 60px | 換行且欄位縮成 36px | 36px | 0 |

60px 那一格原本會溢出 68px，補一條 `.reminder-time { min-width: 0 }` 之後歸零——沒有它，`.field.time` 的 `max-width: 100%` 沒有東西可以夾（那一塊本身縮不到比內容窄）。60px 比任何真機都窄，但一行就治好，沒有理由留著。

**順手補完上一輪沒做乾淨的**：`syncTimeRow()` 上一輪抽出來了，但四個呼叫點只改了兩個，另外兩處仍各自直接設 `hidden`。上一輪的紀錄寫「四處改成呼叫它」，當時並不成立，現在成立了。
