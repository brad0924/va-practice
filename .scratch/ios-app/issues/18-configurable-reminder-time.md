# 18 — 提醒時間開放設定，不再固定 06:00

Status: ready-for-agent
Type: enhancement
Blocked by: 09（已 done）

`spec.md` 決定二十二寫的是「第一版固定為每日 06:00，不做設定畫面。**日後若要開放設定，是獨立的一件事**」。**這張票就是那件事**——它不是推翻那個決定，是那個決定當初就預留的下一步。

## 要做什麼

讓使用者自己決定幾點被叫，預設仍是 06:00。

## 決定

### 用 `<input type="time">`，不自己做時間選擇器

iOS 上這個原生欄位會叫出系統的滾輪，長得跟使用者在其他 app 裡看到的一樣，也自動跟著系統的 12/24 小時制走。自己做一個只會比它差。網頁版同樣有得用（雖然那裡看不到這一區）。

### 時間與開關共用同一格 localStorage，值就是時間

現在 `va-practice:reminder` 存的是 `'on'`，開關關掉時整格移除。改成**存時間字串**（`'06:00'`），語意不變：

| 那一格的值 | 意思 |
| --- | --- |
| 不存在 | 提醒關著 |
| `'06:00'` | 開著，早上 6 點 |
| `'22:30'` | 開著，晚上 10 點半 |

不開第二格，因為「幾點叫」在提醒關著的時候沒有意義——分兩格就會生出「關著但記得上次設 22:30」這種要另外決定的狀態。

**舊值 `'on'` 讀成 06:00**。這是一行的相容處理，維護者的裝置上存的正是那個值，不處理就會在升級後靜靜地不再被叫。等那台裝置重存過一次就可以刪掉，但**不要在同一張票裡刪**。

### 仍然只存本機，不上雲、不進匯出檔

與決定二十三一致：這是「這台裝置要幾點叫我」的偏好，不是使用者的資料。多台裝置各設各的。

### `REMINDER_HOUR` 常數消失，時間變成參數

`planReminders(cards, now)` 要多吃一個時間。「今天那一則」的閘門（`beforeReminderTime()`）也跟著讀設定值而不是常數。

`ScheduledReminder` 的 `hour` / `minute` 兩個欄位**形狀不變**——原生那一端一個字都不用改。

### 改了時間就整批重排

沿用票 09 既有的路徑：寫進 localStorage 之後叫一次 `refresh()`。不需要任何新的機制。

### 版面：時間欄位只在開關打開時出現

關著的時候那一格沒有意義，長在那裡只會讓人以為關著也會叫。開關打開 → 時間欄位出現在它下面。

> **這一條最值得推翻。** 另一種做法是開關與時間同一行、關著時把時間變灰。我選前者是因為「關著就不該看到它」比較誠實，但那會讓這一區的高度跳動一次。有意見就改。

## 這張票不做的事

- 不做多組提醒時間（一天叫兩次之類）——沒有被要求過
- 不做「週末不要叫」之類的條件
- 不動通知的標題與內文
- 不改原生插件（`DailyReminderPlugin.swift` 一個字都不必動）
- 不改開關的外觀（那是票 19）

## 一個順帶的好處：驗收不必再調系統時鐘

票 09 的手動驗收要把 iPhone 的日期時間調到 05:58 再等兩分鐘，麻煩又容易驗錯。時間可設定之後，**把提醒時間設成「現在的兩分鐘後」就能驗**——「今天那一則」的閘門本來就是拿設定時間跟當下比，這條路天然成立。

票 09 那份手動驗收清單因此可以整份簡化，**這張票要順手把它改掉**。

## 驗收

- [ ] 「資料」畫面上，開關打開後出現時間欄位
- [ ] 預設是 06:00
- [ ] 改成別的時間之後，提醒真的在那個時間響
- [ ] 改時間之後，已登記的提醒立刻依新時間重排（不必重開 app）
- [ ] 關掉開關再打開，記得的是上次設的時間，不會跳回 06:00
- [ ] 把時間設成「現在的兩分鐘後」，兩分鐘後真的響（不必調系統時鐘）
- [ ] 把時間設成「現在之前」，今天那一則不排，隔天照設定的時間響
- [ ] 舊值 `'on'` 的裝置升級後照常在 06:00 被叫，不會靜靜地失效
- [ ] 提醒時間不出現在匯出的備份檔裡，也不會被雲端備份覆蓋
- [ ] 網頁版行為零變化，「資料」畫面上不出現這一區
- [ ] `spec.md` 決定二十二補上訂正，指向本票
- [ ] 票 09 的手動驗收清單改成用「設成兩分鐘後」的驗法
- [ ] 既有測試全數通過
