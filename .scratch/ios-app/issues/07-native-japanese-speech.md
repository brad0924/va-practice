# 07 — 原生日文語音：朗讀按鈕在 iOS 上永遠可用

Status: ready-for-agent
Type: enhancement
Blocked by: 01

決策背景見 `../spec.md`，本票對應決定十四、十五、十六。

## 現況

`src/ui/speech.ts` 走 Web Speech API，找不到日文語音時 `hasJapaneseVoice()` 回 `false`，`src/ui/review-view.ts` 據此把朗讀按鈕整個藏起來。這個設計在網頁上是對的——與其讓使用者聽到外語腔調念日文，不如不要出現這個按鈕。

但在 WKWebView 裡，日文語音的存在與否不可靠。結果是使用者不會看到任何錯誤，只會覺得「這個按鈕有時候在、有時候不在」。

（01 的災情回報會確認這件事實際發生的程度；不論結果如何，這張票的做法不變。）

## 決定

### 不開新接縫，在 `speech.ts` 內部分支

該模組對外只有 `initSpeech` / `hasJapaneseVoice` / `speak` 三支，`review-view.ts` 的呼叫方式**一字不改**。模組內部先探測原生語音橋接是否存在：有就用原生（`AVSpeechSynthesizer`），沒有就沿用現有的 Web Speech 路徑。

### iOS 上朗讀按鈕永遠可用

原生語音的日文是系統內建、離線可用，因此 `hasJapaneseVoice()` 在 iOS 上恆為真，按鈕不再時有時無。**網頁版維持原本「沒有日文語音就藏起來」的行為。**

### 朗讀的文字來源不變

仍是 `toReadingText()` 轉出的讀音文字——聽到的與卡片教的讀法一致。這是既有決定，原生實作照搬，不要改成念詞條原文。

### 語速沿用現有設定

現行 Web Speech 路徑用的是 0.9 倍速。原生實作取一個聽感相當的值，不要因為換了引擎就順手調整。

## 這張票不做的事

- 不改 `src/ui/review-view.ts`
- 不改變朗讀的觸發方式——仍然一律由使用者主動點擊，不自動發聲
- 不加語速或語音的設定選項
- 不為 `speech.ts` 補自動測試：它持有全域語音狀態，現在也沒有測試，本票刻意維持對外介面不變正是為了讓這一側零變動

## 驗收

- [ ] iOS 上朗讀按鈕永遠顯示，不會時有時無
- [ ] 點朗讀能聽到日文發音，且念的是振假名標注的讀音而非漢字原文
- [ ] 飛航模式下朗讀照常可用
- [ ] 連續快速點朗讀時，前一次會被中斷，不會疊在一起念
- [ ] 純假名與外來語詞條也能正確朗讀
- [ ] `src/ui/review-view.ts` 一行未改
- [ ] 網頁版行為零變化：沒有日文語音的瀏覽器上，按鈕仍然隱藏
- [ ] 既有測試全數通過，且一個既有測試檔都沒被修改
