# 16 — 連點兩下會把畫面放大

Status: needs-triage
Type: bug
Blocked by: 01

真機回報（票 07 驗收「連續快速點朗讀」時發現）：**連按兩次朗讀按鈕，畫面會被放大。**

朗讀本身是好的——前一次確實被中斷、沒有疊在一起念。放大是撞上的另一件事，與朗讀無關：任何地方連點兩下都會發生。

## 為什麼會這樣

Capacitor 預設就有「禁止縮放」（`zoomEnabled` 預設 `false`），但**它擋不到連點兩下**。

查證過原始碼：`CAPBridgeViewController.swift:322` 在 `zoomEnabled` 為 false 時把 scrollView 的 delegate 指給 `WebViewDelegationHandler`，而那支 delegate 做的事只有一件——`scrollViewWillBeginZooming` 裡把**雙指手勢**關掉（`WebViewDelegationHandler.swift:338-339`）。

連點兩下放大是 WebKit 自己內建的另一套手勢，走的不是同一條路，因此完全不受影響。結論：**這支 app 的雙指放大是關的，連點兩下卻是開的。**

## 已定案

### 範圍是整頁，不是只有按鈕

卡片、列表、任何地方連點兩下都不該放大。只擋按鈕的話會出現「為什麼這裡不會、那裡會」這種沒人解釋得清的差別。

## 待決定（這張票卡在這裡）

**要不要動到網頁版？** 三個選項，代價不同：

| 修法 | 效果 | 代價 |
| --- | --- | --- |
| 共用樣式表加 `touch-action: manipulation` | 連點兩下不再放大，**雙指放大仍然可用** | 手機 Safari 開網頁版也會跟著變——那邊是同一個毛病，等於順手一起修掉，但動到了 spec 開頭「網頁版行為一字不改」那條硬約束 |
| 同一行但只在 iOS 生效 | 網頁版一個像素不動 | 要把平台判斷寫進畫面層或樣式表，違反本 repo 一貫的立場；且網頁版的同一個毛病繼續留著 |
| viewport 關掉整個縮放 | 最省事 | **連雙指放大也沒了**。這是一個背漢字的 app，想放大看筆畫是合理需求，因此不建議 |

第一個選項的「動到網頁版」實際上是**把網頁版的同一個 bug 一起修掉**，不是造成回歸。若選它，應該正式修訂 spec 那條硬約束（改前提，不是為它加一個例外），並在 ADR-0012 或 spec 留下紀錄。

## 這張票不做的事

- 不關掉雙指放大——那是使用者主動做出的縮放，與手滑連點是兩回事
- 不改朗讀的任何行為（票 07 已驗收通過）
- 不動 Capacitor 的 `zoomEnabled` 設定：它預設就是關的，改它沒有用，這一點已由原始碼查證

## 驗收

- [ ] iPhone 上連點兩下（按鈕、卡片、列表任一處）畫面不再放大
- [ ] 雙指撐開放大仍然可用
- [ ] 連按兩次朗讀的中斷行為不變
- [ ] 依「待決定」的結果，網頁版該變的變、該不變的一字不變
- [ ] 既有測試全數通過，且一個既有測試檔都沒被修改
