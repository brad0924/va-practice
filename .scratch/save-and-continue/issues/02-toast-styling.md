# 新增卡片頁的 toast 樣式重做

Status: done
Type: enhancement

## 需求

01 號票（`01-save-and-continue.md`）把「儲存並繼續」的 toast 行為（決定 6、7、8）定案了，但樣式從沒被討論過——票上決定 6、7、8 只講了何時跳、跳多久、寫什麼字，一句都沒講長相。使用者驗收後回饋：「不夠明顯，太小、顏色也不清楚，看能不能改成從上面跳出來」。

## 決定

用 `/prototype` 的 UI 分支（sub-shape A，掛在既有的新增卡片頁）做了五個版面（A~E）× 四個顏色（綠／藍／黃／中性）的組合，透過 `?variant=` `?tone=` 切換，讓使用者在真實表單、真實按鈕旁邊實際比較。

1. **位置從底部改到頂部。** 原本固定在畫面最下方、跟儲存按鈕擠在一起，使用者要求改成從上面跳出來。
2. **最終選定 E＋綠色**：貼頂提示條、淡綠底（`color-mix(in srgb, var(--good) 18%, var(--surface))`）＋左側 4px 綠色色條、寬度 95%（左右各留一點邊界，不做滿版），四角圓角，帶 ✓ 圖示。比較過程中先做了 A（滿版實色橫幅）、B（浮動卡片＋圓形徽章）、C（貼頂提示條，滿版）、D（A 的不滿版版本），使用者確認 C 系的「貼頂淡底＋色條」份量最合適，但滿版（C）不如收邊 95%（E）舒服，因此定案 E。
3. **顏色維持現狀的綠色。** 藍／黃／中性都做出來比較過，使用者最終選回綠色（成功色，語意上最合理），只是不再是原本太淡看不清楚的灰底。
4. **本體仍不吃點擊（`pointer-events: none`），只有 ✕ 例外。** 沿用原本的理由：貼頂之後可能蓋到詞條欄位，使用者要能直接點到底下的輸入框；只有原本蓋住底部按鈕的疑慮已經因為挪到頂部而不存在。
5. **3 秒自動消失＋✕ 提前關掉的行為完全不動**——這次只重做樣式，01 號票決定 6、7、8 的行為原封不動。

## 驗收

畫面層不寫自動化測試（`docs/spec.md`），驗收靠瀏覽器實測：

- 從卡片頁按「新增」，填好詞條與釋義按「儲存並繼續」：畫面上方（貼著頂部列下方）跳出淡綠底、左側綠色色條、帶 ✓ 圖示的提示，寬度不到滿版、四角圓角，不是原本灰底的小藥丸。
- 提示約 3 秒後自動消失；按 ✕ 可以提前關掉。
- 提示顯示期間，詞條輸入框仍然點得到、打得到字（本體不吃點擊）。
- 連續存兩張：同一則被新內容取代，不會疊成兩則。
- 編輯既有卡不會跳出這則提示（沿用 01 號票決定 6）。
