# 卡片頁到期改用六個時間桶顯示

Status: done
Type: enhancement

## 需求

卡片頁（`src/ui/list-view.ts`）目前每張卡右側顯示「新卡／逾期 N 天／今日到期／`YYYY-MM-DD` 到期」四種文字。使用者想改成六個白話時間桶：**新、現在、<24小時、明天、<1週、未來**。

排程模型維持只到日（`due` 仍是 `YYYY-MM-DD`，不含時刻）；本 issue 只動卡片頁的顯示層與樣式，加上一則文件修正。

## 決定

1. **六個標籤與現有天數狀態一對一。** 在只到日的模型下，卡片本來就只有這幾種狀態，依緊急度排成不重疊的階梯，數學上只有唯一一種對應。依現有 `overdueDays(card, now)` 算出的天數（正數為逾期、0 為今日、負數為未到期，`null` 為新卡）：

   | 狀態（days） | 標籤 | 顏色 |
   | --- | --- | --- |
   | 逾期（≥ 1） | 現在 | 紅 `--danger` |
   | 今日到期（0） | <24小時 | 橘 `--hard` |
   | 明天（−1） | 明天 | 黃 `--soon`（新增，`#d9c14f`） |
   | 後天～第 6 天（−2 ～ −6） | <1週 | 藍 `--easy` |
   | 滿 7 天以上（≤ −7） | 未來 | 綠 `--good` |
   | 新卡（`due` 為 `null`） | 新 | 紫 `--new`（新增，`#9a7fe0`） |

2. **「<1週」是嚴格不到 7 天。** 第 7 天（剛好滿一週）歸「未來」，故「<1週」涵蓋後天到第 6 天（days −2 ～ −6）。

3. **逾期不再顯示「拖了 N 天」。** 逾期卡改標「現在」，天數細節捨去——已知且接受的取捨。這也是為什麼「今日到期」標成「<24小時」讀起來像還沒到期：只到日的模型分不出今天卡在當日的哪個時刻，六標籤一對一是接受這點換來的。

4. **只換顯示，排程一律不動。** `sortByDue()`、`buildQueue()`、間隔、抖動、`due` 的資料型別全部不碰；標籤只是同一份到期資料的另一種呈現。同一桶內多張卡的相對順序仍由 `sortByDue()` 依實際到期日決定。

5. **顏色以 `row-state` 的 class 切換沿用現有機制。** `stateModifier()` 改為回傳六種其中之一的 class 尾綴，`styles.css` 為六色各補一條 `.row-state.xxx { color: ... }`；`--soon`、`--new` 兩個新色變數加在 `:root`。

6. **不寫 ADR。** 純顯示層、改回去成本極低，不符合 ADR「難以逆轉」的門檻。

## 驗收

- `npm test` 全綠。
- 逾期卡顯示「現在」（紅），不再出現「逾期 N 天」。
- 今日到期顯示「<24小時」（橘）。
- 明天到期顯示「明天」（黃）；後天到第 6 天顯示「<1週」（藍）；第 7 天起顯示「未來」（綠）。
- 新卡顯示「新」（紫）。
- 到期排序、複習佇列的出題順序完全沒變。

## Comments

- `CONTEXT.md` 的「逾期（Overdue）」詞條要一起修：拿掉「逾期卡另外顯示拖了幾天」，改成反映逾期現在標「現在」、與今日到期仍在列表上以不同標籤區分。只修這一條，不新增其他詞。
- `now()` 其實帶完整時刻，但依只到日的決定不使用；「<24小時」是今日到期這一桶的白話別名，並非真的用小時運算。實作時可留一行註解說明，免得日後有人以為漏算了小時。
