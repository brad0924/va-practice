# 資料畫面新增 Gemini API 金鑰設定

Status: done
Type: enhancement

`02-reading-prefill.md` 的前置條件。本票只做金鑰的存放與設定介面，不做任何呼叫。

## 需求

讀音預填需要一把使用者自備的 Gemini API（Application Programming Interface，應用程式介面）金鑰。金鑰要能在資料畫面設定、存在本機、重整後仍在，而且**絕對不能流出這台裝置**。

## 現況

資料畫面（`src/ui/data-view.ts`）已經是這個 app 唯一的設定區：雲端備份的暱稱密碼、匯出、匯入都在那裡。

本機儲存目前有兩格互不相干的抽屜：

- `va-practice:data`（`src/lib/storage.ts:12`）——整份 `AppData`，會被推上雲端、也是匯出檔的內容。
- `va-practice:cloud`（`src/lib/cloud-backup.ts:16`）——雲端備份的暱稱與密碼，**不在 `AppData` 裡**，因此既不上雲也不進匯出檔。

`exportJson()` 就是 `JSON.stringify(load())`（`src/lib/storage.ts:95`），直接序列化整份 `AppData`。

## 決定

1. **金鑰存第三格抽屜，不進 `AppData`。** 新增一個獨立的 localStorage 鍵（建議 `va-practice:gemini`），比照 `va-practice:cloud` 的做法。

   這是本功能最關鍵的一條，理由是金鑰進 `AppData` 會同時打開**三個出口**：Firebase（有加密）、localStorage（明文）、**匯出檔（明文）**。加密只堵得住第一個——按下「匯出備份」拿到的 `.json` 會躺著一把明文金鑰在下載資料夾裡。

   另一個理由是 ADR-0003 寫過：「若日後要放入任何敏感資料，這個前提必須重新評估」。金鑰不進 `AppData`，這句話就沒有被觸發，ADR-0003 的前提維持不變。

2. **代價已知並接受：金鑰不跨裝置同步，每台各設定一次。** 這是決定 1 的必然結果，不在介面上補救。

3. **讀寫沿用 `StorageLike` 抽象**（`src/lib/storage.ts:16`），與 `cloud-backup.ts` 一致，不直接碰全域 `localStorage`。

4. **對外只導出兩件事**：讀取目前金鑰（未設定回 `null`）、寫入或清除金鑰。`02` 只會用到讀取那支。

5. **介面放在資料畫面既有的雲端備份區塊之後**，沿用該區塊的版面與樣式，不新增畫面、不改導覽。

6. **輸入框用 `type="password"`，且永不回顯已存的金鑰原文。** 已設定時只顯示「已設定」這類狀態文字加一顆清除鍵；要換金鑰就重貼一次。

7. **附一行說明文字**：金鑰從 Google AI Studio 取得，並提醒**該專案不要啟用計費**——一旦啟用，免費層會整個消失，之後每個呼叫從第一個 token 起計費。這行字是這個設計唯一的保險：不綁卡的金鑰即使外洩，代價也只是免費額度被別人用掉，不會產生帳單。

8. **不做金鑰有效性檢查。** 不在儲存時打一次 API 試通。理由是那要多花一次額度、多一組狀態、而且金鑰失效的情境由 `02` 的錯誤提示接住就夠了。

## 驗收

- 在資料畫面貼上一把金鑰並儲存，重整頁面後狀態仍顯示「已設定」。
- 輸入框在任何時候都不顯示已存金鑰的明文。
- 按清除後狀態回到「未設定」，且 localStorage 中該鍵已移除。
- **貼上金鑰後按「匯出備份」，在下載的 `.json` 全文搜尋金鑰字串，找不到。**
- **貼上金鑰後登入雲端備份並推送，把雲端那份解密後檢查，不含金鑰。**
- `AppData` 的欄位沒有增加，資料版本號沒有升，`storage.ts` 的匯入驗證邏輯未被改動。
- 未設定金鑰時，資料畫面與其他所有畫面的行為與現在完全一致。
- 既有測試全綠。
