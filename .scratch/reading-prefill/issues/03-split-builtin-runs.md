# 內建牌組的 36 個多漢字串改成逐字分配

Status: ready-for-agent
Type: enhancement

與 `02-reading-prefill.md` 同批，但兩者互不阻擋。純資料改動，不動任何程式碼。

## 需求

`02` 讓新卡的多漢字串一律逐字分配（`吹[ふ]雪[ぶき]`），但內建牌組現有的多漢字串全部是整串一格（`吹雪[ふぶき]`）。新舊兩種呈現混在同一份牌組裡，把內建牌組跟上。

## 現況

`src/data/cards.json` 共 132 張卡、121 個漢字串：85 個單一漢字（沒有分配問題），34 個兩字，2 個三字。**這 36 個多字串全部是整串一格，一個都沒有拆過。**

完整清單：

```
仮名[がな]      作物[さくもつ]    架空[かくう]      生地[きじ]
帰省[きせい]    心構[こころがま]  度々[たびたび]    粗筋[あらすじ]
芝生[しばふ]    一丸[いちがん]    植木[うえき]      気付[きづ]
吹雪[ふぶき]    目安[めやす]      剃刀[かみそり]    農薬[のうやく]
就職難[しゅうしょくなん]          必着[ひっちゃく]  句読点[くとうてん]
真夏[まなつ]    欠如[けつじょ]    願書[がんしょ]    円高[えんだか]
寄付[きふ]      書留[かきとめ]    真剣[しんけん]    下駄[げた]
英和[えいわ]    電卓[でんたく]    居眠[いねむ]      昨今[さっこん]
見方[みかた]    非難[ひなん]      威張[いば]        稼働[かどう]
勘定[かんじょう]
```

## 決定

1. **能拆的逐字拆，拆不開的維持整串一格。** 掃過這 36 個，絕大多數拆得開（`農薬` → `農[のう]薬[やく]`、`心構` → `心[こころ]構[がま]`、`居眠` → `居[い]眠[ねむ]`）。真正拆不開的熟字訓只有極少數，`剃刀[かみそり]` 是明確的一個。判斷不確定就**保持整串一格**——那是保守且正確的答案。

2. **連濁與促音便照實分配**：`円高` → `円[えん]高[だか]`、`昨今` → `昨[さっ]今[こん]`。分配的是「這一段假名對應這個漢字」，不是還原漢字的字典讀音。

3. **只改 `text` 欄位。** `id`、`meaning`、`interval`、`ease`、`due` 一律不動。識別碼尤其不能動，否則單向合併會把卡片當成新的重複補進去。

4. **同一批改動要套用到兩個地方**：

   - `src/data/cards.json`——給未來的新裝置。
   - **使用者提供的匯出備份 JSON**——給使用者現在正在用的裝置，改完由使用者自行匯入。

   兩份都要改，而且 36 筆的分配結果必須一致。

5. **不寫一次性遷移程式碼。** 單向合併的定義是「已存在的一律不動」，所以改了 `cards.json`，使用者裝置上那 132 張不會跟著變。改用「使用者匯出 → 直接改那份 → 匯入回去」處理，省下一支只跑一次就該刪掉的遷移程式與它的對照表。

6. **這 36 筆需要人工逐一校對**，不能全交給程式或 AI 產完就算。這是一次性成本，付一次就結束。

## 驗收

自動可驗的部分——這兩條是本票的安全網，**必須全數通過**：

- **改動前後，132 張卡的 `toPlainText(text)` 完全相同。** 保證沒有任何漢字或假名被增刪改。
- **改動前後，132 張卡的 `toReadingText(text)` 完全相同。** 保證整串讀音一字未變，語音朗讀聽起來完全一樣。

換句話說，這次改的**只有振假名標在哪個字上方**，卡片的實質內容零變動。

其餘：

- `src/data/cards.test.ts` 全綠（仍是 132 張、識別碼不重複、讀音標記全部解析得掉）。
- 36 筆改動逐一列在 commit 訊息或本票的 `## Comments` 裡，形式為「舊 → 新」，方便日後回查。
- 拆不開而維持整串一格的那幾筆，各註明理由（熟字訓）。
- 使用者匯入改過的備份後，複習進度（間隔、成長倍數、到期日）完全不變。
- 既有測試全綠。
