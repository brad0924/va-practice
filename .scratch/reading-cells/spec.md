# 新增單字時不再手打方括號，改為自動長出讀音格

拆成三張實作票，見 `issues/01-reading-cells-model.md`、`issues/02-editor-reading-cells.md`、`issues/03-docs-and-adr.md`。本檔案是三張票共用的決策紀錄，不直接實作。

## 問題

新增卡片時，讀音以半形方括號寫在詞條裡（`焦[こ]がす`），整串在同一個文字框輸入（`src/ui/editor-view.ts`）。

問題出在輸入法：日文輸入模式下 `[` 鍵打出來的是全形「，要拿到半形 `[` 必須切回英數，打完再切回日文繼續打假名。一張卡有幾個漢字就要來回切幾次。使用者的兩台裝置（Windows + 微軟日文 IME、iPhone 日文鍵盤）都有這個問題。

`docs/spec.md` 已把「讀音標記的輸入體驗」列為核心流程，與複習同等對待。

## 現況調查

以下數字來自 `src/data/cards.json`（132 張內建卡），是本次所有決定的依據。

**卡片的段落樣式**（漢＝要標音的漢字串，仮＝純文字）：

| 樣式 | 張數 | 例 |
|---|---|---|
| 漢仮 | 53 | `焦[こ]がす` |
| 漢 | 46 | `帰省[きせい]` |
| 仮 | 21 | `くしゃみ` |
| 漢仮漢仮 | 5 | `考[かんが]え込[こ]む` |
| 漢仮漢 | 5 | `送[おく]り仮名[がな]` |
| 仮漢仮 | 2 | `ざるを得[え]ない`、`ひび割[わ]れる` |

**漢字串長度**：全部 121 串，其中 85 串是單一漢字，34 串兩字，2 串三字。

**讀音字元**：121 個讀音全部是平假名，共 60 種字元，沒有片假名也沒有雜訊。

**關鍵驗證**：把每張卡的讀音標記去掉後，用「連續漢字＝一串」重新抓一次，抓出來的漢字串與原本被標音的對象**132 張完全一致**，零例外。原因是 `parseReading()` 本來就是「往回吃掉緊鄰括號的**極大**漢字序列」（`src/lib/reading.ts:42`）——「自動偵測漢字串」與現有標記語意是同一件事，不是新規則。

## 決定

### 輸入方式

1. **詞條框只打純文字，不再打括號。** 程式偵測詞條裡的連續漢字，每一串在下方長出讀音格讓使用者填假名。沒有漢字的詞（21 張）不長出任何格。

2. **兩字以上的漢字串，預設逐字一格。** `書留` 預設就是 `書[ ] 留[ ]` 兩格，直接填 `かき`、`とめ` 即可，不需任何額外操作。這是「不引入字典」的直接後果：程式數得出有幾個漢字，但猜不出讀音怎麼分配。

3. **不引入漢字讀音字典。** 評估後拒絕，四個理由：打包產物會從 33 KB 漲到 ~330 KB（10 倍）；連濁（`円高`→`えん`+`だか`）與促音便（`昨今`→`さっ`+`こん`）字典查不到，要另外寫規則；熟字訓（`剃刀[かみそり]`、`吹雪[ふぶき]`）字典本來就拆不開；最嚴重的是猜錯時不會報錯，會安靜產生錯卡。詳見 `docs/adr/0004-no-kanji-reading-dictionary.md`。

4. **合併鍵放在兩格中間的「縫」，可連點多次。** 一串 n 個漢字有 n−1 道縫，每道縫非黏即分，預設全分。點一道縫把左右兩格黏起來，再點一次拆回去。

   之所以不是一顆「整串合併」鍵：`今日中`（きょうじゅう）要能切成 `今日[きょう]` + `中[じゅう]`——`今日` 是熟字訓拆不開、`中` 是獨立的 `じゅう`。整串合併只能選「全黏」或「全分」，兩邊都不對。這種「熟字訓 + 一般漢字混在同一串」在日文裡很常見（`大人買い`、`一昨年`），不是為邊緣情況設計。

5. **合併時把兩格的讀音接起來，切開時把讀音清空。** 合併後那格的讀音，在定義上就是各段讀音接起來（`剃[かみ]` + `刀[そり]` → `剃刀[かみそり]`），沒有接起來會錯的情況，因此不該丟掉使用者已打的字。反過來切開時，程式無法把 `かみそり` 分配回 `剃` 與 `刀`，只能清空——這與決定 8（舊卡不重拆）是同一個限制。

### 資料與相容

6. **儲存格式完全不動，仍存 `焦[こ]がす` 字串。** 內建牌組（`src/data/cards.json`）、雲端備份、匯出檔、單向合併四處都吃這個格式。新介面只是「讀音格 ↔ 標記字串」的翻譯層，`Card.text`、`AppData`、`storage.ts`、`cloud-*.ts` 一律不動，資料版本號不升。

7. **貼上舊標記字串時自動攤回格子，不留「直接改字串」的入口。** 貼上 `焦[こ]がす` 到詞條框，括號消失、詞條變成 `焦がす`、讀音自動落到 `焦` 那格。

   不另開折疊的「直接編輯標記」區：新介面加上切開／合併已經表達得出所有合法標記，再開一個入口就是兩套要雙向同步，多一類 bug 來源。而且「攤回格子」這段程式為了編輯 132 張舊卡本來就非寫不可，套用在貼上只是同一條路。貼上本身就是逃生門。

8. **舊卡打開時照已存的標記還原，不重新逐字拆。** `帰省[きせい]` 只存了一個讀音，硬拆成 `帰[ ] 省[ ]` 程式不知道 `きせい` 該怎麼分配，只能清空——那等於每次編輯舊卡都要重打。「逐字一格」是新打漢字時的預設，不動既有卡。

9. **不做批次轉換。** `書留[かきとめ]` 維持原樣。使用者想改成 `書[かき]留[とめ]`，就是開那張卡點一下那道縫的事。經確認接受。

### 保護

10. **改詞條時，已填讀音按漢字內容對得上就保留。** 依序比對每格的漢字，文字沒變就把讀音搬過來，只有真的新出現的漢字才是空格。改錯字、改詞尾（`考え込む` → `考え込んだ`）不會弄丟已填的讀音。不用「按位置保留」——在詞條前面插入新漢字會讓整排錯位。

11. **同一串漢字裡，讀音要嘛全填、要嘛全空，違反就在儲存時擋下。** 這是儲存格式逼出來的，不是潔癖。`parseReading()` 貪心往回吃漢字，留空的格會被後面已填的格吸走：

    ```
    今[こん]日[にち]中[ちゅう]   → 今(こん) + 日(にち) + 中(ちゅう)   ✓
    今[こん]日中                → 今(こん) + 日中                    ✓
    今日[にち]中[ちゅう]         → 今日(にち) + 中(ちゅう)            ✗ 今被吸走
    今[こん]日中[ちゅう]         → 今(こん) + 日中(ちゅう)            ✗ 日被吸走
    ```

    儲存格式已定不動（決定 6），只能在輸入端擋。規則寫成「全填或全空」而非「留空只能在尾端」——後者雖然多一點彈性，但規則變成兩句話、難記，且 132 張現有卡沒有一張用得到。

12. **讀音欄擋下非假名，儲存時檢查。** 平假名、片假名、長音符 `ー` 放行，羅馬字、漢字、數字擋下並指出是哪一格。這正好接住本次要解決的原始痛點——忘了切輸入法會打成 `kanga`，卡片正面看起來正常，翻面才發現，而且會一路存進雲端備份。片假名放行是因為有人習慣用片假名寫音讀，現有 132 張雖然全是平假名，但沒有理由禁止。

## 驗收

三張票各有自己的驗收條件。整體要成立的是：

- 新增一張含漢字的卡，全程不需切換輸入法，也不需輸入任何括號。
- 132 張內建卡逐一打開編輯畫面再原樣儲存，`Card.text` 一字不差。
- 既有測試全綠，`src/lib/reading.ts` 的既有行為完全不變。

## Comments

- 本檔案由 `/grill-with-docs` 訪談產出，決定皆經逐題確認。
- 訪談中先後提出並被否決的方案：擴充語法接受全形「」（治標，且資料裡會同時存在兩種寫法）、加一顆「插入 []」按鈕（手要離開鍵盤，且沒解決語法本身的心智負擔）、固定拆成「漢字／讀音」兩欄（`書[か]き下[お]ろす` 這種多段漢字塞不進去）。
- 「每個漢字強制各一格、不能合併」也被否決：46 張純漢字卡裡有 `芝生[しばふ]`、`剃刀[かみそり]`、`下駄[げた]`、`吹雪[ふぶき]`、`生地[きじ]` 等熟字訓，讀音與單字對不起來，硬拆會逼使用者填出錯的東西。
- 「兩串標音緊鄰」（`書[かき]留[とめ]` 這種漢字直接黏著、各標各的）在現有 132 張裡一張都沒有，但使用者明確表示日後要能這樣標，因此決定 4 的切開／合併是必需品而非加分項。
