# 拆開改為每道縫獨立，不再整格拆光

Status: done
Type: bug

決策背景見 `.scratch/reading-cells/spec.md`（決定 4）。關聯 `01-reading-cells-model.md`（模型層）與 `02-editor-reading-cells.md`（畫面）。

## 問題

`spec.md` 決定 4 說「一串 n 個漢字有 n−1 道縫，**每道縫非黏即分**……再點一次拆回去」——每道縫應各自獨立。

但 issue 01 的 `splitCell(run, index)` 是「把**整格**拆回逐字」，不是「只拆點下的那道縫」。兩字格（`書留`、`剃刀`）只有一道縫，「拆整格」剛好等於「拆那道縫」，看不出差別；三字以上才露餡：

- `就職難` 合成一格時，格內有兩道 `·`（就｜職、職｜難）。
- 目前**兩道 `·` 點下去做同一件事**——把整格 `就職難` 一次炸成 `就 / 職 / 難` 三格。
- 使用者點第一道縫，期待的是 `就` + `職難`（職難仍合著），實際卻全拆成三個。

功能上還是能到 `就` + `職難`（先全拆再把職難合回去，兩步），但不直覺，且合併狀態下多道 `·` 同動作會誤導。

## 決定

1. **拆開改為每道縫獨立。** 點某格內第 k 道縫（該格 kanji 的第 k−1 與第 k 字之間）→ 只把該格從那個邊界切成左右兩格，其餘不動。讀音兩格皆清空（無法把合併讀音分配回去，沿用 issue 01 決定 8 的限制）。

   ```
   就職難[しゅうしょくなん]   一格，兩道縫 · ·
   點第一道 · → 就[] 職難[]           職難 仍一格
   再點 職難 的縫 → 就[] 職[] 難[]
   ```

2. **模型層加一個「按邊界切」的函式**，例如 `splitCellAt(run, cellIndex, at)`：把第 `cellIndex` 格的 kanji 從第 `at` 字（`at` 為 1 ~ kanji.length−1）切成 `kanji.slice(0, at)` 與 `kanji.slice(at)` 兩格，讀音皆空。

   - 既有 `splitCell`（整格拆逐字）在兩字格等同 `splitCellAt(..., 1)`。改完後畫面只用新函式；若 `splitCell` 就此無人使用，連同它 issue 01 的測試一併移除，不留死 code。
   - `mergeSeam` 不動。

3. **畫面的 `·` 縫要傳「哪一道縫」**（目前 `02` 的 `renderCell` 兩道 `·` 都呼叫 `splitCell(r, ci)`，同動作）。改成第 k 個字前的縫呼叫 `splitCellAt(r, ci, k)`。

4. **`·` 縫的 `aria-label` 依邊界給名字**，比照 `02` 決定 4 的無障礙慣例，且要能區分同格內不同縫：`把${左半}和${右半}拆開`。例 `就職難`：第一道 → 「把就和職難拆開」，第二道 →「把就職和難拆開」。

5. **儲存格式、`toMarkup`、往返一律不動。** 拆開只影響畫面上的分格，不影響組出的標記字串。132 張往返測試維持全綠。

## 驗收

- `就職難` 一格 → 點 就｜職 的縫 → `就` + `職難` 兩格（職難仍一格），兩格讀音皆空。
- 承上，`職難` 那格再點縫 → `職` + `難`。
- 兩字格行為不變：`書留`、`剃刀` 點縫 → 兩格皆空（與 issue 01/02 現行一致）。
- 合併狀態下同格內每道 `·` 的 `aria-label` 各不相同，且切的邊界正確。
- `src/lib/reading.test.ts` 全綠（含 132 張往返）；新增 `splitCellAt` 的測試涵蓋三字格切法。
- issue 02 的畫面驗收（合併、貼上、擋錯、編輯舊卡、保留與重算）不受影響。

## Comments

- 由 issue 02 實作後使用者實測 `就職難` 發現：點第一道縫全拆成三個，與預期的 `就` + `職難` 不符。經確認採「每道縫獨立拆」（符合 spec.md 決定 4）。
