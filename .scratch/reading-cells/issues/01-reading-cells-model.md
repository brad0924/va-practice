# 讀音格：標記字串與可編輯結構之間的雙向轉換

Status: done
Type: enhancement

決策背景見 `.scratch/reading-cells/spec.md`。本票只做純函式與測試，不碰任何畫面。

## 需求

新增一層「讀音格」結構，讓編輯畫面能用「詞條純文字 + 每個漢字串幾格讀音」來表達卡片，並與既有的標記字串（`焦[こ]がす`）雙向轉換。

## 決定

1. **加在既有的 `src/lib/reading.ts`，不開新模組。** `docs/spec.md` 定義了三個模組各對應一個測試接縫，「讀音標記」就是這一個。讀音格是同一個關注點的另一種表達，開第四個模組會讓接縫的說法對不上文件。

2. **既有的 `parseReading`／`toPlainText`／`toReadingText` 一律不動。** 卡片正面、預覽、語音朗讀都靠它們，本票只做加法。既有 12 個測試必須原封不動全綠。

3. **建議的結構**（實作可微調，但必須表達得出「每串漢字被切成哪幾格」）：

   ```ts
   /** 一格：一段連續漢字與使用者填的讀音。reading 為空字串代表未填。 */
   export interface ReadingCell {
     kanji: string;   // '書'、'今日'
     reading: string;
   }

   /** 詞條裡的一串連續漢字，切成一或多格。各格的 kanji 接起來即原文。 */
   export interface KanjiRun {
     /** 這串漢字在詞條純文字中的起始索引，用來定位與重建。 */
     start: number;
     cells: ReadingCell[];
   }

   /** 編輯畫面的完整狀態。term 為不含任何標記的詞條原文。 */
   export interface ReadingDraft {
     term: string;
     runs: KanjiRun[];
   }
   ```

4. **需要的操作**：

   | 函式 | 作用 |
   |---|---|
   | `toDraft(markup)` | 標記字串 → `ReadingDraft`。舊卡與貼上都走這裡 |
   | `toMarkup(draft)` | `ReadingDraft` → 標記字串。儲存時走這裡 |
   | `rebuildRuns(term, previous)` | 詞條改動後重算各串，依漢字內容保留已填讀音 |
   | `mergeSeam(run, seam)` | 把第 `seam` 道縫黏起來（`seam` 為 0 起算，範圍 0 ~ cells.length−2） |
   | `splitCell(run, index)` | 把第 `index` 格拆回逐字 |
   | `validateDraft(draft)` | 回傳錯誤訊息陣列，全部通過時為空 |

5. **漢字的定義沿用既有的 `KANJI` 常數**（`src/lib/reading.ts:13`，含擴充 A 區與疊字符號 `々`）。不另外定義一套，否則「編輯時認定的漢字」與「解析時認定的漢字」可能分岔。

6. **`toDraft` 的預設切法：逐字一格，但已存的標記優先。** 攤開 `帰省[きせい]` 得到一格 `{ kanji: '帰省', reading: 'きせい' }`，不是兩格——已存的標記就是使用者選過的切法（spec 決定 8）。只有標記裡沒被標音的漢字串才逐字開格。

   ```
   toDraft('考[かんが]え込[こ]む')
     → term: '考え込む'
       runs: [ { start: 0, cells: [{ 考, かんが }] },
               { start: 2, cells: [{ 込, こ }] } ]

   toDraft('帰省[きせい]')
     → term: '帰省'
       runs: [ { start: 0, cells: [{ 帰省, きせい }] } ]     ← 一格，不拆

   toDraft('書留')                                          ← 沒標音
     → term: '書留'
       runs: [ { start: 0, cells: [{ 書, '' }, { 留, '' }] } ]  ← 逐字兩格
   ```

7. **`toMarkup`：有讀音的格輸出 `漢字[讀音]`，沒讀音的原樣輸出漢字。** 詞條裡的非漢字部分原樣保留。

8. **`mergeSeam` 把兩格讀音接起來，`splitCell` 把讀音清空。** 合併後那格的讀音在定義上就是各段接起來（`剃[かみ]` + `刀[そり]` → `剃刀[かみそり]`），沒有接起來會錯的情況，不該丟掉已打的字。切開則無法把 `かみそり` 分配回兩個字，只能清空。

9. **`rebuildRuns` 依序比對漢字內容保留讀音**，不按位置。逐格取新舊兩邊的 `kanji` 比對，相同就把 `reading` 與該格的切法一起搬過來；不同就是新格，讀音留空、切法回到逐字。

   ```
   已填 考[かんが] 込[こ]
   詞條 '考え込む' → '考え込んだ'   → 考[かんが] 込[こ]     兩格都保留
   詞條 '考え込む' → '考え直す'     → 考[かんが] 直[]       考保留、直是新的
   詞條 '考え込む' → '深く考え込む' → 深[] 考[かんが] 込[こ] 不因插入而錯位
   ```

10. **`validateDraft` 檢查兩件事**，各自回報是哪一格：

    - **同一串漢字要嘛全填、要嘛全空。** 儲存格式的貪心往回吃會讓留空的格被後面已填的格吸走（spec 決定 11）。訊息形如「`今日中` 這串漢字的讀音要麼全部填、要麼全部留空」。
    - **讀音只能是假名。** 平假名（`ぁ`–`ゖ`）、片假名（`ァ`–`ヺ`）、長音符 `ー` 放行，其餘擋下。訊息形如「`考` 的讀音要填假名」。

    驗證只在儲存時跑，打字過程不擋。

## 驗收

- `npm test` 全綠，`src/lib/reading.test.ts` 既有 12 個測試一字未改。
- **往返測試（本票的核心）**：直接讀入 `src/data/cards.json`，132 張逐一跑 `toMarkup(toDraft(card.text))`，結果必須與 `card.text` 完全相同。這一條同時保證了舊卡編輯不會變形。
- `toDraft` 對六種段落樣式各有測試：`漢仮`（`焦[こ]がす`）、`漢`（`帰省[きせい]`）、`仮`（`くしゃみ`）、`漢仮漢仮`（`考[かんが]え込[こ]む`）、`漢仮漢`（`送[おく]り仮名[がな]`）、`仮漢仮`（`ざるを得[え]ない`）。
- `toDraft` 對未標音的多字漢字串（`書留`）產生逐字兩格；對已標音的（`帰省[きせい]`）產生一格。
- `mergeSeam` 測試：`書[かき] 留[とめ]` → `書留[かきとめ]`；`今[] 日[] 中[]` 連點第 0 道縫 → `今日[] 中[]`，`toMarkup` 得到 `今日中`。
- `splitCell` 測試：`剃刀[かみそり]` → `剃[] 刀[]`，讀音清空。
- `rebuildRuns` 測試涵蓋上面三種情境（改詞尾、換漢字、前面插入）。
- `validateDraft` 測試：`今[こん] 日[] 中[ちゅう]` 被擋；`今[] 日[] 中[]` 通過；`考[kanga]` 被擋；`コ[コーヒー]` 通過。
- 邊界沿用既有測試的關注點：空字串、`あ[い]`（括號前沒漢字）、`焦[こ`（未閉合）、`人々[ひとびと]`（疊字）跑 `toDraft` 不當掉。
