# 01 — 生出一份 iOS 26 的 HIG 逐項清單

Status: done
Type: enhancement
Blocked by: 無，可立即開始

決策背景見 `../spec.md` 的〈驗收決定〉。

## 為什麼有這張票

驗收有兩把尺：Apple 的介面指南逐項對照當**施工指引**，跟 Apple 自家 app 並排目測當**最終判定**。

**第一把尺現在還不存在。** Apple 沒有出一份「Liquid Glass 打勾表」——相關規定散在人機介面指南（HIG，Human Interface Guidelines）的材質、版面、導覽、按鈕幾章裡。沒有這份清單，每一頁畫面都要重新翻一次文件，而且翻到的東西每次不一樣。

這張票要先做完，因為後面每一頁畫面都拿它當施工指引。

## 要做什麼

從 iOS 26 的 HIG 抽出**可驗證**的條目，整理成 `../hig-checklist.md`。

**可驗證的意思是能回答「過／沒過」。** 「用起來要舒服」不收；「玻璃材質上不要再疊半透明背景」收。

要涵蓋的章節，至少：

| 章節 | 要抽什麼 |
| --- | --- |
| Materials | 玻璃材質用在哪些層、不能用在哪、上面疊什麼合法 |
| Layout | 邊距、安全區、圓角半徑的對應關係 |
| Navigation & search | 分頁列與導覽列在 iOS 26 的樣子與行為 |
| Buttons | 尺寸、形狀、狀態、最小點擊區 |
| Typography | 動態字級、字重、系統字體的用法 |

每一條寫成一行，格式：**條目 ｜ 出處章節 ｜ 怎麼驗**。

**這份清單會長大。** 每做一頁畫面碰到新的規定就補進來，不要一次想窮盡。

## 這張票不做的事

- **不寫任何程式碼。** 純文件。
- **不做設計稿。** 這份清單回答「合不合規」，不回答「好不好看」——後者是並排目測那把尺的事。
- **不涵蓋 Android 的設計規範。** 不做 Android，見 `../spec.md`。

## 驗收

- [x] `../hig-checklist.md` 存在，涵蓋上表五個章節
- [x] 每一條都能回答過／沒過，沒有「要舒服」這種條目
- [x] 每一條標出處，日後查得回原文
