# 15 — 卡片列表：搜尋與六個時間桶，順帶把單字本管理接上來

Status: ready-for-human
Type: enhancement
Blocked by: 06, 09

決策背景見 `../spec.md` 的〈實作順序〉。`spec.md:150` 寫著「這幾頁的票等複習畫面做完再開」——
票 `06` 與票 `09` 都收掉了，這道閘開了，這是排在後面那四頁的第一張。

## 為什麼有這張票

`mobile/app/cards.tsx` 現在是 12 行的「還沒做」。app 目前只複習得了，維護不了卡片。

**單字本管理提前，是因為它擋在前面。** 建立單字本的介面住在資料頁，那頁排第三順位。
但列表頁的零狀態、票 `16` 編輯頁的單字本下拉，兩邊都要有本才成立；手機上現在唯一建得出本的地方
是票 `06` 留的探針畫面。等資料頁等不到，所以把單字本那一區從資料頁拆出來，提前放進這張票。

2026-08-28 拍板，三題答案照著走：列表四樣功能全照搬、單字本管理併進這張票、
編輯頁那題見票 `16`。

## 要做什麼

對照 `src/ui/list-view.ts`（229 行）與 `src/ui/books-section.ts`（242 行），做出卡片列表頁。

| 部位 | 內容 |
| --- | --- |
| 搜尋 | 比對詞條、去標記後的詞條、讀音、釋義四個欄位，不分大小寫 |
| 六個時間桶 | 新卡／現在／今日／明天／本週／未來，各自展開收合，空桶顯示並標 0 |
| 排序切換 | 正序倒序，桶順序與桶內順序一起翻 |
| 單字本篩選 | 改的是 `scopes.list` 這一組，與複習、統計那兩組互不影響 |
| 卡片列 | 詞條（含振假名）、釋義、所屬單字本、實際到期日；新卡不長到期日那一欄 |
| 「共 N 張」 | 篩選發生在搜尋與分桶之前，所以 N 是範圍內的張數，不是全 app 的 |
| 單字本管理 | 新增、改名、刪除、匯入單字 |
| 零本 | 一本都沒有時另一套畫面，指向這一頁自己的「新增單字本」，不是死按鈕 |

### 純邏輯先抽進 `core/`

`groupByBucket()`、`bucketOf()`、搜尋的 `filter()` 現在住在 `src/ui/list-view.ts` 裡，
`book-filter.ts` 的 `scopeLabel()` 同理。**這幾支不碰 DOM，抽進 `core/lib/`，兩邊共用一份。**
票 `02` 的原則：邏輯層不准分岔。抽完網頁版改成從 `core/` 取，行為一個字不改，既有測試要全綠。

`mobile/ui/book-scope-sheet.tsx` 已經是通用的（吃 `books` / `selected` / `onChange`），
接上 `scopes.list` 直接能用，不要再寫第二支。它裡面那三行抄過去的 `scopeLabel()`，
這次改成從 `core/` 取。

### 搜尋框

用系統的搜尋列，不自己畫一個。往下捲收起、往上捲帶回來都交給系統。
清單頁的搜尋在 HIG 有專章（`Search fields`、`Searching`），這一頁做的時候要把對應條目
補進 `../hig-checklist.md`——那份清單刻意留成「邊做邊長」，現在五個章節裡沒有清單與搜尋。

搜尋期間的行為照網頁版：空桶藏起來、六桶全展開、清空搜尋框還原成搜尋前的收合狀態。

### 單字本管理

`addBook()`、`renameBook()`、`deleteBook()` 已經在 `core/lib/storage.ts`，判斷全在那裡，
畫面只負責把它說的話翻成看得到的字。刪除確認在 React Native 上沒有 `confirm()`，
改用 `Alert.alert()`。匯入單字要能選檔（`expo-document-picker`），
匯入結果與跳過的詞照 `books-section.ts` 的樣子畫在那一本底下。

### 探針畫面拆掉一半

單字本建得出來之後，探針上那塊建本的入口拆掉。**整支探針先留著**——
登入雲端仍然只有那裡做得到，資料頁還沒開票。

## 這張票不做的事

- **不做編輯畫面。** 那是票 `16`，這一頁點卡片列導過去，接縫留好即可。
- **不做資料頁與統計頁。** 雲端備份、金鑰、提醒、統計圖表都不在這張。
- **不改分桶、排序、搜尋比對的規則。** 抽進 `core/` 是搬家，不是重寫。
- **不動網頁版的外觀。** 與 spec〈不在範圍內〉一致。

## 已知風險

**六個桶加上搜尋列、工具列、tab bar，一頁上的 chrome 很多。** 票 `09` 接受過「底部一次兩條」，
這一頁是上面也有兩層。並排目測那一關要特別看這件事，過不了就先砍工具列那一排。

### 2026-08-31 — 四筆沒寫在拍板裡、但實作時做了的決定

正文與四個圖版沒涵蓋到這幾件，補記在這裡：

**一、切走再切回來，收合狀態留著。** 網頁版離開卡片頁再回來會回到「正序、六桶全收合」，
因為那邊整個畫面重建了。手機上這是一個 tab，切走只是被蓋住，因此狀態留著。
立場與票 `09` 那條驗收「切走再切回來，探針填到一半的欄位還在」一致。
（分桶、排序、搜尋的**規則**一個字沒改——票的〈這張票不做的事〉守住了。）

**二、零本建好第一本之後，那張 sheet 會自己收起來。** 資料一變，這支元件改走正常那條路，
零本那一棵樹連同開著的 sheet 一起被換掉。**要連建第二本就得再按一次「全部 ▾」**，
比網頁版（在資料頁可以連建）多一下。接受它，因為「建好了，讓我看列表」才是那一刻最可能的意圖。

**三、多了兩條翻譯檔沒有的字。** `books.done`（sheet 右上角那顆「完成」）與
`list.noBooksTitle`（零本畫面的標題）。網頁版都沒有：前者是因為這張 sheet 上會開鍵盤，
鍵盤蓋著時「往下滑收起來」不好走，得留一顆按得到的出口；後者是因為手機上的零本畫面是
一整塊空狀態（符號＋標題＋說明＋一顆鈕），比網頁版那一行提示多一層。

**四、`book-scope-sheet.tsx` 改了 546 行，不是「直接能用」。** 票正文寫「接上 `scopes.list`
直接能用，不要再寫第二支」——範圍選擇那一半確實直接能用，多出來的是管理那一半，
而那是圖版二·甲拍板要併進同一張 sheet 的結果。**沒有寫第二支範圍選擇器**，票的原意守住了。

檔案因此來到 610 行，是 `mobile/ui/` 最大的一支。審查建議把 `BookTools`／`NameForm`／
`Outcome` 抽成 `book-manage.tsx`。**這次不抽**，理由有二：那三塊全靠 sheet 自己的
`naming` 與 `expandedId` 驅動，拆檔會把一個互動流程切成兩半；而且它們現在只有一個呼叫端，
抽出來是為還沒發生的需求做準備。票 `16` 的編輯畫面若真的要重用 `NameForm`，那時候有第二個
呼叫端，抽的理由才成立——留在這裡當作那時候的第一個動作。

### 2026-08-31 — 真機第一輪：功能兩條過了，回來改兩處外觀

維護者拿 dev client 測完。**不必重新出包**——這張票沒有動 `mobile/package.json` 的
`dependencies`，也沒有動 `mobile/app.json` 的 `plugins`（原生層最後一次變動停在票 `08`／`09`），
所以包裡的原生程式碼一個字沒變，換的只有 Metro 即時送過去的那一半。
選檔改走 `expo-file-system` 這個決定在這裡回收了：照票裝 `expo-document-picker` 的話，
這一輪驗收前得先等一次 EAS Build。

驗收第 7、8 條過了。剩下的只有並排目測。

改的兩處：

**一、導覽列上的標題整條拿掉，最上面直接是搜尋框。** 「卡片」那兩個字在底下的 tab bar 上
已經有一份，導覽列再寫一次是同一句話講兩遍，而這一頁上面本來就擠。
零本畫面沒有搜尋框，因此那一頁整條導覽列收起來（`headerShown: false`），
不然上面會是一條什麼都沒有的玻璃條。

> 這是對 `N-11`（大標題隨捲動縮成標準標題）的知情偏離。那一條講的是「有大標題的話要會縮」，
> 這一頁乾脆沒有大標題，因此不適用。

**搜尋框跟著改成常駐**（`hideWhenScrolling={false}`）。票原本寫「往下捲收起、往上捲帶回來」，
那是搭配大標題才成立的：大標題縮起來的同時搜尋框跟著收，導覽列上還留著一行小標題。
標題拿掉之後那條路的終點是一條完全空白的玻璃條，因此不做了。維護者當場拍板。

**二、兩處顏色對齊網頁版。** 六個桶各一色（`.bucket-head.*`：新紫、現在紅、`<24小時` 橘、
明天黃、`<1週` 藍、未來綠），以及振假名改成 `#6ea8ff`（網頁版 `--accent`，那邊複習、卡片列、
編輯預覽三處振假名用的都是它）。桶上那個張數維持灰——網頁版的 `.bucket-count` 也另外
設了 `--muted` 蓋掉桶色。

> **這七格是寫死的色碼，違反 `mobile/ui/theme.ts` 那條「顏色一律走 `PlatformColor`」。**
> 這是票 `06` 四顆評分鈕之後的第二次，理由相同：兩邊都在用，換一台裝置不該重新學
> 哪個顏色是什麼意思。代價也相同——「提高對比」打開時這七個顏色不會跟著調整。已知並接受。
>
> `T-14`（不要只靠顏色傳達資訊）不受影響：每個桶名本身就是一句話，展開與否另有箭頭。
>
> 振假名刻意**不是** `color.accent`。那一格是 `systemBlue`，管的是「按得下去的東西」；
> 振假名按不下去，用同一個藍會把它講成一顆按鈕。畫面上因此有兩種藍，是刻意的。

沒改的兩樣（維護者看過選單後沒選）：詞條本體維持 iOS 的純白，釋義與右欄那些小字
維持 iOS 的語意灰。

畫面測試補三條守顏色——寫死的值沒有型別擋得住打錯一位數，也沒有工具看得出「明天」
拿到了「未來」那一格。手機那台現在 273 條。

### 2026-08-31 — 真機第三輪：導覽列的白底黑字，以及搜尋框擺哪

拿掉標題那一改把兩件事翻出來，其中一件是**躲了六張票的舊帳**。

#### 導覽列一直以為自己在淺色模式

真機上看到編輯頁是白底黑字、卡片頁的搜尋框是一片怪白。根因不在這張票：
**這支 app 從來沒告訴 React Navigation 它是深色的。**

`app.json` 那行 `userInterfaceStyle: "dark"` 管的是 UIKit 元件與 `PlatformColor` 語意色，
管不到導覽列——那條列的顏色由 React Navigation 自己那份主題決定，而預設值寫死在
`NavigationContainer.js` 的 `theme = DefaultTheme`（淺色）。

**票 `09` 到 `14` 之間沒有人看得出來**，因為那時候畫面上只有 `NativeTabs`，
它底下是 `UITabBarController`、長相由系統給、不吃這份主題。這張票加了第一個 `Stack`，
洞才浮出來。修在 `mobile/app/_layout.tsx`：整支 app 包一層 `ThemeProvider value={DarkTheme}`。

**但光是深色還不夠，那條列會變成不透明的深灰、不是玻璃。** React Navigation 決定導覽列
底色那一段（`useHeaderConfigProps.js`）只在三種情況給 `transparent`——有自訂 header、
開了 `headerTransparent`、或 iOS 上開著大標題；其餘一律塞主題的 `colors.card`，
那是一塊實色，會蓋掉 Liquid Glass（HIG `M-08`）。

這一頁原本是靠「大標題開著」**免費**拿到 transparent 的，拿掉大標題那條路就斷了——
所以那塊怪白是同一天稍早改出來的，不是原本就有。修在 `mobile/app/cards/_layout.tsx`：
明講 `headerTransparent: true`，不再依賴大標題這個副作用。

> **兩個開關缺一不可**：少了主題是「白底黑字」，少了 transparent 是「深色但沒有玻璃」。

#### 圖版五：搜尋框擺哪

拿掉標題之後最上面多一條空白——那是**空的導覽列本體**，iOS 把搜尋框掛在它底下自成一列。
把搜尋框擠進那一列（`placement="integrated"`）空白沒了，但它變成靠右、左邊留白。

**兩種擺法各有一個拿不掉的代價，不能兼得**（施工圖加了圖版五）：

- `stacked`：搜尋框滿版，但它上面那條導覽列一定存在。
- `integrated`：沒有多的那一列，但它的定義是「放在導覽列的**尾端**」——左邊那塊是留給
  標題與返回鈕的位置，把標題拿掉它也不會讓出來。

所以真正要決定的不是搜尋框，是**上面那一列要放什麼**。四種答案並排之後，
**維護者選了甲：把標題放回去，小小的、置中**。搜尋框維持 `stacked` 滿版。

零本畫面跟著用同一份設定（原本是整條收起來）：建完第一本會從零本切到列表，
兩邊如果一個有 header 一個沒有，那一下會跳。

> `N-11`（大標題隨捲動縮成標準標題）仍是知情偏離，但理由換了：不是「這一頁沒有標題」，
> 而是**這一頁不用大標題**——它一律靠左、又佔一整段高度，而「卡片」那兩個字在 tab bar 上
> 已經有一份。標準高度那一列夠了。
>
> 搜尋框的「捲動時不收起來」是稍早那一輪選的，當時的理由（收起來會變成空白條）
> 現在已經不成立。**沒有自動改回去**——那是維護者選過的，前提變了也該由他決定。
> 要換回票原本寫的行為，改 `hideWhenScrolling` 一行即可。

#### 桶標頭從 44 加到 52

對齊網頁版 `.bucket-head` 的 `min-height: var(--tap)`。**44 是觸控區的下限（`B-01`），
不是這一條該有的高度**——桶標頭是這一頁的骨架，六條連在一起時得比一般的列更有份量。

網頁版還有兩件沒跟進，因為它們不是調間距、是換一種列表長相：桶之間的 8px 空隙（無分隔線），
以及展開後那疊左右內縮的圓角卡片。第一件與**桶標頭黏在頂端**有衝突——黏住的標頭必須有
不透明底色，加了空隙之後捲動時會看到卡片從標頭上方穿過去。真機才判得出來，留著沒做。

#### 一個自己踩的坑，記在這裡

`t('nav.cards')` 一度被寫成模組層的常數，整支檔案當場載不進來（`i18n 還沒啟動`）——
**`t()` 在模組載入的那一刻就算完，那比 `initI18n()` 還早**。這個 repo 已經為同一件事在
`BUCKETS` 與 `RATINGS` 上各留過一段註解，那兩處的解法是「存 key 不存字」；
這裡存不了 key（要交出去的是一整組設定），改成延後到畫的那一刻才算。
測試當場紅燈抓到，沒有上到手機。

#### 驗收狀態

**十一條過了，剩「並排目測」一條。** 這幾輪真機看的是「有沒有壞、順不順眼」，
而那一條要的是拿著手機跟 Apple 自家 app 擺一起判定「不覺得舊」——是獨立的一次動作，
維護者還沒做。建議那時候出一個 `preview` 包（不用連 Metro、不換簽章、直接覆蓋更新）。
