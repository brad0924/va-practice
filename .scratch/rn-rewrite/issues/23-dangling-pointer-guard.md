## 決定

### 一、做，而且擋 commit

掛在既有的 `scripts/hooks/commit-msg` 上。git 一個關卡只認一支 hook，所以隱私權政策那道
與這道共用同一個入口，兩道各自獨立、訊息一起印。

擋得起來的前提是決定二把誤報壓到零。出口比照隱私那道：commit message 裡寫
`Links-checked: <一句話理由>`。

**掃整個工作目錄，不是只掃這次的 diff。** 這道守門要防的事，兩端天生不在同一次改動裡——
票 `21` 刪的是 `ios/` 與 `src/lib/`，壞掉的卻是 `mobile/` 底下十六行沒被碰過的註解。
只看 diff 的話那十六行永遠進不了視野。實測掃四個範圍 41 毫秒。

### 二、改寫法：指路寫成 Markdown 連結，講古繼續用反引號

三個候選裡沒有一個是原本列的。**白名單與看句子都被否掉**：新發現的四種誤報（樣板、套件
內部路徑、假設中的檔）不是「歷史」，那兩種做法對它們一點辦法都沒有。

改寫法的方向對，但原本寫的做法（限縮反引號）跟業界相反。Rust 的 intra-doc link、
C# 的 `<see cref>`、Javadoc 的 `{@link}` 共通的分界線是：**code span 沒人管，連結才受檢**。
放過反引號、另外加一個指路專用的標記，要改的是少的那一邊（指路 62 句），
不是多的那一邊（反引號提及 396 處）。

**`{@link}` 實測否決。** 它認的是程式符號，不是檔案路徑——TypeScript 5.9.3 與 6.0.3 都一樣，
`{@link ./x.ts}`、`{@link ./x}`、`{@link ./x#sym}` 三種寫法全部解析不出來（只有純符號名
`{@link marker}` 過）。而這件事要指的兩個目標剛好都沒有符號可指：一個是目錄（`app/data/`），
一個是零 export 的副作用模組（`lib/install-crypto.ts`）。

**Markdown 連結兩邊都活，因此兩邊共用同一種寫法。** `.md` 在 GitHub 上點得下去；
`.ts` 的 JSDoc 被 VS Code 當 Markdown 排版，而它的 hover provider 會把當前檔案的 URI 設成
`baseUri`（查證於其 `typescript-language-features` 的出貨程式碼），相對路徑因此解得開。
**兩邊的基準都是「這支檔自己的目錄」**，守門照的就是這一條——自己另訂一套（例如從 repo 根算）
會變成守門說得通、點下去卻跳到別的地方。

### 三、範圍是 `mobile/`、`src/`、`core/`、`docs/`

`.scratch/` 不掃。那裡是票與 spec，整片都是講古，而且它們自己不會被刪。

**不掃不代表不能指進去**：`.scratch/` 底下的 spec 與票是最常被指的目標，那些連結照樣受檢。

### 四、既有的指路一次轉完，不留尾巴

方括號裡放**原本反引號裡的字**，行文一個字不動，只多一個連結。這樣 diff 是純加法，
看的人一眼確認沒有任何一句被改寫。

帶「見／參見／詳見／請看／參考」的句子共 **64 句**，轉了 **62 句**：

- **58 句機械轉**
- **4 句手動**：一句路徑含方括號（`./[id].tsx`，會把連結語法搞壞，改用文字當標籤）、
  兩句是票號簡寫（`.scratch/.../issues/01`，補成真的檔名）、一句是真陽性
  （`review-screen.tsx:19`）
- **2 句不轉**：指進 `node_modules/`，見決定六

**全 repo 新增的連結是 63 條，不是 62。** 多的那一條是決定五的第二個真陽性
（`docs/adr/0017:23`）——那一句寫的是「靠 `X` 補上」，不帶「見」字，因此不在上面那 64 句裡。

### 五、兩處真陽性一起修

- `mobile/ui/review-screen.tsx:19`：`../app/data.tsx` → `../app/data/`（票 `18` 拆成目錄）
- `docs/adr/0017:23`：`install-random-uuid.ts` → `install-crypto.ts`（票 `05` 併掉）

留著的話守門第一次執行就失敗。

### 六、指進 `node_modules/` 的維持反引號

`mobile/lib/share-file-native.ts` 有兩處提到 `expo-sharing` 套件內部的檔。那不是版控裡的
東西，寫成連結等於承諾一件這個 repo 管不到的事——**而且會過關但是假的**：本機裝了套件就
查得到，全新 clone 在 `npm install` 之前查不到。

目前零個實例，所以不為它多寫一條規則，記成已知缺口寫在 `dangling-links.mjs` 的檔頭。

## 這張票不做的事

- **不動任何行為**——從頭到尾只動註解、文件，加上兩支 hook 用的檔
- **不掃 `.scratch/`**
- **不轉那 396 處只是「提到某支檔」的反引號**。它們不是指路，轉了會把行文灌爆

### 2026-09-04 — 實作，六個決定與一次方向修正

**開票時列的三個候選做法，一個都沒被選中。**

白名單與看句子在重掃之後就出局了：新發現的四種誤報（樣板佔位符、套件內部路徑、
相對於句子基準的路徑、假設中的檔）**不是歷史**，那兩種做法對它們一點辦法都沒有。
它們解的是「歷史 vs 指路」，而實際的題目比那大。

第三個候選「改寫法」方向對，但寫的做法是**限縮反引號**——要把 27 句講古的改掉。
查了業界之後改成相反的方向：**放過反引號、加一個指路專用的標記**，改的是 62 句指路。
Rust、C#、Javadoc 三邊共通的分界線都是「code span 沒人管，連結才受檢」。

**標記選什麼，靠實測定的，不是靠讀文件。** 第一版推薦 `{@link}`，因為那是 TypeScript
註解的正式標記。寫了一支探針去問語言服務，才發現它認的是**程式符號**不是檔案路徑：
`{@link ./x.ts}` 在 5.9.3 與 6.0.3 都解析不出來，編輯器裡是死文字。而這件事要指的兩個目標
剛好都沒有符號可指。**`{@link}` 等於箭頭寫法但更醜**，於是出局。

Markdown 連結能不能在 `.ts` 註解裡點得動，是最後一道未知。翻 VS Code 出貨的
`typescript-language-features`，hover provider 那一段確實把當前檔案的 URI 設成 `baseUri`；
之後在 VS Code 裡實地確認過連結是藍的、點得下去。**兩邊共用一種寫法因此成立**，
原本規劃的「`.md` 用 Markdown 連結、`.ts` 用 `{@link}`」那個混搭方案不必要了。

**維護者拍板：擋 commit、範圍四個目錄、62 句一次轉完不留尾巴。**
「順手修那兩處真陽性」沒問，直接做了——守門一上線就會對它們叫，留著等於第一次執行就失敗。
