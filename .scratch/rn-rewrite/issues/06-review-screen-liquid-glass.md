# 06 — 複習畫面：第一頁正式程式碼

Blocked by: 01, 02, 03, 04, 05

決策背景見 `../spec.md`。

## 為什麼有這張票

這是改寫的第一頁，也是第一次並排驗收。

**它是正式程式碼，不是原型。** 路線已定案、不留回頭路，所以這一頁寫下去就是未來那支 app 的一部分——接真的儲存、真的排程，不寫死假卡。

選複習畫面打頭陣，是因為這一頁上碰得到全部硬點：Liquid Glass 材質、振假名、單字本開關、長按選取的破綻。

## 要做什麼

對照 `src/ui/review-view.ts`，做出複習畫面：

| 部位 | 內容 |
| --- | --- |
| 標題列 | 「剩餘 N 張」＋單字本開關（改的是複習範圍，要真的能切） |
| 卡片 | 詞條（含振假名）；掀開後顯示釋義 |
| 底部 | 未掀開時一顆「顯示答案」；掀開後換成四顆評分鈕：再次／困難／好／簡單 |
| 完成狀態 | 佇列清空後顯示「今日份完成」 |
| 零本 | 一本單字本都沒有時，另外一套畫面（選單是空的，放上去就是顆死按鈕） |

**接真的東西**：卡從 MMKV 讀（票 `04`），評分走現有的排程邏輯，複習範圍改了要重建複習佇列。跨過午夜的重建、以及「正在看的那張若仍到期就留在最前面、答案維持掀開」這些既有行為照舊。

### 振假名

**兩層 `<Text>` 疊字**，做法與位移量沿用 `../../rn-spike/issues/01`：假名字身底端貼著漢字字身頂端（真機量到 15 device px），漢字底下補 0.45em 行距，整排 `flexWrap` 換行，未標音的部分逐字一欄。

那張票留了一個沒人驗過的假設：`readingPull` 假設 `lineHeight` 多出來的空間上下平分，在瀏覽器上成立，UIKit 上可能全放字的上方。**真機上要重新量一次**，順便調一次系統字級看看。

### 長按選取

- **釋義**加上可選取，長按選得起來。
- **詞條**選不起來（疊字的代價），改用一顆「複製詞條」按鈕，複製**去掉讀音標記後的詞條原文**（`焦[こ]がす` → `焦がす`）。按鈕擺哪、長什麼樣，照票 `01` 的清單走。

### Liquid Glass

用 `GlassView`，用在哪幾層照票 `01` 的清單。**iOS 26 以下自動退回一般區塊**，不另外做仿玻璃版本。

### 朗讀

**要真的會念。** 原生日文語音在這張票裡就接上，挑品質最好的日文語音、語速預設的 0.9 倍，與 `ios/App/App/SpeechPlugin.swift` 對齊。

## 這張票不做的事

- **不做其他四個畫面。** 順序是卡片列表 → 編輯 → 資料 → 統計，票等這一頁做完再開。
- **不做每日提醒、觸覺、Keychain、保險副本。** 那四項另外開票，但都要在上架前補齊——`ADR-0015` 寫明它們是通過審查準則 4.2 的實質內容。
- **不刻意對齊網頁版的外觀。** 前兩張探路票要求對齊，是因為要盲測；這次目的相反。

#### 票上沒寫、但做了的一件事：評分會推上雲端

`review-session.ts` 的 `onPersisted` 接到 `cloud.push()`，與網頁版 `src/app.ts` 的
`persist()` 同一個位置。**不接的話會掉資料**：雲端備份是整份覆蓋、較新的一份勝出，
手機上評的分若不讓 `updatedAt` 往前走，電腦那邊一推就把手機這幾天的複習整批蓋掉。

推送與標答比對不准重疊——兩件事都會抽 12 個位元組當初始向量，而比對期間亂數來源被換成
表裡那個**公開在版控裡**的固定值。閘門在 `App.tsx`；比對期間擋掉的那幾次不會遺失，
`push()` 送的是整份資料，跑完補推一次就全帶到了。

#### 朗讀與 Capacitor 版有一處對不齊

語速對得起來：`expo-speech` 的 iOS 那一端算的是 `rate × AVSpeechUtteranceDefaultSpeechRate`
（`node_modules/expo-speech/ios/SpeechModule.swift`），與 `SpeechPlugin.swift` 的
`AVSpeechUtteranceDefaultSpeechRate * 0.9` 是同一個算式，所以填 `0.9` 就一樣。

**挑語音對不齊。** `SpeechPlugin.swift` 先問系統「使用者在『設定 → 輔助使用 → 朗讀內容』
選了哪顆日文語音」，再在同名的語音裡挑品質最好的版本——票 `ios-app 15` 修的就是這條。
`expo-speech` 的 `getVoices()` 只回報全部語音，**問不到系統偏好的是哪一顆**。
這裡照本票字面走「挑品質最好的日文語音」。代價：使用者在設定裡換過日文語音，這支 app 不跟隨。
要補回來得自寫原生模組。**這一條要不要另外開票，等真機聽過再決定。**

#### 順手挖到、但不歸這張票改的一件事

`core/lib/reading.ts` 的漢字表收到擴充 A 區為止（`[㐀-䶿一-鿿々]`），
**擴充 B 區的漢字標不了讀音**——`𠮟[しか]る` 會被原樣保留成字面。切欄那一端已經處理好
（用 `[...text]` 而不是 `split('')`，一個字佔兩個碼元也不會被切成兩半）。
共用邏輯既有的範圍，這張票不動它。

#### 走了一次 /code-review，四件事改掉了

兩個軸線各跑一支，各自抓到東西，其中兩件是真的 bug。

1. **評分推上雲端之後，佇列會在複習途中被重洗一次。** `cloud-probe.ts` 的 `onPushed`
   原本與 `onPulled` 共用同一條回呼，而那條接的是「整份重讀」。登入的使用者每評一次分，
   伺服器回應一到就重洗順序、把評「再次」排回去的那幾張丟掉。網頁版 `src/app.ts` 的
   `onPushed` 只做 `data.updatedAt = updatedAt; store.save(data)`——**這正是票上那句
   「既有行為照舊」**。改法：兩條回呼拆開，推上去只走新的 `noteCloudTimestamp()`。
2. **勾一本沒有卡的單字本會打斷複習。** 網頁版 `applyData()` 有一道 `sameCards` 閘門，
   比的是**卡**不是「勾了哪幾本」；`setReviewScope()` 原本無條件重建，那道閘門整個漏掉了。
   同樣打在「既有行為照舊」上。兩件都補了測試。
3. **`M-01` 我自評錯了。** 「複製」與「朗讀」都是玻璃膠囊，而它們畫在卡片**裡面**——
   卡片是內容層。玻璃只准用在控制與導覽層。改法：多一個 `ContentPill`，形狀一樣但不套玻璃，
   那兩顆改走它。現在玻璃真的只剩標題列與底部控制列兩處。
4. **「同步」是 `CONTEXT.md` 明列要避開的詞**（會讓人以為兩邊逐張合併），探針畫面那顆
   按鈕從票 `05` 就寫著它。順手正名成「登入並跑一次雲端備份」。

另外修掉：複製完馬上評分時「已複製」會留在下一張卡的按鈕上（`key` 帶卡片編號）；
探針的 `signIn()` 吞掉非雲端來源的例外；單字本開關的無障礙標籤原本會唸出「單字本：」。

**多裝的 `react-test-renderer` 也拆掉了**——`@testing-library/react-native` v14 用的是另一個
套件 `test-renderer`，而且它明寫進 `package.json` 而不是靠別人順手帶進來：
票 `05` 的 CI 第一趟就是掛在這種事上（見 `jest.config.js` 的 `moduleDirectories` 註解）。

#### 朗讀還有第二處落差，是審查抓到的

上面那節只點了「不跟隨系統選的語音」。第二處：**`expo-speech` 看不見 premium 這一級。**
`AVSpeechSynthesisVoice.Quality` 從 iOS 16 起有三級（default／enhanced／premium），
而 `expo-speech` 的原生那一端寫的是 `quality == .enhanced ? "Enhanced" : "Default"`——
**premium 被回報成 `Default`**。`SpeechPlugin.swift` 取的是 `quality.rawValue` 的最大值，
沒有這個問題。後果：使用者若下載過 premium 的日文語音，這裡會挑到 enhanced 那顆，差一級。

資訊在過橋的時候就沒了，補不回來。兩處落差是同一個代價，要補就是自寫原生模組一次補完。

##### 圓角為什麼沒吃到：`GlassContainer` 會把裡面的玻璃融成一塊

`borderRadius: 12` 寫在 `style` 裡是對的，`expo-glass-effect` 的文件範例就是那樣寫。
JS 那一端也沒錯：`[styles.pill, style]` 攤平之後 12 蓋得掉預設的 999。

推論落在原生那一層：底部那一條包在 `GlassContainer` 裡，容器的 `spacing` 是 20，
而四顆之間只隔 12——**靠得比 `spacing` 近的玻璃會被系統融成一塊**，融形時它照自己的形狀畫，
各自的圓角設定跟著失效。標題列看起來正常，是因為那邊本來就要膠囊，融了也看不出差別。

處置：`GlassGroup` 多一個 `spacing`，底部那一條傳 `0`。**不是把容器拿掉**——HIG `M-14`
說相鄰的玻璃要放在同一個容器裡才會正確互動，拿掉就破那一條。傳 0 是「同一組、但各自獨立」，
剛好也是定案 1a 要的「四顆**分開**的玻璃方塊」。

**這是推論，沒有第二個證據。** 真機看一眼就知道：四顆變方的就對了；還是膠囊的話換下一招——
`GlassView` 的原生端另外收一個 `borderRadius` 屬性（`ios/GlassView.swift` 的 `Prop("borderRadius")`），
改成直接遞屬性而不是走 `style`。

##### 「複製」「朗讀」的圖示要等出包

樣版上那兩顆是 44 圓形配線條圖示。**自己畫不算數**：HIG `B-14` 說圖示按鈕優先用 SF Symbols 裡
代表該動作的標準符號，自己畫一個系統已經有的（`doc.on.doc`、`speaker.wave.2`）就是沒過。

系統符號要 `expo-symbols`，那是原生模組。**因此這一項掛在票 `08`＋`09` 那次出包上**，
跟它們一起做。現在先裝的話，目前這個 development 版裡沒有那個模組，兩顆鈕會直接壞掉。
在那之前維持文字鈕——文字鈕不好看，但按得到。

#### 2026-08-26 第四輪：圓角推論成立，但翻出一個一直都在的版面錯

**融形會蓋掉圓角，這條推論是對的。** `GlassGroup` 的 `spacing` 傳 0 之後四顆變方的了，

同一次真機比對又指出兩件事：

##### 「按鈕沒有滿版」——`flex: 1` 一直套錯層

`GlassPill` 裡面是兩層：外面一層可按區域，裡面一層玻璃。**呼叫端給的 `style` 原本套在裡層**，
所以 `flex: 1` 落在玻璃上，而真正排在那條列裡的是外層——外層沒有樣式，就縮到跟文字一樣寬。
四顆評分鈕因此各自縮成一小塊擠在中間，「顯示答案」也一樣。

**這個錯從票 `06` 第一版就在**，只是先前那幾輪按鈕是膠囊、又只有四顆短標籤，縮著看不出不對；
定案 1a 要的是整條列平分，才把它照出來。

處置：`style` 改套在外層並在型別上寫明「只放版面」，玻璃自己 `alignSelf: 'stretch'` 撐滿它。
圓角因為必須套在裡層，改成一個 `block` 開關，不再由呼叫端傳樣式進來。

連帶動到 `ratingsFitOneRow()`：它以前用一個「評分鈕左右各留 4」的數字，而那個內距正是套錯層、
從來沒畫出來過的其中一項。改成用真正的 `PILL_PADDING_H`（18）之後**四顆會比以前更早堆疊**——
那才是它一直以來實際的樣子，不是放寬標準。測試裡的字級跟著從 2.4 改成 1.5。

##### 探針被 Expo 開發版的浮動按鈕擋住

**不是這支 app 的問題，不改程式。** 那是 `expo-dev-menu` 的 floating action button
（`ios/DevMenuManager.swift` 的 `setShowFloatingActionButton`），只存在於開發版，正式版沒有。
搖手機或三指長按叫出開發者選單，在裡面把那顆浮動按鈕關掉即可。

票 `09` 把探針搬進「資料」tab 之後，標題列右上角不再有東西，這件事自然消失。

##### 卡片四邊都要看得到

原本卡片鋪滿整頁、從上下兩條控制列底下透出去。那是第一輪「玻璃看不出來」的解法——
玻璃的重點是折射，底下沒東西經過就跟一塊素色區塊沒兩樣。

維護者知道這個代價，仍然選了「卡片要有明確的邊」，四邊都切，**並且兩條列維持玻璃**。

> **這是知情的偏離：`L-02`（捲動區鋪滿整頁，內容從控制列底下透出來）。**
> 上面那份第一輪的逐項自評裡 `L-02` 那一行**就此作廢**，與 `M-09`、`M-10` 兩條同樣的處理方式。
> 票 `09` 加上導覽列與三頁真內容之後這一區會重新長回來，那時候再回頭看值不值得換回去。

做法：讓開兩條列的距離從「卡片自己的內距」改成「捲動區的內距」，卡片因此不再長到列底下。

##### 單字本開關移到標題列正中間

標題列變成左中右三段：剩餘張數、單字本、探針。用兩格彈簧推，**只是「差不多」置中**——
兩格一樣長，單字本的中心會落在左右兩邊寬度的平均處而不是螢幕正中心。這一頁上兩邊差不到幾點，
看不出來；要真的對準螢幕中心得改用絕對定位，那會讓大字級下的換行整個失效。
