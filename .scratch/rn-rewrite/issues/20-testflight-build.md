## 為什麼有這張票

`../spec.md`〈上架〉寫著：

> **Capacitor 版不先送審，等 React Native 版好了才一起送，而且不設回頭看的時間點。**

「等 React Native 版好了」那個條件在 2026-09-03 達成了：19 張功能票全收，
四項原生功能（語音、觸覺、Keychain、每日提醒）到齊，`ADR-0015` 要的 4.2 實質內容成立。

但**沒有任何一張票在講 React Native 版怎麼出包上 TestFlight**。`rn-rewrite` 那 19 張
全是功能票，最後一張（`19`）的驗收是真機驗收，走的是 `eas build --profile preview`
那種內部散佈的包，**不是 App Store 散佈的包**。

## 現況盤點

### 現成的那條路是 Capacitor 版的，接不上

`.github/workflows/ios-testflight.yml` 存在，而且能動——但它底下跑的是：

- `npx cap sync`
- `xcodebuild -project ios/App/App.xcodeproj`

React Native 版沒有 `ios/App/`（`mobile/.gitignore` 把 `/ios` 排除掉了，原生專案每次
建置重新產生），也不經過 Capacitor。**那支 workflow 一行都用不到。**

它用到的 secrets 倒是可能還有價值，因為指向的是同一個 Apple 帳號與同一個 Bundle ID：

| Secret | 用途 |
| --- | --- |
| `APP_STORE_CONNECT_KEY_ID` / `_ISSUER_ID` / `_PRIVATE_KEY` | App Store Connect API 金鑰，上傳用 |
| `IOS_DIST_CERT_P12` / `_PASSWORD` | 散佈憑證 |
| `IOS_PROVISIONING_PROFILE` | 佈建描述檔 |
| `APPLE_TEAM_ID` | 團隊識別碼 |

Bundle ID 兩版相同：`io.github.brad0924.vapractice`（票 `ios-app 01` 定案，
走 TestFlight 必須先建 app 記錄，因此提前綁死）。**App Store Connect 上那筆 app 記錄
已經存在**，這張票不必重建。

### `mobile/eas.json` 缺兩段

```json
{
  "cli": {
    "appVersionSource": "remote",
    "promptToConfigurePushNotifications": false
  },
  "build": {
    "development": { "developmentClient": true, "distribution": "internal" },
    "preview": { "distribution": "internal" }
  }
}
```

- **沒有 production profile。** 兩個現有的都是 `distribution: "internal"`，出來的是
  ad-hoc 包：裝得上登記過的手機，**上不了 TestFlight**。TestFlight 要 App Store 散佈。
- **沒有 `submit` 段。** `eas submit` 要它才知道往哪個 App Store Connect 帳號上傳。

### 版號那一格

`appVersionSource` 是 `remote`，代表 build number 由 EAS 伺服器管，不是 `app.json`。
`app.json` 的 `expo.version` 是 `1.0.0`，`ios.buildNumber` 沒有設（`remote` 之下正確）。

**但 Capacitor 版那支 workflow 已經佔用過 TestFlight 的 build number。** EAS 從哪個數字
接下去、會不會與既有的撞號，沒有查過。

### 憑證

`mobile/credentials.json` 不存在，代表要嘛走 EAS 代管憑證、要嘛還沒設。
EAS 代管會自己去 Apple 後台建憑證與描述檔——**那與上面那批 GitHub secrets 是兩套東西**，
要不要讓它自己管、還是餵現成的那批進去，沒有決定過。

## 要你拍板的（`/grill-with-docs` 的題目）

1. **憑證讓 EAS 代管，還是餵現成的那批進去？** 代管省事但會在 Apple 後台多建一套；
   餵現成的要把 p12 與描述檔轉成 `credentials.json`。
2. **build 在哪裡跑？** `eas build` 用 EAS 雲端的 macOS runner，那正是當初選 CI 的理由
   （維護者是 Windows、無 Mac，見 `ios-app 11`〈決定〉那段訂正）。既然如此，
   `.github/workflows/ios-testflight.yml` 還要不要留？停掉、刪掉、還是改寫成呼叫 eas？
3. **版號怎麼接。** EAS 的 remote build number 與 Capacitor 版已經用掉的那幾號怎麼銜接。
4. **`ios-app 11`（送審）那張凍結的票要不要解凍。** 它擋在十張 blocker 後面，其中
   `20`（多語系素材）自己就寫著「這條 blocker 是時程選擇而非技術必然」。
   這張票只做到 TestFlight，**送審是另一件事**——但兩者的界線要先畫清楚。
5. **`ios-app 21`（app 圖示還是 Capacitor 範例圖）在 React Native 版還成立嗎？**
   `mobile/assets/icon.png` 是這一版自己的，那張舊票可能已經不適用。
