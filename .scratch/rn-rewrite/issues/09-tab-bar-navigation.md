# 09 — 底部導覽列，四個畫面終於連得起來

Status: done
Type: enhancement
Blocked by: 06

決策背景見 `../spec.md` 的〈實作順序〉與 `../hig-checklist.md` 的〈Navigation & search〉。
版面樣版（維護者挑定的那一張）：https://claude.ai/code/artifact/30a399e0-bec1-4271-af09-170e3320ec12

## 為什麼有這張票

**這支 app 目前沒有任何導覽。** 複習畫面是唯一一頁，網頁版那顆「卡片」按鈕在票 `06` 被拿掉（目的地還沒做），探針只好擠在標題列上當臨時後門。

2026-08-26 並排目測沒過，維護者指名的五處之一就是「標題列三顆膠囊不平衡」——那三顆之所以擠在一起，根源是**沒有地方放導覽**。

這張票不是為了好看才開的：**四個頂層畫面正是 tab bar 存在的理由**，而這個決定會決定後面四頁怎麼長，現在做最便宜。

## 導覽模型：第 1 案，兩條列疊著

三個模型並排比過（畫布上曾有 `Nav1`／`Nav2`／`Nav3`），維護者選第 1 案：

| 模型 | 為什麼沒選 |
| --- | --- |
| 複習當成工作階段（導覽列上只有卡片／資料／統計，複習是蓋上來的一層） | 把每天最常做的事推到第二層 |
| 掀開答案時導覽列讓位給評分列 | 畫面會跳，而且掀開的那段時間走不到別的畫面（違反 `N-03`） |

**選定的做法**：評分列在上、導覽列在下，兩條同時看得見。合規、沒有意外，代價看得見。

> **已知並接受的代價：底部一次兩條 chrome。** 最大字級下評分鈕會堆成四行（票 `06` 已知情接受那件事），再加一條導覽列會更擠。
> 減輕的因素：iOS 26 的導覽列會在捲動時自己縮小，真機上比靜態圖寬鬆——但那要真機才驗得到。

## 要做什麼

### 導覽列本身

**iOS 26 的樣子，不是 iOS 18 的樣子。** 這一點畫錯過一次：舊版是整寬貼底、方角、實心一條；**iOS 26 是浮在內容上的膠囊**，左右內縮到系統邊距內，底下的內容透出來（`N-01`、`L-05`）。

四個 tab，每個都要有文字標籤且只用一個詞（`N-06`）：

| tab | 目的地 |
| --- | --- |
| 複習 | 票 `06` 的複習畫面 |
| 卡片 | 佔位畫面 |
| 資料 | **探針畫面**（見底下） |
| 統計 | 佔位畫面 |

**圖示要用 SF Symbols**（`N-07`，優先選填滿版）。React Native 沒有內建，要加 `expo-symbols`——**這是原生模組，動工要重新出包**。自己畫的圖示不算數，`N-07` 明講。

### 探針搬進「資料」tab

**標題列上那顆「探針」拆掉。** 它做的事（加卡、登入雲端、看標答比對）本來就是資料頁的事，因此改當「資料」那一頁的內容。

好處有三：標題列乾淨了；「資料」不是一個空的 tab，是「還沒做完的資料頁」；資料頁那張票動工時探針就地被取代，不必再找它。

**在這張票做完之前，探針仍留在複習畫面的標題列上**——那是它目前唯一的入口，不能先拆。

### 佔位畫面

卡片與統計各一頁，寫明「還沒做」。**tab 不因為內容是空的就停用或隱藏**，要在頁內說明為什麼是空的（`N-05`）。

## 與票 08 一起出包

票 `08`（評分觸覺）要 `expo-haptics`，這張票要 `expo-symbols`，兩個都是原生模組。**湊在一起出一次包**，不要分兩次——每一次 EAS Build 都要等，而且每等一次維護者的 Metro 快速迭代就斷一次。

**2026-08-26：同一批還多一項。** 票 `06` 的「複製」與「朗讀」要從文字鈕改成圓形圖示鈕（樣版 1a 上就是那樣），用的是 SF Symbols 的 `doc.on.doc` 與 `speaker.wave.2`，因此也要 `expo-symbols`。**票 `06` 已經收掉，因此那一項改由這張票負責**——裝了模組卻只接 tab 圖示，等於讓那兩顆鈕再等一次出包。這不算「動複習畫面的版面」，換的是兩顆鈕的內容，不動排版。

## 這張票不做的事

- **不做卡片列表、資料、統計三頁的真正內容。** 那是各自的票，這裡只給佔位畫面與一條走得到的路。
- **不做編輯畫面。** 它不是頂層畫面，不進導覽列。
- **不動複習畫面的版面**（卡片、詞條、評分鈕長什麼樣）。那些在票 `06`，這裡只在底部加一條列並把它讓開。
- **不加搜尋 tab。** 搜尋現在活在卡片列表裡，`N-08` 那條規定用不上。

### 2026-08-26 — 實作完成，六條收掉，剩下的全部要真機

#### 四個 tab 的符號挑了一輪，維護者選定

三組並排比過，選的是「活動配收藏」那一組。**「複習」與「卡片」天生會搶同一個圖案**（都是一疊卡），這一組的拆法是一個畫動作、一個畫收藏：

| tab | 符號 | 為什麼 |
| --- | --- | --- |
| 複習 | `graduationcap.fill` | 學士帽。它是**在做的一件事**，不是一批東西 |
| 卡片 | `rectangle.stack.fill` | 一疊卡。那一頁裝的就是全部的卡 |
| 資料 | `gearshape.fill` | 齒輪。那一頁之後裝雲端備份、金鑰、提醒，齒輪是 iOS 上最好認的一個 |
| 統計 | `chart.bar.fill` | 長條圖 |

沒選的兩組：「四個都是實物」（卡／書／硬碟／圓餅圖——硬碟這個比喻離雲端備份太遠）、「照雲端那條線走」（打勾／四宮格／雲／長條圖——打勾圓圈在 iOS 上代表「已完成」的狀態，不是一個去處）。

**第三個符號是自己拍板的，一起列進目測那一輪**：「複製」按下去之後換成 `checkmark`。原本鈕面上寫「已複製」三個字，換成圓形圖示鈕之後那三個字沒有地方放，整顆符號換成一個勾是 iOS 自己在做同一件事時的樣子。唸出來的那一句照舊跟著換（`review.copy` → `review.copied`），看不到畫面的人收到的回報一模一樣。

#### 票上沒寫、但做了的三件事

1. **`mobile/app/` 底下八支檔搬到 `mobile/ui/`。** Brief 有交代要搬（那個目錄整個是路由表），但沒說搬去哪。`app/` 現在只剩五支路由檔，每一支十幾行，把共用的那一份接進畫面。
2. **「今日份完成」那一塊抽成 `ui/notice.tsx`。** 佔位畫面要的是同一塊東西（大符號、標題、一句說明），照抄一份就是兩份會走鐘的程式碼。複習畫面那三處空狀態現在與佔位畫面長得一樣——那是刻意的，人才會一眼認出「這不是壞掉，是沒東西」。
3. **探針畫面改成每次切回來重讀一次本機資料**（`useFocusEffect`）。理由見底下。

#### /code-review 抓到兩件事，都改了

**一、探針畫面手上那份資料會停住，而且會掉資料。** 這一頁以前是被蓋上來的一層，離開就整個卸載、回來重建，所以「開機讀一次」等於「每次進來都讀」。改成 tab 之後四頁同時掛著，切走只是被蓋住——**在「複習」評幾張再切過來按「加 5 張卡」，存下去的是上次進來時那份快照，中間評的分整批被蓋掉。**

修法是 `useFocusEffect`，每次這一頁拿到焦點就重讀。**沒有用換 `key` 重建整個元件**：那會把填到一半的暱稱與密碼一起清掉，而 Brief 的加註驗收明講「切走再切回來，探針填到一半的欄位還在」。

**二、三處引用的 HIG 條號對不上表。** `L-05` 管的是「按鈕」不是導覽列；`B-13` 管的是「玻璃效果」的形狀，而那顆圖示鈕自己開頭就寫著不套玻璃。都改掉了。同一輪還補上 `B-10` 在圖示鈕上的偏離說明（尺寸與圓角只能自己給，守的是 44 下限與「圓角永遠取直徑一半」）。

#### 複習畫面那支測試動了兩條斷言

Brief 說「斷言不動」，那是針對元件搬家。**這兩條不是搬家造成的**：「複製」從一顆寫著字的膠囊變成圓形圖示鈕，鈕面上沒有字了，`getByText('複製')` 因此查不到東西。改成 `getByLabelText('複製')`——查的是唸出來的那一句，也就是換掉外觀之後還留著的同一個承諾。

另外加了一條新的：**按鈕裡的符號名字是不是 `doc.on.doc`、按下去是不是換成 `checkmark`。** 名字打錯由 `tsc` 擋（型別收了 SF Symbols 全表），換錯符號只有測試擋得下來。

#### 一件沒解乾淨的事：標題列的單字本更偏了

開票理由裡「標題列三顆膠囊不平衡」只解了一半。拆掉右邊那顆「探針」之後，**「單字本」比以前更偏離中心**——它靠兩格彈簧推到中間，而左邊還有「剩餘 N 張」那行字佔著位置，右邊現在空了。

真的對準螢幕中心得改用絕對定位，那會讓大字級下的換行整個失效（那一條是真機踩出來的，票 `06` 記過）。偏移多少留給並排目測那把尺判。

## Agent Brief

**Category:** enhancement
**Summary:** 用 Expo Router 的原生 tabs 接上四個頂層畫面，探針從標題列搬進「資料」tab，複習畫面那兩顆輔助鈕換成系統符號。

**Current behavior:**

這支 app 沒有導覽。根元件靠一個 `showProbe: boolean` 在複習畫面與探針畫面之間二選一，探針的入口是複習畫面標題列上一顆寫著「探針」的玻璃膠囊。卡片與統計兩個畫面不存在。相依裡沒有任何導覽或符號套件。

**Desired behavior:**

底部一條系統原生的 tab bar，四個 tab（複習／卡片／資料／統計），每個都有一個詞的文字標籤與一個填滿版的 SF Symbol。tab bar 浮在內容上、左右內縮、捲動時自己縮小。複習是預設那一頁；「資料」裝的是現在的探針畫面；卡片與統計各是一頁說明「還沒做」的佔位畫面。複習畫面標題列上那顆「探針」不再存在。

**Key interfaces:**

- **原生 tabs 的 API 目前掛在 `expo-router/unstable-native-tabs`，官方標 alpha。** 元件是 `NativeTabs`，每個 tab 是一個 `NativeTabs.Trigger`，裡面放 `NativeTabs.Trigger.Label` 與 `NativeTabs.Trigger.Icon`。圖示用 `Icon` 的 `sf` prop 吃 SF Symbol 名字（例：`sf="house.fill"`），不要自己畫也不要走 `expo-symbols`——那支留給複習畫面那兩顆鈕。**動工前先查 SDK 57 的版本化文件確認名字有沒有變**（`mobile/AGENTS.md` 就是這樣要求的）。

- **`expo-router` 會把 `mobile/app/` 整個目錄當成路由表。** 現在住在裡面的非畫面元件（玻璃膠囊、詞條、複製鈕、單字本選單、主題常數）必須搬到別的目錄，否則會被當成路由。
- **進入點會改成 `expo-router/entry`，而現在的 `index.ts` 有一個順序約束不能破。** 那支檔第一行載入的加解密補丁**必須早於任何 `core/` 的程式碼**——`core/` 用得到 `crypto.subtle`、`crypto.randomUUID()` 與 `btoa()`，React Native 一個都沒有。改進入點時要確保補丁仍然最先跑，這一點錯了會在載入當場炸掉。
- **儲存、複習流程、雲端備份這三樣是整支共用的單例，四個畫面都要拿得到同一份。** 現在它們在根元件的一個閉包裡建起來，彼此接線（雲端拉下來要重建複習佇列、每次評分存完要推上去）。**不要讓任何一頁自己再建一份**——`../spec.md`〈程式碼怎麼擺〉把「邏輯層分岔」列為這條路上最不能踩的線。用 context 或模組層單例都可以，選一種。
- **加解密標答比對必須仍在 app 啟動時就跑，不能等人點進「資料」tab。** `.github/workflows/mobile-crypto.yml` 只是把 app 開起來、等結論寫成檔案；比對若改成進頁才跑，那支 CI 會永遠等不到。它同時是雲端推送的閘門（比對期間亂數來源被換成固定值，那段時間不准推），閘門邏輯要跟著一起搬，不能只搬畫面。

### 2026-08-27 — 捲動縮小驗收沒過。不是 iOS 版本，是那支 finder 只認第一個孩子

真機（iOS 26）測不出 tab bar 縮小。**`minimizeBehavior="onScrollDown"` 那一行沒有問題，原生那一端也接上了**——`react-native-screens@4.26.2` 的 `RNSTabsHostComponentView.mm` 確實有 `_controller.tabBarMinimizeBehavior = ...`。

問題在**它找不到這一頁的捲動區**。`RNSContainerItemSupport.mm` 的解析順序有三段：

1. `ScrollViewMarker` 註冊的那一個（**這條路是死的**，原生那一半包在 `#if RNS_GAMMA_ENABLED` 裡，要裝 pod 時開環境變數才編得進來）
2. 巢狀容器交出來的
3. 啟發式：`RNSScrollViewFinder.findScrollViewInFirstDescendantChainFrom:`

第三條就是我們走的那一條，而它長這樣：

```objc
} else if ([currentView.subviews count] > 0) {
  currentView = currentView.subviews[0];   // 只走第一個孩子，不看兄弟
}
```

探針畫面的第一個孩子是那層彩色裝飾背景，捲動區排第二。finder 鑽進條紋堆、走到底、回 `nil`。tab bar 手上沒有東西可盯，因此一輩子不縮。

**這個症狀長得極像「iOS 版本不夠」**，票上那條驗收也是這樣寫的（「要 iOS 26，26 以下這個值被系統忽略」），差點就照那個方向結案。

#### 順帶查到：複習畫面本來就找得到，只是沒東西可捲

`review-screen.tsx` 的 `ScrollView` **就是 `root` 的第一個孩子**，finder 找得到。但那一頁通常一個螢幕就塞得下，沒有捲動就沒有縮小。

也就是說：**票 `09` 拿來抵銷「底部一次兩條 chrome」的那個減輕因素，在複習畫面上本來就兌現不了**——那是最擠的一頁，也是唯一不會捲的一頁。這筆帳要重算，但重算屬於並排目測那一輪要看的事，不在這則裡下結論。

#### 修法：裝飾層搬進捲動區（維護者選定）

排在前面又要畫在底下，在 iOS 上是互斥的——「畫在底下」就等於「排在前面」。因此把裝飾層搬進 `ScrollView` 當第一層，捲動區升格成 `root` 的第一個孩子。

**代價是裝飾層會跟著內容一起捲**，玻璃卡與背景的相對位置不再變化，滑動時看不到卡片掠過不同顏色。這一頁是暫時的鷹架（資料頁那張票會整張換掉），因此接受。

沒選的那條是「排到後面再用 `zIndex` 壓回底層」：版面一行不動，但 React Native 在新架構下會不會順手把 `subviews` 也重排，讀原始碼讀不出結論——賭錯就要再出一次包。

#### 這條規矩以後每一頁都適用

**任何想吃到捲動縮小的畫面，捲動區都必須在「一路只走第一個孩子」那條鏈上。** 裝飾層、絕對定位的標題列、任何排在捲動區前面的兄弟，都會把它擋掉。程式碼看不出來，測試也守不住（那是原生的 subview 順序），只有真機會說話。

### 2026-08-27（同日更正）— 上一則的結論是錯的。缺的是一顆 `ScrollViewMarker`，不必重出包

搬完裝飾層之後真機再測，**還是不縮**。回頭把整條鏈重查一次，上一則有兩個地方講錯：

**錯的第一件：「`RNS_GAMMA_ENABLED` 沒開」。** 那是我從 podspec 讀到旗標存在就推論的，沒有去查實際的包。查了兩份 build log，`-DRNS_GAMMA_ENABLED=1` **確實在 RNScreens 的編譯參數裡**——Expo SDK 57 預設就開著。

**錯的第二件：以為那支「只走第一個孩子」的 finder 管的是捲動縮小。** 它管的是別的事（點狀態列回到頂端）。真正把捲動區交給 `UITabBarController` 的是 `setContentScrollView:forEdge:`，而整個套件裡**只有一條路會叫它**：

```objc
- (void)registerDescendantScrollView:(UIScrollView *)scrollView fromMarker:(RNSScrollViewMarkerComponentView *)marker
{
  [_controller setContentScrollView:scrollView forEdge:NSDirectionalRectEdgeAll];
```

`fromMarker:` ——**要有人真的畫出一顆 `ScrollViewMarker`，這條路才會被走到。** 我們一顆都沒有，所以從頭到尾沒有任何人告訴 tab bar 該盯哪個捲動區。`minimizeBehavior` 那一行設得再對也沒有用。

#### 修法：一顆不畫任何東西的元件

```tsx
import { ScrollViewMarker } from 'react-native-screens/experimental';

<ScrollViewMarker>
  <ScrollView contentContainerStyle={styles.center}>…</ScrollView>
</ScrollViewMarker>
```

它從自己**唯一的那個孩子**解析出捲動區，再往上找到這一頁的 tab screen 去註冊。**它是往上找的，因此擺哪一層都行**，裝飾層排在前面也不影響。

**上一則那個「裝飾層搬進捲動區」的改動已經倒回去了。** 它當時是為了討好那支找錯對象的 finder，代價是條紋會跟著內容捲、玻璃卡與背景的相對位置不再變化——而那正是這一頁存在的理由。理由消失，代價就不該留著。

#### 不必重新出包

`RNSScrollViewMarkerComponentView.mm` 在現有這包裡**已經被編成 `.o`**（build log 查得到）。加的是純 JavaScript 的一行 import 與一層包裝，Metro 重載就吃得到。

#### 這條規矩以後每一頁都適用

**任何想吃到捲動縮小的畫面，都要自己包一顆 `ScrollViewMarker`。** 它不是自動的，`NativeTabs` 也不會幫你補。兩條規矩不能破：只能有一個孩子（原生那邊有 assert），而且那個孩子要解析得出捲動區。

它來自 `react-native-screens/experimental`，那個入口的檔頭寫明「隨時可能改，不跟大版號」。升 SDK 之後這條驗收若又不過，先回來確認 `RNS_GAMMA_ENABLED` 那個旗標還在不在。

#### 上一則裡仍然成立的那一段

複習畫面**一個螢幕就塞得下、沒東西可捲**，因此票 `09` 拿來抵銷「底部一次兩條 chrome」的那個減輕因素，在最擠的那一頁上本來就兌現不了。這筆帳還是要在並排目測那一輪重算。
