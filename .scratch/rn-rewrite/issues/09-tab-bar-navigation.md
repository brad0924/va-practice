# 09 — 底部導覽列，四個畫面終於連得起來

Status: ready-for-agent
Type: enhancement
Blocked by: 06

決策背景見 `../spec.md` 的〈實作順序〉與 `../hig-checklist.md` 的〈Navigation & search〉。
版面樣版（維護者挑定的那一張）：https://claude.ai/code/artifact/30a399e0-bec1-4271-af09-170e3320ec12

## 為什麼有這張票

**這支 app 目前沒有任何導覽。** 複習畫面是唯一一頁，網頁版那顆「卡片」按鈕在票 `06` 被拿掉（目的地還沒做），探針只好擠在標題列上當臨時後門。

2026-08-26 並排目測沒過，維護者指名的五處之一就是「標題列三顆膠囊不平衡」——那三顆之所以擠在一起，根源是**沒有地方放導覽**。

這張票不是為了好看才開的：**四個頂層畫面正是 tab bar 存在的理由**，而這個決定會決定後面四頁怎麼長，現在做最便宜。

## 導覽模型：第 1 案，兩條列疊著

三個模型並排比過（畫布上曾有 `Nav1`／`Nav2`／`Nav3`），維護者選第 1 案：

| 模型 | 為什麼沒選 |
| --- | --- |
| 複習當成工作階段（導覽列上只有卡片／資料／統計，複習是蓋上來的一層） | 把每天最常做的事推到第二層 |
| 掀開答案時導覽列讓位給評分列 | 畫面會跳，而且掀開的那段時間走不到別的畫面（違反 `N-03`） |

**選定的做法**：評分列在上、導覽列在下，兩條同時看得見。合規、沒有意外，代價看得見。

> **已知並接受的代價：底部一次兩條 chrome。** 最大字級下評分鈕會堆成四行（票 `06` 已知情接受那件事），再加一條導覽列會更擠。
> 減輕的因素：iOS 26 的導覽列會在捲動時自己縮小，真機上比靜態圖寬鬆——但那要真機才驗得到。

## 要做什麼

### 導覽列本身

**iOS 26 的樣子，不是 iOS 18 的樣子。** 這一點畫錯過一次：舊版是整寬貼底、方角、實心一條；**iOS 26 是浮在內容上的膠囊**，左右內縮到系統邊距內，底下的內容透出來（`N-01`、`L-05`）。

四個 tab，每個都要有文字標籤且只用一個詞（`N-06`）：

| tab | 目的地 |
| --- | --- |
| 複習 | 票 `06` 的複習畫面 |
| 卡片 | 佔位畫面 |
| 資料 | **探針畫面**（見底下） |
| 統計 | 佔位畫面 |

**圖示要用 SF Symbols**（`N-07`，優先選填滿版）。React Native 沒有內建，要加 `expo-symbols`——**這是原生模組，動工要重新出包**。自己畫的圖示不算數，`N-07` 明講。

### 探針搬進「資料」tab

**標題列上那顆「探針」拆掉。** 它做的事（加卡、登入雲端、看標答比對）本來就是資料頁的事，因此改當「資料」那一頁的內容。

好處有三：標題列乾淨了；「資料」不是一個空的 tab，是「還沒做完的資料頁」；資料頁那張票動工時探針就地被取代，不必再找它。

**在這張票做完之前，探針仍留在複習畫面的標題列上**——那是它目前唯一的入口，不能先拆。

### 佔位畫面

卡片與統計各一頁，寫明「還沒做」。**tab 不因為內容是空的就停用或隱藏**，要在頁內說明為什麼是空的（`N-05`）。

## 與票 08 一起出包

票 `08`（評分觸覺）要 `expo-haptics`，這張票要 `expo-symbols`，兩個都是原生模組。**湊在一起出一次包**，不要分兩次——每一次 EAS Build 都要等，而且每等一次維護者的 Metro 快速迭代就斷一次。

**2026-08-26：同一批還多一項。** 票 `06` 的「複製」與「朗讀」要從文字鈕改成圓形圖示鈕（樣版 1a 上就是那樣），用的是 SF Symbols 的 `doc.on.doc` 與 `speaker.wave.2`，因此也要 `expo-symbols`。**票 `06` 已經收掉，因此那一項改由這張票負責**——裝了模組卻只接 tab 圖示，等於讓那兩顆鈕再等一次出包。這不算「動複習畫面的版面」，換的是兩顆鈕的內容，不動排版。

## 這張票不做的事

- **不做卡片列表、資料、統計三頁的真正內容。** 那是各自的票，這裡只給佔位畫面與一條走得到的路。
- **不做編輯畫面。** 它不是頂層畫面，不進導覽列。
- **不動複習畫面的版面**（卡片、詞條、評分鈕長什麼樣）。那些在票 `06`，這裡只在底部加一條列並把它讓開。
- **不加搜尋 tab。** 搜尋現在活在卡片列表裡，`N-08` 那條規定用不上。

## 驗收

- [ ] 四個 tab 都在，每個都有一個詞的文字標籤，圖示是填滿版的系統符號
- [ ] 導覽列是浮著的膠囊、左右內縮，捲動時底下看得到內容經過（不是一塊不透明實色）
- [ ] 三個佔位畫面進得去、回得來，頁內說得出為什麼是空的
- [ ] 探針在「資料」tab 裡，複習畫面的標題列上沒有它了
- [ ] 評分列與導覽列同時在場時不重疊，卡片內容讓得開兩條
- [ ] 最大字級下走一次：評分鈕堆成四行加上導覽列，仍然按得到、看得到
- [ ] 每一條導覽路徑上導覽列都看得見（`N-03`）
- [ ] 複習畫面的「複製」與「朗讀」換成 `doc.on.doc` 與 `speaker.wave.2`，不是自己畫的（`B-14`）
- [ ] `../hig-checklist.md` 的 Navigation 那一章逐項核過，做不到的逐條寫明理由
- [ ] **並排目測**：與 Apple 自家 app 擺一起，維護者判定不覺得舊

### 2026-08-26 — Triage：導覽列走 Expo Router 的原生 tabs，標 `ready-for-agent`

> *This was generated by AI during triage.*

**票上沒寫的那一件事：導覽列拿什麼搭。** 票把長相、四個 tab、探針怎麼搬都寫死了，但沒說用哪一套框架。三條路並排比過（畫布：https://claude.ai/code/artifact/8778f6f3-5ea0-4ee6-bbb9-e6b698e6261e），維護者選 **Expo Router 的原生 tabs**。

| 沒選的 | 為什麼 |
| --- | --- |
| `react-native-bottom-tabs` + React Navigation | 一樣接到系統的 tab bar，行為拿得到，但相依樹更大、路由要手寫，而且跟 `../spec.md`〈路線〉定的 Expo 官方工具鏈不一致 |
| 自己用 `GlassView` 畫一條 | **捲動縮小做不到**——那是 `UITabBarController` 內部的行為，不對外開放 |

**第三條路為什麼是致命的**：上面〈已知並接受的代價〉那一段，票自己寫的減輕因素是「iOS 26 的導覽列會在捲動時自己縮小」。**那句話只有系統原生的 tab bar 兌現得了。** 自己畫的話那個減輕因素直接消失，最大字級下就是四行評分鈕加一條永遠滿高的導覽列——正是那一段最擔心的畫面。

**玻璃不是差別。** `expo-glass-effect` 已經在包裡，票 `06` 那顆膠囊就是真玻璃，三條路的 `N-01` 都過得了。差的只有捲動縮小與系統自帶的 tab 行為。

**`expo-symbols` 仍然要裝。** 前兩條路的 tab 圖示由框架給，但複習畫面那兩顆「複製」「朗讀」還是要它。〈與票 08 一起出包〉的安排一個字不改。

## Agent Brief

**Category:** enhancement
**Summary:** 用 Expo Router 的原生 tabs 接上四個頂層畫面，探針從標題列搬進「資料」tab，複習畫面那兩顆輔助鈕換成系統符號。

**Current behavior:**

這支 app 沒有導覽。根元件靠一個 `showProbe: boolean` 在複習畫面與探針畫面之間二選一，探針的入口是複習畫面標題列上一顆寫著「探針」的玻璃膠囊。卡片與統計兩個畫面不存在。相依裡沒有任何導覽或符號套件。

**Desired behavior:**

底部一條系統原生的 tab bar，四個 tab（複習／卡片／資料／統計），每個都有一個詞的文字標籤與一個填滿版的 SF Symbol。tab bar 浮在內容上、左右內縮、捲動時自己縮小。複習是預設那一頁；「資料」裝的是現在的探針畫面；卡片與統計各是一頁說明「還沒做」的佔位畫面。複習畫面標題列上那顆「探針」不再存在。

**Key interfaces:**

- **原生 tabs 的 API 目前掛在 `expo-router/unstable-native-tabs`，官方標 alpha。** 元件是 `NativeTabs`，每個 tab 是一個 `NativeTabs.Trigger`，裡面放 `NativeTabs.Trigger.Label` 與 `NativeTabs.Trigger.Icon`。圖示用 `Icon` 的 `sf` prop 吃 SF Symbol 名字（例：`sf="house.fill"`），不要自己畫也不要走 `expo-symbols`——那支留給複習畫面那兩顆鈕。**動工前先查 SDK 57 的版本化文件確認名字有沒有變**（`mobile/AGENTS.md` 就是這樣要求的）。
- **捲動縮小是 `NativeTabs` 上的 `minimizeBehavior="onScrollDown"`，需要 iOS 26 與 Xcode 26。** 這一項是票裡「兩條 chrome」代價的減輕因素，不能漏掉。
- **`expo-router` 會把 `mobile/app/` 整個目錄當成路由表。** 現在住在裡面的非畫面元件（玻璃膠囊、詞條、複製鈕、單字本選單、主題常數）必須搬到別的目錄，否則會被當成路由。
- **進入點會改成 `expo-router/entry`，而現在的 `index.ts` 有一個順序約束不能破。** 那支檔第一行載入的加解密補丁**必須早於任何 `core/` 的程式碼**——`core/` 用得到 `crypto.subtle`、`crypto.randomUUID()` 與 `btoa()`，React Native 一個都沒有。改進入點時要確保補丁仍然最先跑，這一點錯了會在載入當場炸掉。
- **儲存、複習流程、雲端備份這三樣是整支共用的單例，四個畫面都要拿得到同一份。** 現在它們在根元件的一個閉包裡建起來，彼此接線（雲端拉下來要重建複習佇列、每次評分存完要推上去）。**不要讓任何一頁自己再建一份**——`../spec.md`〈程式碼怎麼擺〉把「邏輯層分岔」列為這條路上最不能踩的線。用 context 或模組層單例都可以，選一種。
- **加解密標答比對必須仍在 app 啟動時就跑，不能等人點進「資料」tab。** `.github/workflows/mobile-crypto.yml` 只是把 app 開起來、等結論寫成檔案；比對若改成進頁才跑，那支 CI 會永遠等不到。它同時是雲端推送的閘門（比對期間亂數來源被換成固定值，那段時間不准推），閘門邏輯要跟著一起搬，不能只搬畫面。
- **`app.json` 要加 `expo-router` 外掛與 scheme。**

**Acceptance criteria:**

票上方〈驗收〉那十條全部成立，其中兩條在此加註：

- [ ] 第 1 條的圖示用 `NativeTabs.Trigger.Icon` 的 `sf` prop；**四個符號動工時挑一輪給維護者目測**（票上只定了複習畫面那兩顆是 `doc.on.doc` 與 `speaker.wave.2`，四個 tab 的沒定）
- [ ] 第 2 條「捲動時底下看得到內容經過」**在「資料」tab 上驗，不是複習畫面**。理由：票 `06` 收尾記了 `L-02` 的知情偏離，卡片收成四邊都看得到的一張，複習畫面兩條列底下是純黑，這一條在那裡驗不到。探針畫面本來就包在 `ScrollView` 裡，內容夠長

另加三條這條路線特有的：

- [ ] `minimizeBehavior` 有接上：真機捲動時 tab bar 會縮成小膠囊
- [ ] 切走一個 tab 再切回來，該頁的狀態還在（複習到第幾張、探針填到一半的欄位）
- [ ] 現有測試全過。複習畫面那支測試若因為元件搬家而找不到 import，改路徑即可，斷言不動

**Out of scope:**

- 票上〈這張票不做的事〉四條照舊。
- **不動 `core/` 的邏輯層。** 這張票只換畫面怎麼組起來。
- **不碰加解密**，只確保它照舊在啟動時跑。
- **不改複習畫面的版面。** 「複製」「朗讀」換的是兩顆鈕的內容（文字換成圓形圖示鈕），排版不動。
- **不裝 `expo-haptics`。** 那是票 `08`，同一次出包但不同票。
