# 05: 手機橫著拿，問答改成左右兩欄

Status: done
Type: enhancement
Blocked by: 02

## 要做什麼

手機橫著拿時高度很矮，詞條加四列選項會超出一個螢幕，限時 10 秒內還得捲動。改成左右兩欄：左邊詞條與碼表，右邊四個選項直排，不必捲動就看得到全部。

## 驗收

- [ ] 切兩欄的門檻**直接沿用拼字票 08 定好的那一條**，不另訂一個數字。
- [ ] 手機橫著拿：左欄詞條與碼表，右欄四個選項直排，四個都不必捲動就看得到。
- [ ] 詞條底下答完才出字的那一行（「答對了 · N 分」，票 07 加的）跟著詞條放左欄。
- [ ] 平板橫著拿不切，維持上下排。
- [ ] 直握的排法完全沒變。
- [ ] 長的釋義在右欄照常換行，不撐破版面。
- [ ] jsdom 沒有排版，以上全部靠實機驗收（`ADR-0014`），至少一台手機橫、直各看一次，平板或桌機縮窄視窗看一次。

## 規格出處

`.scratch/quiz/spec.md` 實作決定十；測試決定「只能實機驗收的」。

## Comments

**只改 CSS，程式一行沒動。** 問答答題頁本來就是「標題列、`.prompt`（碼表、詞條、答完那一行、結束鈕）、`.quiz-options`」三塊，跟拼字答題頁同一個形狀。所以直接把拼字那條 `@media (max-height: 31rem)` 的三條規則各多掛一個 `.screen:has(> .quiz-options)`。「答完那一行」本來就在 `.prompt` 裡，自動跟著進左欄。

**無頭 Chrome 量過的數字**（iframe 框死尺寸，字型不是 iPhone 的，只當參考）：

- `667×375`、`667×320`、`844×390`、`844×340`：切成兩欄，右欄 222px 寬。四個短釋義不必捲。
- `375×667`、`390×844`、`768×1024`、`1024×768`、`1180×820`：改動前後量到的每個數字完全相同，都是上下排。

**已知代價：四個選項都很長時，橫握右欄要捲。** 四個都接近 30 字時，右欄只有 222px 寬，每個選項折成三行、97px 高，加起來超過右欄高度（例如 `667×375` 要 414px、右欄只有 307px）。原因是 `.screen` 的 `max-width: 30rem`，667px 寬的螢幕左右各空 93px——拼字票 08 的 Comments 記過同一塊空白。

試過兩種補救：問答橫握時拿掉那個上限，長選項降到 73px，但 667 寬仍要捲；再加上選項降到 44px 高、字小一號，量過的四種尺寸就全部不必捲。維護者看過數字後**選擇接受要捲，不開票**。

**還沒做的驗收：實機。** 至少一台手機橫、直各看一次，平板或桌機縮窄視窗看一次（`ADR-0014`）。
