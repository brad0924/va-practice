# 07: 答完那一刻印出這題拿幾分

Status: ready-for-agent
Type: enhancement
Blocked by: 02

## 為什麼有這張票

2026-09-18 維護者實機測完票 04 後問：「按下答案以後沒有像拼字一樣馬上看到分數，是正常的嗎？」

這是照規格做的。spec 實作決定七列了點下選項之後畫面要做的事（碼表停、選項鎖住、標讀音、正解綠、點錯紅、停 1 秒），清單裡沒有「印出這題幾分」。但規格談的時候沒有討論過這一點，比較像漏談，不是刻意不印。拼字答完會多一行「拼對了 · 8 分」，問答沒有，兩邊不一致。

當時端出三個做法：加一行分數、停留維持 1 秒；加一行分數、停留拉長到 1.6 秒；維持現狀。**維護者選了第一個。**

## 要做什麼

- **答完那一刻，畫面上多一行字**，講這一題的結果與分數。三種收尾各一句：答對、答錯、逾時。樣子比照拼字答題頁那一行（`spelling-view.ts` 的 `OUTCOMES` 與 `.verdict`）：字加顏色，答對綠、答錯紅、逾時用拼字那個「晚了」的顏色。
- **分數一律問 `settle()` 回傳的結果**，畫面自己不算。拼字那一行三句都吃 `{points}`，答錯與逾時必定是 0 分，但那條規則歸 `quiz.ts` 管，不寫死在句子裡。
- **過了時限才點下去，照逾時印**（票 02 已經把那種情況畫成逾時，這一行跟著走），不會出現「答對了 · 0 分」。
- **停留維持 1 秒**（`SETTLE_PAUSE_MS` 不動）。實玩之後嫌太趕再另外調。
- **這一行放在詞條底下**，也就是畫面上半、選項上面。選項在下半，點完眼睛本來就要往上看讀音，分數擺在同一塊。票 05 做左右兩欄時，這一行跟著詞條與碼表放左欄。
- **答題中、還沒點的時候，這一行是空的**，不佔位置也不閃。

## 三語文字

問答自己一組 key（`quiz.settledCorrect`／`quiz.settledWrong`／`quiz.settledTimeout`），不借拼字那三條：拼字講的是「拼對」，問答是「答對」，與成績頁頂上那一格各自一組 key 同一個理由。

- 中文：`答對了 · {points} 分`、`答錯了 · {points} 分`、`逾時 · {points} 分`。逾時用「逾時」，不用拼字的「時間到」，與票 03 成績頁那兩個字一致。
- 英文與日文照拼字那三句的寫法（英文名詞在前 `Points: {points}`，日文 `{points}ポイント`）。動手前先讀每一份翻譯檔開頭的規矩。

## 驗收

- [ ] 點對：詞條底下印「答對了 · N 分」，N 與這一題結算出來的分數一致。
- [ ] 點錯：印「答錯了 · 0 分」。
- [ ] 逾時、以及過了時限才點：印「逾時 · 0 分」。
- [ ] 還沒點的時候那一行是空的；進下一題時清掉。
- [ ] 停留時間仍是 1 秒。
- [ ] 新增的畫面文字三份翻譯檔都補齊。
- [ ] 測試斷言那一行的字，不斷言 class 名（`ADR-0014`）；顏色若要自動測試，比照拼字把「這一行算哪一種」拉成可測的東西。
- [ ] 冒煙測試走過問答答題頁「已作答」的狀態時，三種語言都沒有漏出原始 key（現有的那一步應該已經涵蓋，確認一下）。
- [ ] spec 實作決定七補一段更新，比照票 06 在 spec 裡留下的寫法：原文保留，後面接「2026-09-18 更新（票 07）」。

## 只能實機驗收的

- 1 秒內看得到分數那一行，正解綠、點錯紅、讀音都還看得清楚，不覺得太擠。
- 375px 寬時那一行不換成兩行、不把選項往下推到要捲動。
