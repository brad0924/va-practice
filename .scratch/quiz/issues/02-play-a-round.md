# 02: 問答走通一輪

Status: done
Type: enhancement
Blocked by: 01

## 要做什麼

使用者從複習畫面點「問答」，就能從頭玩到尾：一題一題答、看到對錯、一輪結束看到成績、再來一輪。

這張**先不做挑書**：點進來直接拿**全部**單字本出題，挑書頁是票 04 的事。成績頁先只有頂上三格加「再一輪」，沒答對的清單是票 03 的事。

## 驗收

**導覽**
- [x] 複習畫面標題列右邊擺三顆：「拼字」「問答」「卡片」。
- [x] 拼字的標題列右邊從「卡片」改成「問答」。
- [x] 問答的標題列：左「拼字」、中「問答」、右「卡片」。答題與成績頁共用同一條，比照拼字那一條。
- [x] 卡片畫面左上角的返回從「拼字」改成「問答」。
- [ ] **在 375px 寬量過一次複習標題列**：膠囊變省略號可以；按鈕拆字或標題列換行就停下來回報，不要自己改版面規則（spec 實作決定九）。

**進場**
- [x] 上一輪還封存著就給成績頁，否則直接用全部單字本開一輪。
- [x] 出不了題時（沒有可出的卡，或整個 app 湊不出四個不同的釋義），給與拼字「這本是空的」同一個空畫面。

**答題**
- [x] 上方是詞條，**不標讀音**，旁邊一個 10 秒碼表，樣子與拼字的碼表同一種。
- [x] 下方四個選項直排、佔滿整行寬度，長的釋義照常換行。選項前**不印數字**。
- [x] 點下一個選項：碼表停住；其他選項全部點不動；詞條標上讀音；正解轉綠，點錯的轉紅。
- [x] 逾時：正解轉綠、詞條標上讀音、沒有紅的，記 0 分。
- [x] 兩種情況都停 1 秒再自動進下一題，這 1 秒不算作答時間。停留長度開成具名常數。
- [x] 手滑連點兩個選項，同一題只結算一次。
- [x] 沒有朗讀鈕、沒有鍵盤操作。
- [x] 中途「結束」鈕直接結算、跳成績頁。

**一輪與成績**
- [x] 一輪存在 app 狀態裡自己那一格，與拼字那一格分開。
- [x] 答題途中跳去別的畫面，回來看到的是那一輪的成績頁。
- [x] 在拼字與問答之間來回切換，兩邊的上一輪各自都還在。
- [x] 成績頁頂上三格：答對 `9 / 12`、總分、平均，每格底下有自己的標籤。
- [x] 成績頁有「再一輪」，用同一批卡重開一輪。

**三語與守門**
- [x] 新增的畫面文字三份翻譯檔都補齊。動手前先讀每一份翻譯檔**開頭的規矩**（英文那份有單複數與名詞順序的規定）。譯名以 `docs/glossary.md` 為準：Quiz／クイズ。
- [x] 問答的畫面一行都不 import 資料存放那支模組，也不從別的畫面繞路 import 到：擴充拼字現有的那一道守門，不另寫一道。
- [x] 三語冒煙測試走進問答的答題頁與成績頁，三種語言各一次。
- [x] 答題的 jsdom 測試：點了一個選項後其他點不動、1 秒之內還停在原題、過了 1 秒換題、逾時後換題且記成逾時、「結束」到成績頁、跳走再回來看到成績頁。不斷言 class 名與版面（`ADR-0014`）。

**實機**
- [ ] 正解綠、點錯紅、讀音標上，這 1 秒在手機上看得清楚。

## Comments

實作在 `src/ui/quiz-home.ts`（入口與頁間接線）、`quiz-view.ts`（答題）、`quiz-summary.ts`（成績）、`quiz-bar.ts`（標題列）。測試在 `quiz-home.test.ts`、`quiz-view.test.ts`，導覽在 `src/app.test.ts`，三語在 `src/i18n/smoke.test.ts`。

**驗收第五條（375px）踩到停止條件，沒有勾。** 量法：無頭 Chrome 開 375×667 的 iframe，單字本只有一本、膠囊只寫「全部」。結果：

- 中文：「拼字」「問答」一行，「卡片」掉到第二行，標題列 48px → 88px。
- 日文：三顆各一行，136px。英文：兩行，88px。
- 沒有拆字。原因不在膠囊：`1fr auto 1fr` 讓左右兩欄等寬，左欄只放「剩餘 N 張」，右欄只分得到約 135px，三顆中文鈕要 154px。
- 對照組：拿掉「問答」回到兩顆，中文是一行（48px）；英文與日文在兩顆時就已經換行（這台 Windows 的字型，與 iPhone 不同，只能當參考）。

照這一條的規矩停下來回報。維護者決定先照現況提交，版面改由新票處理：網頁版比照手機版改成底部導覽列（`.scratch/web-tab-bar/`）。那張票做完之後，這張的「導覽」一節會整節被取代。

實作時維護者拍板的兩件事：

- **出不了題時整頁換成一段說明**（圖示、標題、一句話，樣子比照拼字零本那一頁），句子是問答自己新的一條（`quiz.noCardsTitle`／`quiz.noCardsNote`）。沒借拼字那句 `spelling.noCards`：那句講「沒標讀音」，而讀音不是問答的出題條件。票 04 做挑書頁時可以改回拼字那種「頁內一句紅字」。
- **碼表抽成共用的 `src/ui/countdown-clock.ts`**，拼字與問答都用它。拼字的測試一行沒改，照樣全綠。

另外三件實作時自己拍板的事：

- **守門改成順著 `./x` 一路往下追 import**（`spelling-home.test.ts` 的 `reachable()`），拼字與問答兩條線共用。原本只看入口的鄰居，碼表搬出去之後就多了一層，照原寫法追不到。拿「在 `countdown-clock.ts` 塞一行 import storage」試過，兩條線都會紅。
- **過了時限才點下去，照逾時畫。** 碼表 0.1 秒才醒一次，瀏覽器裡還常晚到；空檔裡點下去 `quiz.ts` 會判 0 分，畫面卻照「有點」畫，會出現「正解轉綠卻 0 分」或「逾時卻有紅的」。審查時抓到的，補了一條測試。
- **`app.test.ts` 的測試卡從兩張加到四張**：問答要整個 app 湊得出四個不同的釋義。拼字那條「練到一半跳走」原本跳去卡片，拼字標題列右邊改成問答之後改成跳去問答。

沒做的：答題頁的顏色（綠、紅）沒有自動測試。spec 測試決定把顏色列為實機驗收，因此沒像拼字成績頁那樣拉出一支可測的 `toneOf()`。
