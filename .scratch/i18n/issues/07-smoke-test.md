# 07 — 三語冒煙測試

Status: ready-for-agent
Type: enhancement
Blocked by: 06

決策背景見 `../spec.md` 決定十一。

## 要做什麼

一支約 20 行的測試：三種語言各切一次，主要畫面各渲染一次，檢查兩件事——

1. **沒有拋出例外**
2. **畫面上沒有漏出原始 key**（例如出現字面上的 `books.addButton`）

## 它抓的是什麼

只有一件事：**程式某處拿顯示文字去做判斷，而不是拿 key。**

例如某段程式寫成「如果標頭文字等於『新』就做某事」——中文下會過，切到英文就靜默失效。這種問題 TypeScript 型別擋不到，一般測試也不會碰到，因為測試預設只跑一種語言。

**它抓不到的：**

| 問題 | 為什麼抓不到 |
| --- | --- |
| 漏譯 | 票 02 的型別已經在建置時擋掉了，重複 |
| 英文太長把按鈕撐爆 | jsdom 沒有真實排版與字型。那要靠票 08 的實機驗證 |
| 翻錯（意思不對） | 機器判斷不了 |

## 決定

### 不要整套測試跑四遍

收益只剩上面那一項，成本卻是測試時間 ×4。**一支冒煙測試就夠。**

### 「沒有漏出原始 key」怎麼判

key 的命名是 `區塊.名稱` 這種帶點的英數字串（票 02 定案）。渲染完之後掃一次 `textContent`，若出現符合 `^[a-z]+\.[a-zA-Z]+$` 的獨立字串，就是漏了。

注意誤判：卡片內容、單字本名字是使用者資料，也可能長得像 key。**這支測試用的是自己造的測試資料**，把資料造成不會誤判的樣子即可，不要為了迴避誤判把判斷式寫複雜。

### 渲染哪些畫面

複習、卡片列表、編輯、統計、資料五個。這五個涵蓋了 204 條裡的絕大多數。

不必追求 100% 覆蓋——冒煙測試的定位是「有沒有整個燒起來」，不是完整驗證。

## 這張票不做的事

- **不改任何翻譯內容**
- **不把現有測試改成跑四遍**
- **不處理版面問題**（票 08）
- **不為了迴避誤判把判斷式寫複雜**

## 驗收

- [ ] 測試存在，三語各渲染五個畫面一次
- [ ] 故意在某個畫面留一個沒有對應翻譯的 key → 紅燈
- [ ] 故意讓某段程式用顯示文字做判斷 → 切到非中文時紅燈
- [ ] 整支測試跑起來不超過幾秒（三語 × 五個畫面）
- [ ] `npm run test` 與 `npm run typecheck` 全綠
