# 04 — 語言選單

Status: done
Type: enhancement
Blocked by: 03

決策背景見 `../spec.md` 決定十。

## 要做什麼

資料畫面新增一段「介面語言」，讓使用者選語言。**這是整個 i18n 需求裡使用者唯一看得到的新東西。**

## 決定

### 放在資料畫面最上面

```
[卡片]      資料      [統計]
─────────────────────────────
## 介面語言          ← 新增
## 雲端備份
## Gemini API 金鑰
## 每日提醒
## 手動備份
```

理由：語言是「app 用什麼話跟你說」，比其他四段都基礎；而且看不懂畫面的人要找語言選單時，最上面最容易找到。

### 用 `<select>`，不自製清單

`editor-view.ts:44` 的單字本選擇已經是同一種元件，不是新東西。iPhone 上會叫出系統原生的選取介面，手感不用自己調。

**被否決的是自製清單**（四行直接列出、選中打勾）：外觀完全可控，但滑動與點擊的手感要自己調到跟原生一樣。若日後想改，落點不在 i18n——純前端做法屬 `.scratch/touch-feel-gaps/`（會同時影響語言選單與單字本選單，是共用元件問題），呼叫 Capacitor 原生 Action Sheet 才屬 `.scratch/ios-app/`。

### 四個選項用各自的語言寫

| 值 | 顯示 |
| --- | --- |
| `system` | 系統預設（跟著當前介面語言變） |
| `zh-Hant` | 繁體中文 |
| `en` | English |
| `ja` | 日本語 |

**除了「系統預設」以外，四個選項的文字不隨介面語言變。**

理由很實際：萬一有人手滑切到日文，滿畫面日文的時候他還認得出「繁體中文」那四個字找得回來；用當前介面語言寫的話就變成一場猜謎。

「系統預設」沒有自稱，只能跟著當前介面語言變，因此它是 `zh-Hant.ts` 等三支檔案裡的一條 key。

### 說明文字沿用既有措辭

這一段的 `hint` 要說明「只影響這台裝置」。`data-view.ts:39` 的每日提醒已經有一句現成的措辭可以沿用：

> 這個開關只影響這台裝置，不會上傳雲端，也不會出現在匯出的備份檔裡。

語言的情況一模一樣（`../spec.md` 決定五），照抄同一個立場即可，不要另外發明講法。

### 切換之後立刻重新渲染

不需要重開 app。切換後把當前畫面重新渲染一次，接線走 `app.ts`——與「複習範圍一變就重建佇列」是同一種做法（票 02 已定）。

### 選「系統預設」時不顯示目前實際是哪一種

**已定案：不做。** 也就是選項就寫「系統預設」，不寫成「系統預設（日本語）」。

理由是那會讓 `<option>` 的文字變成動態的，而換到的好處只是省掉使用者自己看畫面判斷——他選完之後畫面立刻就切了，看一眼就知道是哪一種。

若實作時覺得沒有它真的很難懂，在本檔 `## Comments` 記一筆退回討論，**不要默默加上去**。

## 這張票不做的事

- **不改資料畫面的名稱**。那個畫面叫「資料」但已經裝了 Gemini 金鑰與每日提醒，加上語言之後名實不符會更明顯——這是已知的，見 `../spec.md` 決定十三，日後要改是另一張票
- **不自製彈出面板**
- **不動其他四段的順序或內容**

## Comments

**「最上面」改成「單字本底下」。** 票面與 spec 決定十都把資料畫面寫成四段（雲端備份、
Gemini、每日提醒、手動備份），但實際上最上面還有第五段「單字本」——`data-view.ts` 的
註解寫著「它是這一頁的主角」。兩份文件都漏數了這一段。使用者裁決：語言排在單字本底下、
雲端備份上面，也就是**其餘設定之首**。票面「語言比其他幾段基礎」的理由仍然成立，
只是那個「其他幾段」不包含單字本。

**三個自稱是寫死的中文字面值**（`'繁體中文'`、`'English'`、`'日本語'` 在
`data-view.ts`）。票 03 的驗收「非測試 `.ts` 檔沒有剩下的中文字面值」多了第四種例外，
理由就是票面那條「除了系統預設以外不隨介面語言變」——進了翻譯檔就會被票 06 翻掉。
`data.langSystem` 是四個選項裡唯一進翻譯檔的一條。

**版面借 `.form` 的直排與間距**，沒有新增 CSS。`list-view.ts` 的空狀態已經用過同一招
（那裡的註解就寫著「借 .form 的直排與間距」）。直接排在 `section` 底下的話，
選單的下緣會貼著說明文字——`.hint` 的 `margin` 是 0。

### 新增 `src/app.test.ts`

票 02 的 Comments 寫著「`app.setLang()` 這 4 行到票 04 之前是零覆蓋的死碼，
票 04 驗收會驗到它」。那條接線跨三段（選單 → `app.setLang()` → 重畫），只有真的從
`start()` 走一遍才驗得出來，因此開了這支檔案。**它是目前唯一從開機演起的測試**，
只裝這一件事。

`start()` 直接碰全域的 `localStorage`，而 vitest 的 jsdom 環境裡沒有那個東西
（Node 26 的實驗性 `localStorage` 蓋掉了 jsdom 的，`window.localStorage` 與
`globalThis.localStorage` 兩邊都是 undefined），因此測試用 `vi.stubGlobal()` 換一份
記在 Map 裡的假貨進去。

分辨語言靠的是 `books.addButton`——票 03 之後 `en.ts`／`ja.ts` 只有兩條是真譯文，
那是其中一條，也是資料畫面上唯一三語各自不同的字。票 06 填完之後這個選擇會變寬。

### code review 後的修正

**`docs/spec.md` 的測試規範改掉了（使用者裁決）。** 原本寫「畫面本身不撰寫自動化測試」，
並解釋「擋的是需要瀏覽器或 jsdom 才跑得起來的測試」——但 `editor-view.test.ts`、
`book-filter.test.ts`、`dom.test.ts` 早就跑在 jsdom 上了，那句話在這張票之前就已經
與現況對不上。改成的界線是：**不做真瀏覽器的端對端測試；jsdom 上只寫非 DOM 不可的
行為（焦點、鍵盤與指標事件的接線、元素順序、事件接上沒接上），不斷言版面、不斷言
class 名、不做 DOM 快照。** 選的是改前提而不是替既有三支各記一筆例外。

**`app.test.ts` 裡寫死的英文譯文改成查表。** 原本是
`expect(...).toBe('+ Add vocabulary book')`，票 06 換英文譯文時它會無辜紅燈，
而 `.scratch/i18n/spec.md` 明文採用「測試從翻譯檔取字串斷言」。改成
`en['books.addButton']`。同一條測試裡 `expect(navigator.language).toBe('en-US')`
也拿掉了——那驗的是 jsdom，不是產品。

**順序測試補一條有「每日提醒」的。** 原本只餵 `reminder: null`（＝網頁版），
那一段根本沒長出來，驗收寫的「其餘四段順序不變」實際只驗到三段。

**沒有採納的一條**：`langSelect()` 這支 helper 在兩支測試檔裡各有一份。量小，
而且兩邊撈的是不同的東西（一個是元件回傳的節點、一個是整個 app 畫進去的那一格），
抽成共用反而要多一個檔案。

**i18n spec 決定十追記了一行**（不改原文），註明落點從「最上面」修正為「單字本底下」。

### 手動驗過的

（`system`／`zh-Hant`／`en`／`ja`）、預設停在「系統預設」都對。**iPhone 的原生選取
介面還沒驗**，那一條留著。
