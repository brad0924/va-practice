# 08 — 日文介面與日文學習內容會不會打架：實機判定

Status: done
Type: research
Blocked by: 06

決策背景見 `../spec.md` 決定七。

## 要做什麼

**這張票只判定有沒有問題，不做任何設計。**

在 iPhone 實機把介面切成日文，打開複習畫面，回答一個問題：**一眼看過去，能不能立刻指出畫面上哪幾個字是「要背的」。**

- **可以** → 關掉這張票，在 `../spec.md` 決定七底下補一行「已實機驗證不需處理」
- **不行** → 開第二張票討論怎麼改（底色、外框、字級、字體），那時候你手上有實機畫面，是看著東西討論，不是憑空想

## 問題長什麼樣

中文介面現在是這樣：

```
┌────────────────────────────┐
│ 剩餘 12 張          [卡片] │  ← 介面
├────────────────────────────┤
│         こ                 │
│        焦がす              │  ← 學習內容（詞條）
│                            │
│       燒焦、烤焦           │  ← 學習內容（釋義）
│                            │
│    [🔊 朗讀]   [編輯]      │  ← 介面
├────────────────────────────┤
│ [再次][困難][好][簡單]     │  ← 介面
└────────────────────────────┘
```

切成日文之後，介面那三塊也變成日文，跟正中央要背的日文詞條混在同一個畫面上。

## 判定時要記得的三件事

**一、詞條已經有三個很強的區隔特徵**：位置在正中央、字級最大、頭上頂著振假名。評分按鈕則在最底部、包在方框裡。所以「打架」未必真的嚴重——這正是要實機看的原因。

**二、釋義永遠是使用者自己打的字。** 日文介面下的畫面不是「全日文」，而是「日文介面 + 日文詞條 + 使用者的釋義」三種混在一起。判定時要用**真實的卡片**，不要用測試資料。

**三、英文介面沒有這個問題**，拉丁字母與日文的漢字假名一眼分得開。所以要判的只有日文一種，順手看英文有沒有版面問題就好。

## 順便看一件事：版面有沒有被撐爆

英文普遍比中文長、日文的假名也會拉長行寬，按鈕被撐爆是真實風險，而**jsdom 測不出來**（票 07 的冒煙測試明文不管這個）。既然已經在實機上了，三種語言各掃一遍五個畫面，看有沒有文字溢出、換行怪異、按鈕擠在一起。

發現的話記在本檔 `## Comments`，另開票修，**不要在這張票裡順手改 CSS**。

## 怎麼接實機

熱點加 `vite --host`，手機連過去。這是這個 repo 既有的做法，`.scratch/touch-feel-gaps/issues/01` 的驗收也是這樣寫的。

**Windows 上的桌面瀏覽器判不了這件事**——字體渲染、字級、觸控距離都不一樣。

- **不改任何翻譯內容**
- **不設計視覺區隔方案**。判定「會混」就開第二張票，這張只出判定

## Comments

### 判定：不會混

**維護者在 iPhone 實機上判定為「不會混」，可以馬上清楚辨認哪幾個字是詞條。**

因此不開第二張設計票，不做任何視覺區隔。票面推測的那三個區隔特徵（位置在正中央、字級最大、頭上頂著振假名）實測站得住。

### 驗證環境走的是 TestFlight，不是 dev server

票面「怎麼接實機」那一節寫的是熱點加 `vite --host`。**實際走的是 TestFlight**：把當前分支打成 build 上 TestFlight，用 iPhone 下載 app，在 app 裡把介面語言切成日文。

這條路比票面寫的那條好，理由有二：

1. **真實卡片是白吃的午餐。** 票面第二點要求「用真實的卡片，不要用測試資料」，但 `localStorage` 是綁網址的——`http://<電腦IP>:5173/va-practice/` 是一個全新的空抽屜，得先把備份檔搬進手機再匯入才有真卡。TestFlight 那份就是平常在用的 app，資料本來就是真的。
2. **原生殼才看得到的東西，網頁版看不到。** 票 07 的 `## Comments` 記了兩個缺口——`data-view.ts:268` 的「每日提醒」整區在 `app.reminder === null` 時直接回 null，而**網頁與 jsdom 都是 null**；朗讀按鈕則要 `speechSynthesis` 才長得出來。這兩塊只有原生殼裡才在畫面上。走 dev server 網頁版反而掃不到。

**日後這類實機驗證票的「怎麼接實機」建議改寫成 TestFlight 優先**，熱點加 `--host` 留給「還沒打 build、只想快速看一眼」的場合。這是本票的順帶發現，沒有另外開票。

### 版面掃描：三語五畫面，沒有發現問題

日文與英文各切過一次，複習、卡片列表、編輯、統計、資料五個畫面都看過。**沒有文字溢出、換行怪異或按鈕擠在一起。**中文是現況，本來就沒問題。

因此不開修版面的票。

值得記一筆的是這一條**確實沒有第二個東西在守**：票 07 明文寫「英文太長把按鈕撐爆」抓不到，因為 jsdom 沒有真實排版與字型。而 `b6f8d5d`（英文的每日提醒黏成一團）證明這類問題真的會發生。所以這次掃出全綠是有價值的資訊，不是走過場——但同時也表示，**日後改文案或改 CSS 之後沒有任何自動檢查會再幫忙看一次**，那仍是已知缺口。
