# 文件跟上焦點落點測試：spec 那條「畫面本身不撰寫自動化測試」已經被翻案

Status: needs-triage
Type: enhancement
Blocked by: 01

## 現況

`01` 在 `src/ui/editor-view.test.ts` 開了 jsdom，測 `jumpToEmpty` 的兩條落點分類。程式那邊
沒問題（七條測試會紅會綠，拔碼驗過），問題在 `docs/spec.md` 有三句話與它直接打架：

| | 原文 |
|---|---|
| `:206` | **畫面本身不撰寫自動化測試**。以此工具的規模，瀏覽器層級測試的維護成本高於其所能攔截的缺陷。 |
| `:208` | 這句擋的是**需要瀏覽器（或 jsdom 這類假瀏覽器）才跑得起來的測試**，不擋畫面資料夾底下的純邏輯 |
| `:227` | （Out of Scope）**畫面層級（瀏覽器）自動化測試**。 |

`:208` 點名的正是 jsdom，射程一字不差地涵蓋 `01` 做的事。

### `01` 為什麼沒處理到

`01` 的「這張票不做的事」寫著：

> **不改 `docs/spec.md:105`。** 那句管的是「模組不得 import DOM」，而 `editor-view.ts` 是畫面
> 不是模組，畫面本來就碰 DOM。預設環境仍是 `node`，模組一旦 import DOM 測試照樣爆，
> 那條紀律的牙齒沒掉。

這段本身是對的：`:105` 那條規則沒被破，也真的不必改。但 `:206`／`:208`／`:227` 是另外三條
規則，`01` 從頭到尾沒提到——**是看漏，不是刻意留下**。

（`CONTEXT.md` 不受影響：只有〈必填格〉與〈讀音編輯器〉兩條寫了「不碰畫面，因此可以獨立
測試」，那是在講模組，兩句都還成立。）

## 要決定的事

這張票掛 `needs-triage` 而不是 `ready-for-agent`，因為方向與措辭都還沒拍板。

### 一、翻案的形狀：窄例外，還是重寫那條規則？

- **窄例外**：`:206` 那條留著當通則，補一句唯一例外（`editor-view.ts` 的落點分類，理由是
  `relatedTarget` 翻不成序號、而它擋的是使用者看得到的行為）。好處是門檻仍然很高，下一個
  想寫畫面測試的人得先證明自己也在那個例外裡。
- **重寫**：把規則從「畫面不寫」改成一條可判斷的界線（例如「只有純 DOM 事件分類才准開
  jsdom，不准斷言 DOM 結構」）。好處是規則本身說得出准與不准，不必靠例外清單長大。

`01` 的「這張票不做的事」已經替第二種寫好一半材料——不測 Tab、不測 DOM 結構、不測
`cancelling` 與 `isComposing`，那幾條就是界線的內容。

### 二、`:227` 的 Out of Scope 怎麼收尾

它現在是光禿禿一行「畫面層級（瀏覽器）自動化測試」。翻案之後這一行是刪掉、還是改成
「除了 X 以外」，取決於第一題選哪個。

### 三、要不要開 ADR

`required-fields` 那次的判準是「決定沒變，只有描述實作位置的句子過期了 → 不開 ADR」。
這次相反：**決定本身被翻了**（原本明文否決的東西現在做了），照那個判準應該開一張。
但也可以認為它小到只值 spec 裡的一段話。待定。

## 不做的事

- **不改 `docs/spec.md:105`。** 理由同 `01`：那條管的是模組不得 import DOM，預設環境仍是
  `node`，牙齒沒掉。
- **不動 `CONTEXT.md`。** 見上，兩處「可以獨立測試」講的都是模組，沒有過期。
- **不改任何 code。** 這張票純文件。
- **不追加測試。** `01` 劃掉的那幾條（`cancelling`、`isComposing`、Tab、DOM 結構）維持劃掉。

## 驗收

- 只讀 `docs/` 的人不會讀到一條與 repo 現況相反的規則。
- `docs/spec.md` 的測試那一節說得出「`editor-view.test.ts` 為什麼准，下一個檔案憑什麼不准」。
- `npm test` 與 `npm run typecheck` 不受影響（純文件改動）。
