# 文件跟上必填格：詞彙、spec 的第五個模組、ADR-0006 的過期敘述

Status: ready-for-agent
Type: enhancement
Blocked by: 01

## 需求

`01` 把必填規則從三個檔案收進一個新模組「必填格」。**規則本身一條都沒變**，變的是它住在哪。三份文件因此有敘述過期或缺漏，這張票補齊。

不開新 ADR——ADR-0006 與 ADR-0009 的決定（輪詢順序、避讓退讓、儲存順序、讀音必填）一個字都沒動，只有描述實作位置的句子過期了。

## 決定

### 一、`CONTEXT.md`：新增〈必填格〉

放在〈讀音格〉之後、〈讀音預填〉之前——它與讀音格同一個家族，讀者先認識格子再認識「哪些格非填不可」。

```
**必填格**：
編輯畫面上非填不可的那幾格：詞條、每一個讀音格、釋義。三種格共用同一句
「還空著」的定義（去除頭尾空白後沒有字），換欄鍵要把游標送去哪、按下儲存
時先擋哪一格，都由它回答。不碰畫面，因此可以獨立測試。
_Avoid_: 驗證器、必填欄位（太泛）、輪詢器（把手段寫進名字）
```

### 二、`CONTEXT.md`：微調〈讀音編輯器〉

現有那條寫「決定什麼時候該重建格子、什麼時候該去讀音預填、預填回來的東西收不收」——這幾件事都還成立，不動。要動的是它不再管必填：`commit()` 現在只做假名檢查與組出讀音標記，「哪一格還空著」歸必填格。在該條目裡補一句交代，並用 `[[必填格]]` 的方式指過去（沿用現有條目互相提及的寫法）。

### 三、`docs/spec.md`：〈模組與接縫〉一節（約 L90-104）

- **L92**「建立四個模組，各自對應一個測試接縫。前三個性質相同，第四個不同，分開說。」→ 改成五個模組，並把「第四個不同」改成「後兩個不同」。
- **「某個畫面的大腦」那一組**（現在只有讀音編輯器）新增一條：

  > **必填格**：編輯畫面上非填不可的那幾格——詞條、每一個讀音格、釋義。對外提供兩項操作：「從這一格出發，換欄鍵該往哪去」與「按下儲存時，第一個該擋的是哪一格」。兩者共用同一句「還空著」的定義（去除頭尾空白後沒有字），但走不同順序——換欄照畫面的由上而下，儲存把讀音排在最後（ADR-0006／0009）。AI 預填期間的避讓與退讓也收在此模組內。**各格目前的內容以函式注入**，模組本身不持有任何值。
- **L104**「第四個模組與前三個的差別在於**它只搬走判斷，不搬走畫面**……」→ 主詞改成後兩個模組。那整段講的界線（模組不得 import 任何 DOM、文案與樣式留在畫面那側）對必填格一字不改地成立，只是措辭要涵蓋兩個。

### 四、`docs/spec.md`：測試那一節（約 L190-206）

- **L190**「四個接縫各自對應一組測試」→ 五個。
- 新增必填格的測試段落，內容對齊 `01` 的驗收清單：輪詢三態（送過去／不跳也不送出／放行）、到底繞回頭、避讓與退讓（含「釋義已有值時退讓進讀音格」那條）、trim 判空（單一空白視為空）、儲存順序是詞條→釋義→讀音。
- **讀音編輯器那條的結尾**「以及貼上帶標記字串會攤回讀音格，與儲存時的空白與驗證結果」→ 「空白」那半移到必填格那條，讀音編輯器只留假名驗證與組出標記字串。
- **L206**「目前屬於這一類的有讀音編輯器、卡片列表的時間桶分組、統計數字的計算，以及單字本開關收合後那行標籤」→ 清單加上必填格。

### 五、`docs/adr/0006-focus-first-empty-field.md`：訂正結尾那段

現在寫著：

> 拿掉這整套只需刪掉 `blur` 與 `keydown` 裡那兩段判斷。真正被鎖住的是「離開的那一格必須有值」與「焦點落到其他輸入框或讀音區就不跳」兩條——它們不是偏好，是不加就會壞掉的前提，日後改寫這段邏輯時不能省。

第一句過期了：判斷已經不在 `blur` 與 `keydown` 裡。改成交代現在要動哪裡（必填格模組，加上畫面兩處的呼叫），並補一句兩條前提現在分住兩邊——前提一在模組裡（它是判空，跟儲存那條共用同一句），前提二仍在畫面（它讀 `relatedTarget`，只有畫面看得到）。**兩條前提「不加就會壞掉」的地位不變**，那句話要留著。

## 不做的事

- **不開新 ADR。** ADR-0006 與 0009 的決定沒有任何改變。
- **不改 ADR-0009。** 它通篇講的是「讀音由選填改必填」與其代價，一句都沒過期。
- **不改任何規則的敘述。** 這張票只更新「規則住在哪」與「怎麼測」，行為描述一字不動。

## 驗收

- `CONTEXT.md` 讀得出「必填格」是什麼、與「讀音格」「讀音編輯器」的關係。
- `docs/spec.md` 的模組數量、測試接縫數量、`src/ui/` 底下可測純邏輯的清單三處數字與內容一致，沒有一處還停在四個。
- ADR-0006 結尾照著做真的能拿掉這整套——描述的檔案與位置與 `01` 落地後的程式相符。
- 搜 `docs/` 與 `CONTEXT.md`，沒有任何一處在描述 `01` 刪掉的東西（`firstEmptyReading`、`Commit` 的 `empty-term` 與 `empty-reading`）。`.scratch/` 底下的舊票不在此列——那是決策紀錄，照慣例保留原樣。
