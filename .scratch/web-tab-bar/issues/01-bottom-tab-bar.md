# 01: 網頁版改成底部導覽列，比照手機版

Status: ready-for-agent
Type: enhancement

## 為什麼有這張票

網頁版現在沒有導覽列。六個頂層畫面（複習、拼字、問答、卡片、資料、統計）靠標題列左右兩顆鈕串成一條線，每接進一個新畫面，就要改四支檔案的標題列（`review-view.ts`、`spelling-bar.ts`、`quiz-bar.ts`、`list-view.ts`）。

問答接進來之後，這條線撐不住了。問答票 `quiz/02` 在 375px 寬量過複習標題列：三顆鈕排不下，中文換成兩行、日文換成三行（數字記在那張票的 Comments）。票上寫明「換行就停下來回報，不要自己改版面規則」，維護者看完決定：**網頁版比照手機版，改成底部導覽列**。

手機版早就是這樣做的（`rn-rewrite/09`），四個 tab：複習、卡片、資料、統計。

## 維護者已經定的事（2026-09-18）

1. **四格，與手機版一模一樣**：複習、卡片、資料、統計。
2. **拼字與問答不進導覽列，收進複習畫面裡**，從複習畫面進去。入口是分段切換，見決定 5。
3. **每格是圖示加一個詞**，與手機版同一種排法。圖示自己畫（內嵌 SVG），樣子盡量模仿手機版那四個 SF Symbols：複習 `graduationcap.fill`、卡片 `rectangle.stack.fill`、資料 `gearshape.fill`、統計 `chart.bar.fill`。**實作時先端幾種給維護者目測挑**，不直接定。
4. **編輯卡片那一頁照樣顯示導覽列**，隨時跳得走。已知代價：跳走時正在打的字直接丟掉——網頁版的編輯頁沒有草稿。

當時端出來的選項與業界慣例：Apple HIG 與 Material Design 都建議底部導覽放 3 到 5 格。「六格全放」超過上限、「五格（統計留在資料裡）」與手機版不一致，維護者選了與手機版一致的四格。

## 看完原型之後定的事（2026-09-22）

原型在分支 `prototype/web-tab-bar`（commit `3532a75`，不進 main）。疊在真的 app 上，網址參數 `?entry=A|B|C&shape=A|B&icons=A|B|C` 三軸切換。

5. **入口：分段切換。** 複習、拼字、問答三個畫面的標題列正下方各有一排「複習｜拼字｜問答」，目前那一段亮著，點別段直接換過去。同一排也是拼字與問答回複習的路，因此拼字、問答標題列左邊不放返回鈕。
   - 落選的兩個：標題列右上角一顆「練習 ▾」選單（進去後左上「‹ 複習」返回）；今日份完成那一頁底下兩顆鈕（還沒複習完就進不去）。
6. **形狀：浮著的膠囊**，左右內縮、圓角到底，目前那一格墊一塊淡色底——與手機版 iOS 26 的樣子一致。落選的是整寬貼底加上緣分隔線。
7. **圖示：平常線條、選中變實心**，選中那格同時換成強調色。落選的是全部實心（手機版現在的樣子）與全部線條。手機版要改成同一套，另開票 `ios-app/23`。
8. **ADR 要開一份**，記「網頁版導覽從一條線換成底部四格，拼字與問答收進複習」。
9. **拼字與問答標題列中間那兩個字（「拼字」「問答」）這張不動。** 維護者要把它換成單字本膠囊、連帶拿掉挑書頁與「換單字本」，那是另一件事，開在 `web-tab-bar/02`，接在這張後面做。

## 要做什麼

### 導覽列本身

- 四格：複習、卡片、資料、統計。字查 `nav.*`，三份翻譯檔本來就有，不必新增。
- 目前在哪一格要看得出來。**標記走 `aria-current="page"`**，樣式照它上色——與拼字答題頁 `.slot[aria-current]` 同一個做法，測試因此不必斷言 class 名（`ADR-0014`）。
- **拼字、問答兩個畫面亮「複習」那一格**，因為它們是從複習進去的。編輯頁亮「卡片」。
- 形狀是浮著的膠囊，圖示平常線條、選中實心（決定 6、7）。

### 分段切換

- 複習、拼字、問答三個畫面，標題列正下方一排三段：複習｜拼字｜問答。字查 `nav.*`。
- 目前那一段同樣走 `aria-current`，測試不斷言 class 名。
- 三個畫面的**每一頁**都有：複習的零本版本；拼字與問答的挑書、答題、成績、零本、出不了題那幾頁。
- 答題途中點別段跳走，那一輪照舊封存，回來看到成績頁——與按導覽列跳走同一條規則。

### 標題列上的導覽鈕全部拿掉

導覽列接手之後，標題列上「往隔壁畫面」的鈕就沒有用了：

| 畫面 | 拿掉 |
| --- | --- |
| 複習 | 右邊的「拼字」「問答」「卡片」（拼字與問答改走分段切換） |
| 拼字 | 左邊「複習」、右邊「問答」（`spelling-bar.ts`） |
| 問答 | 左邊「拼字」、右邊「卡片」（`quiz-bar.ts`） |
| 卡片 | 左邊「問答」、右邊的「資料」（「新增」留著） |
| 資料 | 左邊「卡片」、右邊「統計」 |
| 統計 | 左邊「資料」 |

**畫面自己的東西留著**：複習的剩餘張數與單字本膠囊、卡片的「新增」、編輯頁的「取消」、拼字與問答答題頁的「結束」、拼字與問答中間的標題字（決定 9）。

### 連帶要改的

- **`app.ts` 的導覽**：導覽列掛在哪一層、畫面切換時怎麼知道要亮哪一格。
- **測試**：`src/app.test.ts` 的〈導覽〉整節、`src/i18n/smoke.test.ts` 的走法都是照標題列那幾顆鈕寫的，要改成按導覽列與分段切換。
- **橫著拿**：拼字票 `spelling-practice/08` 切兩欄的門檻（`max-height: 31rem`）是從「標題列 + 上半 + 磚」的高度反推的。底部多一條導覽列、頂上多一排分段切換，那條算式要重算。問答票 `quiz/05` 沿用同一條門檻，一起看。
- **底部留白**：`--screen-pad-bottom` 是實機量過定的固定值（`styles.css` 開頭的註解）。導覽列貼底之後這一段要重看，iPhone 的主畫面捷徑（standalone）要實機驗。
- **舊票的驗收**：問答票 `quiz/02` 的〈導覽〉一節、拼字票 `spelling-practice/06` 的標題列決定，這張做完之後就被取代。在那兩張票的 Comments 各留一行指過來。
- **ADR（Architecture Decision Record，架構決策紀錄）**：開一份（決定 8）。

## 驗收

- [ ] 每個頂層畫面底部都有四格導覽列：複習、卡片、資料、統計，每格一個圖示加一個詞。
- [ ] 目前在哪一格看得出來；拼字與問答亮的是「複習」。
- [ ] 導覽列是浮著的膠囊；圖示平常線條、選中那格實心。
- [ ] 編輯卡片那一頁也有導覽列。
- [ ] 標題列上往隔壁畫面的鈕全部拿掉，畫面自己的東西留著。
- [ ] 複習、拼字、問答每一頁的標題列下方都有分段切換，目前那一段看得出來，點了換得過去。
- [ ] 拼字與問答的「上一輪」照舊封存：答題途中按導覽列或分段切換跳走，回來看到成績頁。
- [ ] 375px 寬時標題列、分段切換與導覽列都不換行、不拆字，三種語言各量一次。
- [ ] 手機橫著拿時，拼字與問答切兩欄的門檻照新的高度重算過。
- [ ] 導覽與三語冒煙測試改成按導覽列與分段切換走，不斷言 class 名與版面（`ADR-0014`）。
