# 進拼字先挑單字本，選擇只記在這台裝置

Status: done
Type: enhancement

## 問題

拼字要出哪幾本的卡，得有人決定。三組現成的範圍（複習／列表／統計）都不能借用——借了就會發生「想在拼字單練一本，結果把今天要複習的範圍一起改掉」。

## 用詞

**一輪**照 `CONTEXT.md`：從挑單字本到跳出成績的這一段。

**不要叫「拼字範圍」。** 「範圍」在這個專案專指那三組跟著備份走的選擇（`BookScopes`），拼字挑的這幾本不是那個東西。畫面上的字用「單字本」。

## 決定

1. **拼字的首頁就是挑單字本那一頁。** 按下複習畫面的「拼字」進來，看到的是這頁，不是題目。

2. **用現成的 `bookFilter`**（`src/ui/book-filter.ts`），不另做一套。統計頁那顆 `block` 版是撐滿一列的樣子（`src/styles.css` 的 `.book-filter-toggle.block`），這裡照抄。

3. **選擇存在本機，不進 `AppData`。** 不動 `BookScopes`、不升資料版本號、不碰備份與雲端（`ADR-0021` 的 Considered Options 最後一條）。用 `localStorage` 另一把 key，與 `storage.ts` 那把分開。

4. **手機挑的與電腦挑的可以不一樣**，這是想要的行為，不是漏做。

5. **至少要挑一本才能開始。** 一本都沒挑時「開始」按不下去，比照三組範圍「都至少要有一本」的規矩。

6. **本機存的那組 id 可能指不到任何一本**（那本被刪了、或這是另一台裝置）。讀進來時先濾掉指不到的，濾完全空就當成沒挑過，回到預設。**不要當機、也不要靜默出一輪空題**。

7. **預設是全選。** 第一次進來、或存的那組全部失效時，把現有的每一本都勾起來——比「一本都沒勾、按鈕是暗的」好，使用者按一下就開始得了。

8. **挑到的每一本都拿不出卡時**（全是沒標讀音的卡，或本身就是空的），不開始，顯示與「這本是空的」同一個空畫面（spec 決定 17），並讓使用者回去改選。

9. **零本時**（整支 app 一本單字本都沒有）比照 `review-view.ts` 的 `noBooksView()`，指路去資料頁建立。

10. **成績頁的「換單字本」回到這一頁**（票 `05`）。

## 驗收

- 從複習畫面按「拼字」，第一眼看到的是挑單字本那一頁。
- 第一次進來時每一本都是勾起來的。
- 取消勾選到一本都不剩時，「開始」按不下去。
- 挑好按「開始」，出的題只來自挑到的那幾本。
- 離開拼字再回來，上次挑的那幾本仍然是勾著的。
- 在資料頁改複習範圍，回拼字，拼字這邊挑的那幾本不受影響；反過來也一樣。
- 匯出備份，檔案裡沒有拼字挑的那組 id。
- 手動把本機存的那組改成不存在的 id，再進拼字：不當機，退回全選。
- 挑到的單字本裡一張卡都拿得出來時才開始；全部拿不出來時顯示空畫面並讓人回去改選。
- 一本單字本都沒有時，指路去資料頁建立。
- `src/ui/spelling-books.test.ts`（或併進票 `03` 那支）涵蓋上述行為。
- 根目錄 `npm test` 與 `npx tsc --noEmit` 全過。

## Comments

實作時偏離了兩條決定，兩條都記在這裡而不是改決定本身。

**決定 8 的「空畫面」做成了頁內一句話，不是整頁換掉。** 那條同時要求「顯示空畫面」與「讓使用者回去改選」，兩件事互相拉扯——整頁換掉的話開關就不在了，得再長一顆「回去改選」的鈕。做法是把那一句話印在開關底下（借 `.error`，它的 `:empty` 規則本來就會把空的收起來，與 `editor-view.ts` 的驗證訊息同一種處理），開關與「開始」都留在原地。spec 決定 17 真正要的是「空的單字本」與「卡都沒標讀音」共用**同一句話**，那一條照做了，只有一句。

**決定 5 的「一本都沒挑時開始不了」目前走不到。** `bookFilter` 會把最後一本鎖住，勾不掉（`book-filter.ts` 的 `item()` 那個 `locked`），因此挑到零本這件事在畫面上發生不了。「開始」自己那道 `disabled` 還是寫了，當第二層。測試釘的是走得到的那一條：取消到只剩一本時那一顆勾不動，而「開始」照樣按得動。

另外四件實作時才知道的事：

- **標題沒放。** 原本在標題列放了一顆 `.bar-title` 寫「拼字」，實際跑起來偏在左邊——`.bar:has(.bar-title)` 是 `1fr auto 1fr` 的格線，中間那欄要靠左右兩欄等寬才落在正中間，而左右兩顆導覽鈕是票 `06` 的。標題因此一起留給票 `06`，這張票的標題列與 `spelling-view.ts` 一樣是空的。連帶：`nav.spelling` 這條 key 這張票沒有加，票 `06`／`07` 照原本的計畫加。
- **`App` 多了兩樣**：`random()` 與 `spellingBooks`。前者比照既有的 `now()`（`app.ts` 的 docblock 本來就寫著「當前時間與亂數在這裡才第一次接觸真實世界」，只是亂數一直沒開在介面上），一輪要靠它洗；後者比照 `gemini`。兩樣都不是導覽，與票 `06` 的 `showSpelling()` 不衝突。
- **一輪在這一頁開，`onStart(round)` 端出去**，與票 `03` 的 `onFinish` 同一種接法：這張票不碰 `app.ts` 的導覽，接線是票 `06` 的事。`spelling-view.ts` 的 docblock 本來就是這樣預期的。
- **不借 `cardsInBooks()`。** 它住在 `storage.ts`，而票 `03` 有一條守門測試釘住「拼字這條線一行都不 import 那支」。那個過濾只有一行，抄比破例划算；`spelling-books.test.ts` 也照抄了那道守門。

## 待人工確認

自動測試蓋不到的兩條：

- **最大字級下版面會不會爆。** 那一句提示與出不了題時的紅字都是整段中文，字級放到最大時會往下推「開始」；`.panel` 會捲，但沒有實機量過。
- **這一頁還走不到。** 複習畫面那顆「拼字」是票 `06`，因此驗收第一條（從複習畫面按「拼字」看到這一頁）要等那張票。這一輪是拿 `spelling-preview.html`（丟棄用，未進版控）點過的：挑書 → 開始 → 出題，以及挑到出不了題的那一本時的紅字。
