# 拼字橫著拿時改成左右兩欄：左邊題目，右邊磚

Status: needs-info
Type: enhancement

## 問題

拼字畫面是一直排：上半釋義與碼表，下半散落的磚。手機橫著拿的時候這個排法會把磚壓扁。

票 `03` 實機量過的數字：`375 × 667` 直握時場地有 379px 高，十二塊磚各 46px；轉成 `667 × 375` 之後場地只剩 112px 高，同樣十二塊磚縮到 24.5px。磚沒有跑出畫面外、也沒有重疊（票 `03` 決定 11 守住了），但小到一半，手指點起來很勉強。

橫螢幕缺的是高度，多的是寬度。左邊放釋義、碼表與填格，右邊放磚，磚就能維持原本的大小。這也是限時作答類的通用做法——橫向模式一律把題目與作答區左右分開，而不是繼續上下疊。

## 待決

**門檻怎麼定，維護者要實機轉一轉再說。** 兩個候選：

- **看高度**：上半固定的 13rem 加上標題列的 3rem 已經吃掉 16rem，剩下的高度不夠磚展開就切成兩欄。平板與電腦縮小視窗都吃得到，但門檻要實玩才知道訂在哪。
- **看方向**：`orientation: landscape` 就切。規則一句話講得完，但平板橫著拿其實高度夠，卻也會被切成兩欄，磚反而變小。

**定了之後這張票才是 `ready-for-agent`。** 底下的決定都不受這一條影響——它只決定「什麼時候換版面」，不決定「換成什麼樣子」。

## 用詞

**磚**、**一輪** 照 `CONTEXT.md`。「兩欄」只描述版面，不是新的領域概念，不進詞彙表。

## 決定

1. **版面切換走 CSS，程式不參與。** `.screen` 在橫向時改成 grid：標題列橫跨上方，底下左右各一半。用 `:has(> .kana-field)` 只挑到拼字這一頁——`.screen` 是五個畫面共用的 class，不加限定會把複習、卡片、資料、統計一起改掉。

2. **上半那塊在橫向時不再寫死 13rem。** 票 `03` 決定 9 那個固定高度是為了直握時三個假名與六個假名換題不上下抽動；橫向時它變成左欄，高度撐滿，抽動改由**左欄寬度固定**來擋。兩種版面各自守住同一件事，用的是不同的邊。

3. **格線的欄數列數要看場地的長寬比，不能只看磚數。** 現在 `buildTiles()` 寫的是 `Math.ceil(Math.sqrt(n))`，十二塊固定排成四欄三列。場地變成又高又窄之後那個形狀就錯了，該是三欄四列。

   **抽成一支純函式**：吃「幾塊磚、場地多寬、場地多高」，吐「幾欄幾列」。場地尺寸由呼叫端量了遞進來，函式自己不碰 DOM——jsdom 量不出版面（`ADR-0014`），這是唯一測得動的形狀。

4. **轉螢幕的當下要重排。** 掛 `matchMedia` 或 `resize` 監聽器，照 `ADR-0011` 的成對註冊，另加 `isConnected` 自癒——這一頁的碼表已經是這樣做的，抄它。**不要重開一輪**：轉個螢幕不該讓已經填好的格子消失，也不該讓碼表歸零。

5. **磚的大小仍然由 CSS 的 `min()` 夾住**，`--cols` 與 `--rows` 照舊由程式給。那條式子裡的 `1.5` 是跟著 `TILE_JITTER` 算出來的，不要動它（理由寫在 `styles.css` 那條規則的註解裡）。

6. **不動 `mobile/`。** 這一輪只做網頁版（spec 開頭）。iOS 版的橫向另外再說。

7. **標題列在橫向仍然佔 3rem。** 票 `06` 把兩顆導覽鈕填進去之後也一樣。橫向的高度本來就緊，這 3rem 值不值得要在實機上看——**先照現況做，不要順手拿掉**，那是票 `06` 的地盤。

## 驗收

- `667 × 375`（iPhone 橫握）下，左邊看得到釋義、碼表與填格，右邊是磚。
- 同一個尺寸下，十二塊磚不小於直握時的大小（直握 `375 × 667` 量到 46px）。
- 十二塊磚全部落在場地內、彼此不重疊；直握與橫握都要成立。
- 轉螢幕之後磚重新排過，不會留在轉之前的格線上。
- 轉螢幕不會弄丟已經填好的格子，碼表也不歸零。
- **直握的版面一個像素都沒變**：`375 × 667` 下仍是四欄三列、磚 46px、上半 208px。
- 複習、卡片、資料、統計四個畫面的版面沒有被改到。
- `mobile/` 底下一個字都沒改。
- 畫面被換掉之後那個監聽器不再作用（照 `ADR-0011`）。
- 算欄列的那支純函式有測試：同樣十二塊磚，寬場地吐四欄三列、窄高場地吐三欄四列。
- `src/ui/spelling-view.test.ts` 補上對應的行為。
- 根目錄 `npm test` 與 `npx tsc --noEmit` 全過。

## Comments

這張票是驗收票 `03` 時當場長出來的。維護者跑〈375px 下十二塊磚〉那一條時轉了一次螢幕，問「橫的時候有辦法把選擇格放右邊嗎」。

門檻那一條（決定看高度還是看方向）維護者選了「實機試過再決定」，因此這張票開成 `needs-info` 而不是 `ready-for-agent`。下一步是做一個轉得動的原型讓他在 iPhone 上試，試法見上一輪定下來的做法：電腦開熱點、`npm run dev -- --host`，手機連同一個網路。Windows 這邊看不到 Safari 的除錯器，量到的數字要印在畫面上。
