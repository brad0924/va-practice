# 導覽多一節：複習 → 拼字 → 卡片，另加一條複習直達卡片的捷徑

Status: done
Type: enhancement

## 問題

網頁版四個畫面是串成一條的：每個畫面的標題列只有左右各一顆按鈕，接到隔壁那一個。今天是 `複習 → 卡片 → 資料 → 統計`。拼字要當第五個，得決定掛在哪一節，而複習畫面的標題列已經有三樣東西了。

（iOS 版底下是四個原生 tab，`mobile/app/_layout.tsx`。**這一輪不動它。**）

## 用詞

導覽鈕上的字是**拼字**兩個字，不是「練習」。畫面標題也是。

## 決定

1. **順序變成 `複習 → 拼字 → 卡片 → 資料 → 統計`。**

2. **複習畫面的標題列同時放「拼字」與「卡片」兩顆**，並排在右側，用現成的 `.bar-side`（`src/ui/list-view.ts:20` 已經在用這個容器把兩顆鈕擺同一邊）。

3. **拼字畫面**：左邊返回「複習」，右邊往「卡片」。

4. **卡片畫面左上角的返回從「複習」改成「拼字」。** 因此從複習按「卡片」直接跳過去、再按返回時，會跑到一個剛剛沒經過的畫面——**這是已知並接受的代價**，維護者看過圖之後選的。

5. **標題列照現在的規矩硬塞，不改 `.bar-centered`。** `src/styles.css` 那條 `grid-template-columns: 1fr auto 1fr` 一行不動。

   後果算得出來：右欄要裝兩顆 `.bar-action`（各 `padding: 0 0.75rem`，兩個中文字），約 116px；左右欄 `1fr` 等寬，所以左邊也吃掉 116px。375px 螢幕扣掉 `.screen` 的左右 `0.75rem` 內距與兩道 `0.5rem` 間隙之後，**複習範圍膠囊從上限 144px 被壓到約 103px**。範圍名字長一點就只看得到開頭兩三個字加省略號。

   **維護者知情接受。** 換掉的是不必再與 `ADR-0010`「標題列中央放一顆開關」起第二次衝突——那條上個月才為了 iOS 動過一次。

6. **膠囊仍然按得到、仍然收得成一行。** `.book-filter-toggle.pill` 本來就有 `max-width` 與 `text-overflow: ellipsis`，被壓窄只是切得更短，不該換行、不該被擠出畫面外。最大字級下要實機確認。

7. **`app.ts` 加一支 `showSpelling()`**，比照現有的 `showReview()` / `showList()` / `showData()` / `showStats()`。

8. **`nav.spelling` 這條翻譯 key 由票 `07` 補齊三份。** 這張票只負責接線，不自己寫死中文字。

## 驗收

- 複習畫面標題列右側同時看得到「拼字」與「卡片」兩顆，兩顆都按得動、去對的地方。
- 複習畫面的複習範圍膠囊仍然按得開，名字太長時收成一行加省略號，不換行、不跑出畫面外。
- 拼字畫面左邊回複習、右邊去卡片。
- 拼字的三個畫面（挑單字本、答題、成績）標題列中央都印出「拼字」兩個字，落在正中間。
- 卡片畫面左上角的返回指向拼字。
- 資料與統計兩個畫面的按鈕一個字都沒動。
- 375px 寬度下，複習標題列的四樣東西都在畫面內，沒有任何一個被截斷到按不到。
- 最大字級（瀏覽器字級放到最大）下，複習標題列換行而不是溢出。
- `mobile/` 底下一個字都沒改。
- `src/ui/review-view.test.ts` 之類的既有測試沒有紅燈；新的導覽路徑有測試涵蓋。
- 根目錄 `npm test` 與 `npx tsc --noEmit` 全過。

## Comments

驗收倒數第二條（最大字級下換行而不溢出）需要在真機或縮小視窗實測，自動測試蓋不到。做完這張票時記得提醒維護者確認，別讓它沉底。

驗收第三條（兩個畫面的標題）是票 `04` 實作時長出來的，原本七張票都沒有人認領它。spec 決定 19 寫著「導覽鈕、畫面標題、詞彙表條目都用『拼字』這兩個字」，但票 `03` 與票 `04` 的標題列都是空的——`.bar-title` 靠 `grid-template-columns: 1fr auto 1fr` 的左右兩欄等寬才落在正中間，而那兩顆鈕是這張票的，單獨掛標題會偏到左邊那一格。兩顆鈕接上之後標題自然就正了，因此併進這張票。

`nav.spelling` 這條 key 也還沒有人加過（票 `04` 一度加了又拿掉，因為那張票用不到）——照決定 8，它跟這條標題一起在這裡第一次被用到。

票 `05` 做完之後，決定 7 的內容變得更小也更明確：**`showSpelling()` 裡只要呼叫 `spellingHome(app)`**（`src/ui/spelling-home.ts`），不要自己判斷該給哪一頁。「有上一輪就給成績頁、沒有就給挑書頁」那條規則與拼字三頁之間的換頁都已經寫在那一支裡，形狀比照現有的 `showReview()` / `showList()`。

連帶多一條驗收，是票 `05` 驗不了而落到這裡的：**練到一半按右上角「卡片」跳走，再按「拼字」回來，看得到剛才那一輪的成績；按「換單字本」才回到挑書頁。** 規則本身有 `src/ui/spelling-home.test.ts` 釘住，但那顆鈕不存在，整條路這一輪走不到。

### 實作後補記

三件票上沒寫、實作時決定的：

1. **拼字三頁的標題列抽成 `src/ui/spelling-bar.ts`**，四個地方共用（挑書、答題、成績，加上挑書的零本版本）。其他四個畫面各自拼自己的標題列，那是因為它們本來就長得不一樣；拼字這四處要的是同一條。

2. **零本狀態下複習畫面右側仍然放「拼字」**，兩個狀態長一樣。端給維護者選過。反面的選法是零本時只留「卡片」，代價是拼字自己的零本畫面從此走不到。

3. **`nav.spelling` 三份翻譯在這張票補齊**，決定 8 照字面做不到：接上 `t('nav.spelling')` 之後，`en.ts` 與 `ja.ts` 的 `const en: typeof zhHant` 會逼著三份一起補，少一條就編譯錯。與票 `04`、`05` 的先例一致。票 `07` 的 Comments 已同步改掉，免得下一個人去補一條已經在的 key。

### 決定 5 的算式對，前提錯了

實機驗 375px 時發現：被壓窄的不是膠囊，是**兩顆導覽鈕**——兩個中文字被拆成上下兩行，標題列被撐高。

決定 5 算的「右欄 116px、左欄跟著 116px、膠囊退到 103px」沒有錯，錯在它假設那兩顆鈕守得住 116px。守不住：`.bar-action` 當時沒有 `white-space: nowrap`，而旁邊的 `.book-filter-toggle.pill` 有。三欄搶不到位子時，瀏覽器挑不會抗議的那個下手，於是壓的是鈕不是膠囊。

補了兩條 CSS（`src/styles.css` 的 `.bar-action` 與 `.bar-side`），決定 5 凍結的那一行 `grid-template-columns: 1fr auto 1fr` 仍然沒動：

- `.bar-action` 加 `white-space: nowrap` —— 鈕不再拆字，擠壓轉回膠囊，決定 5 的算式這才成立。
- `.bar-side` 加 `flex-wrap: wrap` 與 `justify-content: flex-end` —— 只在最大字級時才看得出來：兩顆鈕整顆上下疊、標題列變高，而不是推出畫面右邊。少了這一條，驗收 8 會被上一條直接撞爛（鈕既不能拆字也不能疊，只剩溢出一條路）。

**這條 CSS 兩個畫面共用**：卡片畫面的「資料」＋「新增」也走 `.bar-side`，一起受惠。

**還沒驗的兩條**（自動測試蓋不到，要實機或縮小視窗）：375px 寬度下複習標題列四樣東西都在畫面內、最大字級下換行而不溢出。
