# 成績畫面：三格數字加逐格對照

Status: done
Type: enhancement

## 問題

拼字不動排程（`ADR-0021`），所以一輪練完之後，**成績是這個玩法唯一留下來的東西**。它得回答一件事：我哪幾個字沒記熟，錯在哪一格。

## 用詞

**計分**、**一輪**照 `CONTEXT.md`。不要寫「分數」「評分」——後者是複習那邊的四級自評。

## 決定

1. **一輪什麼時候結束**（spec 決定 11、12）：挑到的每一張卡都出過一次就強制結算；中途按「結束」也結算；**直接跳去別的畫面，那一輪照樣封存**，下次回拼字首頁看得到。三條都要做。

2. **頂上三格並排**，每格一個數字加一個標籤：

   | 格 | 數字 | 標籤 |
   | --- | --- | --- |
   | 左 | `9 / 12` | 拼對 |
   | 中 | `76` | 總分 |
   | 右 | `6.3` | 平均 |

   **平均是總分除以全部題數**（76 ÷ 12 = 6.3），不是除以拼對的題數。維護者當面選定。

   三個數字各自帶標籤，是為了不必猜「6.3」是分還是秒。

3. **主體是逐格對照。** 每一張沒拼對的卡一塊，塊裡三行：釋義、「你拼的」那一排格子、「正解」那一排格子。兩排上下對齊。

4. **錯的那一格標紅（`var(--again)`），對應的正解標綠（`var(--good)`）**，其餘格子中性。挑這個排法就是要讓濁音干擾看得出來——「我把 `が` 拼成 `か`」要一眼就到。

5. **逾時沒拼完的用虛線空格**，不要留空白或補問號。使用者看得出自己拼到哪裡就停了。

6. **拼對的卡不列出來。** 這一頁只講沒拼對的。

7. **一張都沒拼錯時**，主體換成一句話，不要留一塊空白。

8. **底下兩顆鈕**：「再一輪」用同一批單字本重來，「換單字本」回票 `04` 那一頁。第二顆是可以拿掉的——左上角的返回鍵本來就回得去；維護者未表示要拿掉，先留著。

9. **成績不落地**（spec 決定 26）。不存進 `AppData`、不進備份，重整頁面就沒了。「上一輪」只活在記憶體裡。

10. **錯題多的時候整塊要捲**，不要壓縮格子。一張錯題的高度是固定的，錯十張就是捲。

11. **數字一律 `font-variant-numeric: tabular-nums`。**

## 驗收

- 挑到的每一張卡都出過一次之後自動跳出成績。
- 中途按「結束」跳出成績。
- 中途直接跳去卡片畫面，再回拼字首頁，看得到剛才那一輪的成績。
- 頂上三格分別是拼對題數、總分、平均分，每格都有標籤。
- 平均分等於總分除以全部題數（12 題拿 76 分顯示 6.3，不是 8.4）。
- 每一張沒拼對的卡都列出來，「你拼的」與「正解」上下對齊。
- 拼錯的那一格是紅的，對應的正解是綠的。
- 逾時沒拼完的卡，沒填到的位置是虛線空格。
- 拼對的卡不出現在清單上。
- 一張都沒拼錯時，主體是一句話而不是空白。
- 按「再一輪」用同一批單字本重新開始，不會回到挑書那頁。
- 按「換單字本」回到挑書那頁，上次挑的仍然勾著。
- 重整頁面之後，成績消失。
- 錯十張時整塊可以捲，格子不被壓扁。
- `src/ui/spelling-summary.test.ts`（或併進票 `03` 那支）涵蓋上述行為。
- 根目錄 `npm test` 與 `npx tsc --noEmit` 全過。

## Comments

實作前有三件票上沒寫死的事，端了原型（一頁並排的手機框）給維護者當場選：

- **「結束」放釋義那一塊的右下角。** 另外兩個選項是「磚那一片底下加一列」與「佔用標題列中央」。前者會吃掉磚的高度，後者要回頭改票 `06` 的決定 2。選中的這個浮在上半部、不佔一行，與右上角的碼表、左上角的所屬單字本同一種手法。375px 下量過：收尾那行字右緣在 x=230，「結束」左緣在 x=304，中間空 74px，撞不到；英文那句更長也還差得遠。
- **中途跳走再回拼字時直接落在成績頁**，按「換單字本」才回挑書頁。另外兩個選項是「挑書頁多一條入口」與「挑書頁頂上直接印三格」，兩者都要在挑書頁上多擺一塊跟挑書無關的東西。
- **複習畫面那顆「拼字」鈕仍然留給票 `06`。** 這張票只寫「進拼字該看哪一頁」那條規則，不碰標題列。**因此驗收第三條的後半（真的從卡片畫面按鈕走回來）這一輪走不到**，規則本身則有 `spelling-home.test.ts` 釘住。

票上沒寫死、由實作決定的三處：

**決定 1 沒說按「結束」時正在拼的那一題算不算，做成了不算。** `summary()` 的算法本來就只數已經結算過的（spec 決定 23，「還沒出到的那幾題不列入——它們沒被拼錯，只是沒發生」），正在拼到一半的那一題是同一種情況。補判一次的話，中途收工的平均分會被一題硬生生的 0 分拉下來。

**決定 8 沒說按「換單字本」之後上一輪還留不留，做成了放掉。** 留著的話，從挑書頁再跳去別的畫面、回來又會彈回那份成績——使用者剛剛才明白地離開它。這一顆因此是離開成績頁的門，不是繞一圈回來的路。

**決定 4 的「其餘格子中性」涵蓋逾時沒填到的位置。** 第一版把那幾格的正解標成綠的，理由是「沒填到也是這個字沒記熟」，那是票上沒有的規則，而且與答題畫面收尾時的 `.slot.done.missed`（票 `03`，註解寫著「那不是『你答錯了』，是『你還沒填到』」）講反了。已改回中性，兩個畫面現在說同一句話。

另外五件實作時才知道的事：

- **答題畫面得每結算一題就把進度往外報一次。** 決定 1 第三條「跳去別的畫面那一輪照樣封存」第一版沒做到：只有整輪結束才封存，練到第七題跳去卡片畫面等於全部白練。畫面被 `root.replaceChildren()` 丟掉時沒有人通知它，所以進度不能等到最後才交。`spellingView` 的第三個參數因此拆成兩支——`onSettled`（每題一次）與 `onDone`（收工一次），兩支收的是同一種東西，差別只有「還剩幾題沒出」。不用一個布林旗標，是因為那會變成呼叫端每次都要解讀的暗號。

- **多了一支 `src/ui/spelling-home.ts`。** 三頁之間換頁不經過 `app.ts`：拼字是一座小島，島內三頁互相認得，島外只有一道門。換頁的手法是把自己那一棵 `.screen` 原地換掉（`replaceWith`），因此不必多包一層容器，每一頁仍然是 `#app` 的直接子節點，`.screen` 那條 `height: 100%` 照樣算得出高度。票 `06` 的 `showSpelling()` 只要呼叫這一支。
- **`App` 多了一格 `spellingRound`。** 畫面被 `root.replaceChildren()` 丟掉時沒有人通知它，而「跳走也封存」要求那一輪活得比畫面久。比照票 `04` 加 `random()` 與 `spellingBooks` 的做法，寫成可變欄位而不是一對 getter 加方法——它就是一格，沒有伴隨的副作用要守，與 `keyHandler` 同一種形狀。
- **「拼錯那一格是紅的」測不了顏色，改測規則。** `ADR-0014` 明文不准斷言 class 名，而這又是要有驗收的一條。上色那條規則抽成 `toneOf()`（純函式，離開 DOM 照樣成立），斷言得下去；顏色本身留給眼睛。同一招票 `03` 用 `aria-current` 解過類似的問題。
- **「再一輪」重新讀一次挑到的那幾本，不是把上一輪的卡再洗一次。** 中途去卡片頁改過的東西，下一輪就吃得到。那段過濾與 `spellingBooksView` 的「開始」共用同一支 `openRound()`——各抄一份的話，改了出題資格只有一邊會跟著動。

已知的小缺口：**「再一輪」時那幾本剛好一張卡都拿不出來，會靜靜退回挑書頁**，不印那句「出不了題」的紅字——那句話的開關在 `spellingBooksView` 自己的閉包裡，只有它自己的「開始」按得到。人落在挑書頁上按一次「開始」就看得到理由，多一次點擊。要收掉的話得讓 `spellingBooksView` 多收一個參數，這一輪判斷不划算。

## 待人工確認

自動測試蓋不到、要真的縮視窗或拿手機看的兩條：

- **最大字級下（瀏覽器字級放到最大）成績頁會不會爆。** 三格數字、逐格對照的兩排格子、底下兩顆鈕都跟著 `rem` 走，字級放大時一起長；`.panel` 會捲，但沒有實機量過。與票 `03`、`04` 留下的同一條並在一起看。
- **驗收第三條的後半（真的從卡片畫面按鈕走回拼字）**。要等票 `06` 把那顆「拼字」鈕接上。規則本身有 `spelling-home.test.ts` 釘住（拼完一題直接把整棵樹丟掉，再進來一次，成績還在），但真的用手按過去這一輪還沒發生。

其餘版面條件已用真瀏覽器在 375px 下量過：十二張錯題全部不溢出、每一張的「你拼的」與「正解」兩排右緣像素相同（對齊）、頁面不會橫向捲。十個假名的長詞（`ありがとうございます`）格子會縮到 22px 而不是撐出去。

## 驗收之後修的

手動驗收（2026-09-08）撞出兩件事，自動測試一件都蓋不到。

**成績頁的 `.missed` 與答題畫面的 `.slot.done.missed` 撞名。** 逐格對照那一塊本來叫 `.missed`，而答題畫面「逾時沒填到」的格子身上也掛著 `missed` 這個 class——`.missed` 這條選擇器把兩個都選中了，於是那些格子被灌進 `padding: 0.7rem 0.8rem` 與 `border-radius: 0.9rem`，字被往下推、下緣溢出 2.1px，貼在框線上。**只有那幾格會被看到**，因為它們是唯一有底色的，字歪掉才顯得出來。已改名成 `.missed-card`，量過修正後上下各 5.3px。

這一類撞名 jsdom 抓不到（`ADR-0014` 明文不斷言版面，jsdom 也不算樣式），只有真瀏覽器看得出來。同一次順手掃過這次新加的其他 class（`.missed-list`、`.missed-meaning`、`.missed-label`、`.missed-none`、`.slots.compact`、`.slot.done.wrong/right/plain`、`.end-round`），沒有第二處撞到。

**干擾磚會出現廢棄假名 `ゑ`。** 那不是這張票的東西，是票 `02` 挑干擾那一段；已另開票 `09`。維護者當時回報的是「`る` 的顯示怪怪的」，實際上看到的字是 `ゑ`。
