# 拼字畫面：上半釋義與碼表，下半散落的磚

Status: done
Type: enhancement

## 問題

票 `01` 與 `02` 把「這一題是什麼、點下去會怎樣、拿幾分」都算好了，但那支模組不碰畫面。這張票畫出使用者真正會摸到的東西。

## 用詞

**磚**、**一輪**、**計分**照 `CONTEXT.md`。畫面上不要出現「選項」「題目」「分數」。

## 決定

1. **新開 `src/ui/spelling-view.ts`**，照 `review-view.ts` 的形狀：一個 `screen`，裡面 `header` / `main` / `footer`，狀態變化走一支 `refresh()`，不整頁重建。

2. **上半部**：正中間是釋義，字級比照複習畫面的 `.term`。左上角印這張卡的**所屬單字本**，沿用 `review-view.ts` 的 `bookLabel()` 那一套（絕對定位、不佔一行、不可點、螢幕閱讀器唸「單字本：XXX」）。右上角是碼表。

3. **碼表是一圈會縮的環加上數字**，數字用 `font-variant-numeric: tabular-nums`，跳動時不會左右位移。剩 5 秒轉黃（`var(--soon)`）、剩 3 秒轉紅（`var(--again)`）。

4. **填格排在釋義底下**，正解幾個假名就幾格。空格虛線、填好的實線，**下一塊磚會補進去的那一格要看得出來**——只取消中間一格時，畫面上必須指得出「下一塊補去哪」，否則使用者不知道自己在填哪裡（spec 決定 4 的直接後果）。

5. **下半部是磚，絕對定位散著擺、不對齊。** 位置由 `random` 決定，但**不得重疊**：先鋪一張看不見的格線，再在每一格內做小幅隨機偏移。純亂數會疊在一起，那是原型踩過的。

6. **點磚 → 走 `place()`；點已填好的格子 → 走 `clearSlot()`。** 畫面自己不算對錯、不算分，一律問票 `01` 那支模組。

7. **碼表在第一題出現的那一刻就開始跑**，不等使用者動作。這一版沒有「準備好了嗎」的過場。

8. **逾時、拼錯、拼對三種收尾都停住碼表，把正解翻出來，短暫停留後進下一題。** 停留幾秒是個具名常數。

9. **`main` 的高度固定，不隨假名多寡跳動。** 三個假名跟六個假名的題目輪流出現時，畫面不該上下抽動。

10. **不做鍵盤操作**（spec 決定 25）。`app.keyHandler` 在這個畫面設成 `null`，不要留半套。

11. **磚在手機寬度下不得溢出。** 十二塊磚（六個假名的長詞）在 375px 下要排得進去；排不進去就縮磚，不要讓磚跑出畫面外——那是 `mobile/ui/review-screen.tsx` 的膠囊真機踩過的坑（2026-08-26）。

12. **`touch-action` 與 `-webkit-tap-highlight-color` 沿用全站設定**，不在這個畫面另外處理。磚是 `<button>`，本來就吃得到 `src/styles.css` 那幾條。

13. **這個畫面只讀 `app.data.cards`，不寫任何東西**（`ADR-0021`）。不呼叫 `app.applyData()`、不碰 `storage.ts`。

## 驗收

- 畫面上半只看得到釋義，詞條與讀音都不出現。
- 左上角印出這張卡的所屬單字本；找不到那本就不印，也不填佔位字元。
- 碼表在題目出現時就開始跑，剩 5 秒轉黃、剩 3 秒轉紅，數字跳動時不左右位移。
- 三個假名的題目給 9 秒，六個給 18 秒。
- 點一塊磚，它補到最前面的空格，那塊磚變成不可點。
- 連點三塊錯的磚，前兩下畫面上不出現任何對錯提示。
- 點已填好的中間那一格，只有那一格變空，前後兩格不動；畫面上看得出下一塊磚會補進那個洞。
- 拼完最後一格才判定；拼錯與逾時都翻出正解再進下一題。
- 三個假名與六個假名的題目交替出現時，畫面不上下抽動。
- 375px 寬度下，十二塊磚全部在畫面內，彼此不重疊。
- 鍵盤按任何鍵都沒有反應。
- 整個畫面的程式沒有 import `storage.ts`，也沒有呼叫 `applyData()`。
- `src/ui/spelling-view.test.ts` 涵蓋上述行為（jsdom，照 `ADR-0014`）。
- 根目錄 `npm test` 與 `npx tsc --noEmit` 全過。

## Comments

實作時偏離了兩條決定，兩條都記在這裡而不是改決定本身。

**決定 2 的「字級比照複習畫面的 `.term`」沒有照做。** `.term` 是 `clamp(2rem, 11vw, 3rem)`，而它裝的是一兩個漢字；釋義是中文句子，同樣的字級三行就把決定 9 那個固定高度擠爆。實作用的是 `clamp(1.25rem, 6vw, 1.75rem)`，長釋義自己捲。兩條決定衝突時選了決定 9，因為它有可觀測的驗收條件（畫面不上下抽動）。

**決定 5 的「位置由 `random` 決定」換了一條路。** 這張票不吃 `random`——一輪是挑單字本那頁洗好端進來的，畫面這層拿不到亂數源。格內偏移量改由「那一格裝了哪個假名」算出來，而哪個假名落在哪一格是 `startRound()` 用注入的亂數洗出來的，因此位置照樣是亂數決定的。順帶換到一個好處：同一題重畫幾次磚都待在原地，點一塊磚整片不會跳。

另外三件實作時才知道的事：

- 借 `bookLabel()` 不能從 `review-view.ts` 借。那支為了改複習範圍 import 了 `storage.ts`，借過去會讓「拼字一行都不碰 storage」只剩字面上成立，票 06 接上導覽之後還會變成兩支互相 import。已抽成 `src/ui/book-label.ts`，兩個畫面各自 import；`spelling-view.test.ts` 有一條守門擋這件事重演。
- 「下一塊磚補去哪一格」的標記走 `aria-current` 而不是一個 class。`ADR-0014` 明文不准斷言 class 名，而這條又是要有測試的驗收；`aria-current` 是那一格的語意不是長相，斷言得下去，螢幕閱讀器也順便唸得出來。
- 磚不能用 `aspect-ratio: 1` 當正方形。裡面那個假名會把高度撐開（矮螢幕上量到 24.5 × 33.8），而格內偏移的縱向百分比對照的正是高度，偏移量因此比算好的大四成，上下兩排會疊在一起。寬高都明寫成同一個 `--tile` 才守得住。

## 待人工確認

自動測試蓋不到、需要真機或縮視窗才驗得了的只剩一條：**最大字級下（瀏覽器字級放到最大）版面會不會爆**。磚與填格的大小都跟著 `rem` 走，字級放大時兩者一起長，但上半部是固定的 13rem，釋義那塊可能捲不下。

其餘版面條件已用真瀏覽器量過，五種尺寸（375×667、320×568、667×375、844×300、375×480）下十二塊磚都是 0 塊出界、0 對重疊，磚會隨螢幕變矮而縮小。
