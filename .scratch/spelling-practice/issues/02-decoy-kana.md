# 干擾假名挑濁音清音變體與同行鄰居，不要隨便抽

Status: done
Type: enhancement

## 問題

拼字下半部的磚，正解每個假名各一塊，其餘是干擾。干擾從哪裡來決定了這個玩法有沒有用。

從五十音表隨便抽，抽到的常常一看就知道不可能（`を`、`ん`），題目變得很好猜——只要認得出哪幾塊「像是這個詞會用到的」就拼得出來，根本不必真的記得讀音。

## 用詞

**磚**是單個假名。正解那幾塊之外的叫**干擾**。

## 決定

1. **每個正解假名各拉出自己的干擾**：它的濁音／半濁音／清音變體，加上五十音表同一行的鄰居。`が` 拉出 `か`、`ご`、`ぎ`；`す` 拉出 `ず`、`さ`、`そ`。

   濁點與同行混淆本來就是日文最常錯的地方。維護者要的就是這個——干擾要練到刀口上，不是湊數。

2. **五十音表有規則，寫成程式算，不要手打一張對照表。** 濁音清音是固定的成對關係，同行是固定的五個一組。手打的表會漏、會打錯，而且日後想加片假名時要再打一次。

3. **磚數 = 正解假名數 + `DECOY_COUNT`**，常數初值 `6`（spec 決定 15）。三個假名擺九塊，六個假名擺十二塊。

4. **干擾不得與正解裡的任何一個假名相同。** 正解是 `こがす` 時，`こ`、`が`、`す` 三個都不能再以干擾的身分出現——畫面上會變成兩塊一樣的磚，而使用者不知道該點哪一塊。

5. **干擾之間也不重複。**

6. **候選不夠時的備案**：短詞（一兩個假名）拉不出六塊不重複的干擾。這時往外擴——先補相鄰行，再不夠就從整個平假名表補。**寧可補到滿，也不要讓短詞的磚變少**：磚數浮動會讓難度跟著浮動，那正是決定 3 要避免的事。

7. **片假名與長音符 `ー`**：正解可能含片假名（外來語詞條）或 `ー`。片假名照同一套規則拉干擾（片假名的五十音表結構一樣）；`ー` 沒有濁音也沒有同一行，它的干擾直接走決定 6 的備案。

8. **亂數注入。** 挑哪幾個、擺哪個位置都吃傳進來的 `random`，不用 `Math.random()`。

9. **這支歸在 `core/lib/spelling.ts` 裡**（票 `01` 開的那支），不另開檔。它是出題的一部分，拆兩支反而要在兩處維護「磚是什麼」。

## 驗收

- 正解 `こがす` 出來的九塊磚裡，含 `こ`、`が`、`す` 各一塊，其餘六塊都不是這三個。
- 那六塊裡看得到濁音清音的對子（例如 `か` 或 `ご`）與同行鄰居，不是整表亂抽。
- 九塊磚彼此不重複。
- 兩個假名的短詞照樣擺出八塊（2 + 6），沒有因為候選不足而變少。
- 六個假名的長詞擺出十二塊。
- 正解含片假名時，干擾也是片假名，不會混進平假名。
- 正解含 `ー` 時不會爆掉，該塊照樣有干擾陪它。
- 程式裡沒有手打的五十音對照表。
- 同一組 `random` 種子跑兩次，磚的內容與順序完全一樣。
- `core/lib/spelling.test.ts` 涵蓋上述每一條。
- 根目錄 `npm test` 與 `npx tsc --noEmit` 全過。
