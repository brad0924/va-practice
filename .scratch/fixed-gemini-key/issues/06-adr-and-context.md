# 06 — 新開 ADR-0016，更新 CONTEXT.md 的「讀音預填」

Status: ready-for-agent
Type: enhancement
Blocked by: 01

決策背景見 `../spec.md`，本票對應決定十七。

## 要做什麼

### 一、新開 `docs/adr/0016-fixed-key-via-firebase-ai-logic.md`

主題：**iOS 的讀音預填改用維護者提供的固定金鑰，走 Firebase AI Logic 代理；網頁版維持自備金鑰。**

**`ADR-0005` 留著不改寫。** 那是歷史，新的這份指回去。0016 裡要講清楚 0005 的哪些前提還在、哪些換掉了：

**還在的**：
- 「這個功能永遠是選配的……離線、超額、模型掛掉、回覆過不了驗證，一律降級成手動填，絕不擋住儲存」——完全保留，而且因為額度共用，這條保底路徑被踩到的機會變多了。
- 「金鑰刻意不進 `AppData`」——網頁版照舊；iOS 上根本沒有金鑰這個東西了，因此 `ADR-0003` 那句「若日後要放入任何敏感資料，這個前提必須重新評估」仍然沒有被觸發。
- 「端點寫死單一模型而非 `-latest` 別名」的精神——見下。

**換掉的**：
- 「需要使用者自備的金鑰，沒設定時連請求都不發」——iOS 上不再成立。
- 「代價是金鑰不跨裝置，每台各設定一次」——iOS 上不再是代價，改成一個新的代價：共用額度。
- 「不經過任何第三方伺服器」——iOS 上請求先經過維護者的 Firebase 專案。
- 「專案對外部服務的依賴又多了一項」——現在是三項：Firebase RTDB（雲端備份）、Firebase AI Logic（讀音預填）、Firebase Remote Config（模型與提示詞）。

**Considered Options 至少要寫進去的三條**（連同否決理由）：
- 硬把金鑰塞進 ipa
- 自己寫一支 Cloud Function 當代理
- 網頁版也吃固定金鑰

**Consequences 必須誠實寫的**：
- **app 越受歡迎，讀音預填越常罷工。** 決定二（不留自備金鑰的後路）、三（給任何人用）、八（不開計費）三者相乘的必然結果。這是知情選擇，不是疏漏。
- `ADR-0005` 那個沒有第二道防線的風險（整串讀音幻覺）被放大了：原本只會發生在自己申請金鑰的人身上，現在每個下載的人第一張卡就可能中。
- 本決定不沿用 `.scratch/ios-app/issues/14` 立下的判例「密碼跟著走，同意不跟著走」——讀音預填不問使用者，理由與代價見 `../spec.md` 決定十。
- Remote Config 為什麼不牴觸「拒絕 `-latest` 別名」：拒絕的是**無預警**改答案，不是不能改。方向盤在維護者手上。
- 升級 Blaze 是一條隨時可走、不必送審的退路，但那是單向門：免費層整個消失、帳單無法設上限、整個 Firebase 專案一起升。

### 二、更新 `CONTEXT.md` 的「讀音預填」詞條

現在寫著：

> 需要使用者另行設定才會啟用，沒設定時完全不發生，讀音格一律留空給人填。

這句話在 iOS 上不再成立。改寫時保留這個詞條原本最重要的那件事——**填進來的仍是使用者的草稿，程式不承擔「讀音一定正確」的責任**——並補上兩邊行為不同的事實。

`_Avoid_` 那一行的既有項目全部保留。

### 三、詞彙表同步

`CONTEXT.md` 與 `docs/glossary.md` 要一起改，否則 `src/lib/glossary.test.ts` 會紅燈。

**評估是否需要新增詞條**，但不要為了湊而加。候選：
- 「固定金鑰」——維護者提供、藏在伺服器端、iOS 使用者看不到也改不了的那把。與網頁版的「自備金鑰」是兩個東西，容易混淆，可能值得各給一條。
- 「共用額度」——所有 iOS 使用者一起舀的那桶水。

若判斷不需要新增，把判斷理由寫進本檔案的 `## Comments`。

## 驗收

- `docs/adr/0016-*.md` 存在，上述每一項都有著落。
- `ADR-0005` 一個字都沒改。
- `CONTEXT.md` 的「讀音預填」不再宣稱「需要使用者另行設定才會啟用」。
- `npm test` 全綠（`glossary.test.ts` 是守門的那支）。
