# 04 — 兩處文案：429 訊息與編輯畫面的確認提示

Status: ready-for-agent
Type: enhancement
Blocked by: 02

決策背景見 `../spec.md`，本票對應決定十二、十三。

**純文案票，不碰任何執行邏輯。**

## 要做什麼

### 一、429 的錯誤訊息

`src/i18n/zh-Hant.ts:254` 現在是：

```
'gemini.httpError': 'Gemini 回了 {status}：{reason}',
```

這句是寫給「知道自己有一把金鑰」的人看的。固定金鑰之下，429 的意思從「你的額度爆了」變成「大家的額度今天用完了」，而使用者一點辦法都沒有。

需要一條 iOS 專用的說法，講清楚兩件事：不是他做錯什麼、明天會恢復。**現有那條給網頁版的訊息保留不動**——網頁版使用者用的是自己的額度，那句話對他仍然成立。

三種介面語言（`zh-Hant`、`en`、`ja`）都要補，`src/i18n/smoke.test.ts` 會抓漏。

### 二、編輯畫面那行「請確認」提示

`ADR-0005` 把它列為三道防線之一：

> 這一項只靠「填進格子而非直接存檔」＋「一行『請確認』提示」＋「預覽」擋，沒有第二道防線。

這道防線的受眾剛換人：從「自己跑去 Google AI Studio 申請金鑰的人」變成「從 App Store 隨便下載的人」。原本那行字預設讀者知道自己開了什麼功能，現在不能這樣假設。

措辭要寫明**讀音是 AI 猜的、儲存前請自己看過**。不要只寫「請確認」——那句話沒說要確認什麼。

## 不要做的事

- 不新增第四道防線（例如強制勾選、二次確認）。`ADR-0005` 的三道防線維持三道，本票只把第二道加粗。
- 不改網頁版既有的那條 429 訊息。
- 不動 `gemini.*` 其他錯誤訊息。

## 驗收

- 三種語言都有新的訊息，`npm test` 全綠（`src/i18n/smoke.test.ts` 是守門的那支）。
- iOS build 上人為觸發 429（例如把 Remote Config 的模型改成一個會被拒的值，或直接把額度用完），確認顯示的是新訊息。
- 網頁版用一把過期金鑰觸發錯誤，確認顯示的仍是原本那條。
- 編輯畫面的提示在三種語言下都不會撐破版面（`ADR-0013` 的介面在地化前提）。
