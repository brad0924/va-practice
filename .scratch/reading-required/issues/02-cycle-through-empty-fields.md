# 換欄鍵改成輪詢所有必填格，↵ 與 ✓ 共用同一套

Status: ready-for-agent
Type: enhancement
Blocked by: 01

## 需求

使用者原話：「新增卡片時，只要有輸入格還是空著的，按手機的 enter 就要從其他輸入格跳過去（之前是解釋跟讀音互跳而已）」。

現況與這句話有兩處出入，先釘清楚：

- 現在跳的是**詞條 ↔ 釋義**，不是釋義 ↔ 讀音。`jumpOnEnter` 只掛在那兩格上（`editor-view.ts:222-225`），讀音格完全沒掛。
- 所以在讀音格按 ↵ 走的是表單原本的 submit（＝「儲存並繼續」），釋義還空著就吃一行紅字——正是 ADR-0006 花力氣要避免的那件事。

要改成：換欄鍵把游標送到**下一個還空著的必填格**，順序是詞條 → 讀音格（左到右）→ 釋義。決策脈絡見 `docs/adr/0006-focus-first-empty-field.md`（該 ADR 已改寫）。

**依賴 `01`。** 讀音沒變成必填之前，空的讀音格既是合法終點又不能當終點，輪詢會卡死。

## 決定

### 換欄規則（↵ 與 ✓ 共用）

```
從目前這格往下找下一個還空著的格子，到底繞回頭
順序：詞條 → 讀音格（左到右）→ 釋義
前提一：離開的那一格必須有值（trim 後非空）
前提二：焦點自己落到別的輸入框、或讀音區裡的任何東西，就不搶
不出錯誤訊息、不儲存
全部有值時 ↵ 放行送出表單（✓ 本來就不送出）
```

- **輪詢方向是「從目前這格往下、到底繞回頭」**，不是「一律回到最上面那個空的」。使用者明確選這個：跟手指往下填表單的方向一致，不會突然往回帶。代價是中間還空的格子會被暫時跳過，繞完一圈才回來。
- **✓ 也比照 ↵。** ADR-0006 原本決定「讀音格失焦不跳」，使用者選擇一致性優先，那條退場。兩顆鍵的落點必須一樣。
- **前提一、前提二兩條照留**，一個字都不能省：少了前提一，兩格都空時按 ✓ 會來回彈、鍵盤永遠收不掉；少了前提二，點另一個讀音格、按合併縫 `⊕` 或拆開縫 `·` 都會被彈走，桌機 Tab 順序也會壞。
- 組字中的 Enter（`isComposing`）不攔，那是輸入法在確定候選字。

### AI 預填避讓

```
離開詞條時，若正在詢問 AI、或這一下離開會開始詢問
（有金鑰 ＋ 詞條有漢字 ＋ 讀音格全空 ＋ 這個詞還沒問過）
  → 這次輪詢把讀音格整段跳過，游標直接送到釋義
```

沒有這條會壞掉：詞條打完按 ↵ → 游標跳進第一個讀音格、鍵盤留著 → 你開始打假名 → 約一秒後 AI 回覆到達，`settle()` 把 `runs` 換掉並要求重畫 → `renderReading()` 整個 `replaceChildren` → 你打的字被蓋掉、游標消失、鍵盤收起來。就算你什麼都沒打，光是重畫就會讓游標和鍵盤一起沒掉，而「鍵盤留得住」正是 ↵ 這條路唯一的價值。

**判斷條件是「會不會去問」，不只是「正在問」**，因為時序：`keydown` 發生在 `blur` 之前，而詢問是 `blur` 才觸發的——按鍵的當下 `note` 還是 `null`。只看「正在問」的話第一次按永遠漏掉。守門條件與 `reading-editor.ts` 的 `prefill()` 完全相同，別各寫一份會漂移的清單。

沒設金鑰的人永遠不走這條。

### 不動的部分

- 「儲存」／「儲存並繼續」兩顆按鈕的行為由 `01` 決定，這張票不碰。換欄鍵與按鈕落點不同是已知且接受的（換欄走畫面順序、按鈕走詞條 → 釋義 → 讀音）。
- 「取消」按鈕的 `pointerdown` 防點空旗子照舊。
- `startEditing`（焦點回到欄位時清旗子）現在要涵蓋讀音格，否則讀音格聚焦時旗子不會被清掉。

## 被放棄的替代方案

見 `docs/adr/0006-focus-first-empty-field.md` 的 Considered Options，重點三條：一律回到最上面那個空格、✓ 完全不動只改 ↵、AI 撞車改成「回覆到了但游標在讀音區就不套用，改出一行『點一下套用』」。

## 驗收

`npm test` 全綠。畫面層照 `docs/spec.md` 慣例不寫自動化測試，靠實測。

**iPhone（主要情境，未設 Gemini 金鑰）**

- 新增卡片，詞條打「焦がす」按 ↵ → 游標跳到讀音格、**鍵盤不收**、沒有紅字。
- 承上，打「こ」再按 ↵ → 游標跳到釋義、鍵盤不收。
- 承上，打「燒焦」再按 ↵ → 卡存進去，行為與「儲存並繼續」一致。
- 詞條打「大丈夫」（三格），手指直接點進**第二格**打「じょう」按 ↵ → 游標跳**第三格**（不是第一格）。
- 承上，填完第三格按 ↵ → 游標跳釋義；填完釋義按 ↵ → 游標**繞回第一格**。
- 詞條打完、游標在**空的**讀音格，按 ↵ → 游標不動（前提一），鍵盤不收。
- 詞條打完，按 ✓ → 游標跳到讀音格，**鍵盤收掉**（iOS 規矩，可接受）。
- 讀音格打完假名按 ✓ → 游標跳到下一個空格，鍵盤收掉。
- 詞條打完、點進讀音格 → 不會被彈走（前提二）。
- 詞條打完、點讀音區的合併縫 `⊕` 或拆開縫 `·` → 不會被彈走。
- 全部填滿後按 ✓ → 游標不動，鍵盤收起來。

**iPhone（有設 Gemini 金鑰）**

- 詞條打「大丈夫」按 ↵ → 游標跳**釋義**（避讓），不是讀音格；讀音區上方出現「詢問中…」。
- 承上約一秒後 AI 填好讀音 → 讀音區重畫，游標仍在釋義、沒有被炸掉。
- 承上，AI **失敗**時（斷網或改壞金鑰）→ 讀音格仍空，此時在釋義按 ↵ → 游標跳到第一個讀音格（避讓條件已不成立）。

**任何裝置**

- 桌機在詞條按 Tab → 焦點照既有順序走到下一個元素，不會被搶。
- 桌機用注音打釋義，選字時按 Enter → 只是確定候選字，不會跳格也不會送出。
- 編輯既有卡（全部有值），在任一格按 ↵ → 送出並返回列表。

## Comments

- 已知、這次不處理：AI 正在查的那一秒，使用者若用手指自己點進讀音格打字，回覆到達時仍會覆蓋掉打的字。避讓只擋「程式把你送進去」，擋不住「你自己走進去」。這在 ADR-0005 落地時就存在。
- 讀音格的 `blur` handler 要掛在 `renderCell()` 裡，因為 `renderReading()` 會把那些元素整批換掉。
